## 1. 摘要
本文档定义 Agent 权限系统的设计语义。核心声明：
> **模型可以请求任何操作，但在数据结构上无法授予自身任何权限；高风险操作要么经人工审批，要么由结构性机制证明其无害。**

设计要旨归纳为四项：授权权由人独占；秘密内容不进入模型上下文；出站操作受数据流账本约束；账本的清除路径在结构上对模型封闭。

本设计相对传统权限模型的主要增量为数据流治理：模型上下文窗口构成数据转运介质，单次调用的合规不能保证调用组合的合规。为此引入断流、账本与残留追踪三项机制，将治理覆盖至传统模型无法触及的组合风险。

## 2. 背景与问题定义
### 2.1 传统权限模型的覆盖缺口
经典权限模型治理“主体对资源的操作”。Agent 场景引入新的风险维度：
> 模型上下文中出现的全部内容，均可能在后续调用的参数中被复述。
### 2.2 组合风险示例
```
T1：fs.read 客户名单.xlsx      —— 合法的读取
T2：net.send 邮件，正文引用名单 —— 合法的发送
组合效果：数据外泄；两次调用单独审计均合规。
```
`fs.read` 与 `net.send` 各自满足放行条件，其组合构成外泄通道——**上下文窗口本身即为转运介质**。该类危险组合不可静态枚举（“当前周期读取过哪些内容”是运行时事实），故数据流治理必须在运行时执行。

数据流治理是本设计唯一真正新增的语义；其余部分为经典安全原则（最小权限、职责分离、fail-closed、审计）在 Agent 场景的落实。

## 3. 目标与非目标
### 3.1 目标
| # | 目标 |
|---|------|
| G1 | 授权仅在根层发生；模型在全生命周期仅持有请求权 |
| G2 | 秘密内容不进入模型上下文 |
| G3 | 敏感数据出站（出网、出域）前必须经检查或审批 |
| G4 | 检查记录不可被模型诱导清除 |
| G5 | 数据残留（写入工作区的文件）跨会话可追踪 |
| G6 | 全部放行与拦截可归因、可回放 |
| G7 | 审批摩擦可度量：审批必要率与同意率漂移作为一等健康指标，驱动标注复审与部署校准 |
### 3.2 非目标
本设计明确不承诺以下事项：
- 提示注入的内容层免疫——仅承诺压缩爆炸半径（注入内容不获得权限、不作为指令执行）；
- 审批人对摘要的正确理解——系统责任止于摘要的生成与签名；
- 规则自身的正确性——内核强制保证无旁路，不保证策略无误（见 §7 底线 4）；
- 侧信道、多委托人共享上下文、显式导出至系统外数据的覆盖。

## 4. 设计立场
权限经历三段生命周期：
```
根层授予（一次）→ 派生求值（每任务一次）→ 调用时内核强制（每次调用）
```
- **强制点位于内核**（沙盒与网关），不位于提示层——提示层不构成安全边界；
- **审批是唯一逃逸路径**——模型不持有任何可变更权限的结构通道；
- **摩擦按实际使用征收**——能力被授予而未使用时不产生审批摩擦，共现事实发生时于正确的时刻支付。

## 5. 风险判定模型
### 5.1 三问判定
操作风险判定不依赖动词规则表的穷举，而是对任一操作依次询问三个问题：

| 问 | 判定维度 | 判定为“是”时的处置 |
|---|---|---|
| **Q1**：后果在当前时点不可撤回吗？ | 付款、删除、DDL、发布、外部进程执行 | 必须人工审批 |
| **Q2**：操作是否将内容置入模型上下文？ | 文件读取、网络抓取、消息接收 | 敏感内容记入账本；秘密级必须断流 |
| **Q3**：操作是否修改权限包络本身？ | authorized_keys、crontab、shell rc、本系统策略文件 | 必须人工审批；秘密级直接禁止 |
三问皆否 → 静默放行。示例：沙箱内写临时文件——整体销毁即撤销（Q1 否）、沙箱边界封闭内容不可外移（Q2 否）、无法触及权限包络（Q3 否），判定无害。
### 5.2 动词与后果的关系
动词仅是三问的载体：`fs.write` 本身无风险属性，写沙箱无害、写 crontab 危险，差异由写入目标落入的三问维度决定。
### 5.3 标注缺省方向
未标注资产 = internal；标注存疑 = sensitive。该保守方向不可配置关闭。
### 5.4 持久化写入的显式声明
三问不含第四问“操作是否修改持久状态”。此为刻意设计而非遗漏，理由如下：
1. 持久化写入（编辑文档、修改代码）是 Agent 的正常工作流本身。若将其设为独立判定问，每次正常写入均需审批，摩擦摊派至全流程，用户必然建立绕过路径——该结果违反摩擦分配原则（§4）。
2. 写入的风险不在写入动作，而在残留内容。三问治理效果与包络，残留维度由机制五（§6.5）兜底；残留摩擦在“使用时”（再次读取、再次出站）征收，而非“写入时”征收——此为摩擦分配原则的又一应用。
### 5.5 边界澄清
跨出强制边界的持久化（外部同步目录、发布渠道）不适用 §5.4 豁免，按出站语义处理：相应路径必须标注为 boundary（写入转审批），或声明为 external 域。不存在无治理的持久化路径。

## 6. 机制设计
### 6.1 机制一：权限单向收紧
**规则**：根层签发一次授权；任务派生时逐层取最严；每次调用由内核强制执行。模型扩大权限的唯一路径是人工重新签署。
```typescript
// 根层授权（仅根层可创建）
interface Grant {
  caps: Record<string, {        // 如 "fs.write.sandbox"
    tier: 'auto' | 'gated' | 'forbidden';
    paths?: string[];           // 范围白名单
    maxLabel?: 'public'|'internal'|'sensitive';  // 可触达最高敏度
  }>;
  budget?: { steps?: number; tokens?: number; cost?: number };
}
// 任务层请求（仅持有请求权，无授予字段）
interface TaskRequest { requires: string[]; wants?: Partial<Grant['caps']> }
```
**派生算法**：
```
effective(cap) = meet(根层意愿, 任务请求)   // 逐轴取严：tier 取严、范围求交、maxLabel 取严
                 ⊔ 三问下限                 // Q1 命中 → 下限 gated；Q3 命中 → 下限 gated
                 ⊓ 底线钳制                 // 秘密写 → forbidden（不可放宽）
未声明能力 = forbidden（封闭世界）
```
关键性质：
- **三问下限与底线钳制不参与 meet**——任何层级、任何配置（含 full-access）均不得放宽；
- **范围白名单不豁免标注**——paths 白名单包含秘密文件时，秘密规则仍然生效；
- **每次派生产出不可变快照**，钉住当时的标注与规则版本——策略变更不影响运行中任务，事后可归因；
- **权限格自身属于 Q3 边界资产**——本系统的策略文件、标注表的写入，与人工签发同级审批。
### 6.2 机制二：秘密断流与代金券
**规则**：秘密级内容（私钥、凭据、环境配置）读取时不返回原文，返回代金券（SecretRef）。后续使用由网关校验用途后代为签名。模型与业务代码在全流程不接触原文。
**设计依据**：未进入上下文的原文不构成泄漏面。该机制具有结构性保证且实现成本最低，是本设计的首选防线。
```typescript
interface SecretRef {
  refId: string;
  allowedSinks: string[];       // 可用工具集（创建时绑定，不得由模型指定）
  purpose: {                    // 结构化用途声明
    service: string;            // 如 's3'
    actions: string[];          // 如 ['GetObject']
    resourcePattern: string;    // 如 'arn:aws:s3:::my-bucket/*'
  };
}
```
**解析流程（网关代签）**：
```
1. 校验 tool ∈ allowedSinks                    失败即拒绝
2. 校验 service/action/resource 匹配 purpose    失败即拒绝
3. 网关由结构化参数构造最终请求并签名
4. 业务代码仅获得已签名请求，不含原文
```
**三条配套纪律**：
- **代金券不透明**：出站工具收到代金券字符串时一律视为数据，不得自动解析原文——否则“原文不进上下文”将被“代金券进上下文、出站时解析”的路径绕过；
- **构造权唯一**：最终请求的字节由网关构造，业务代码不接触原始请求——规范化责任（路径 realpath、协议编码）全部收拢于网关内，不下推至不可信侧；
- **暴露面诚实声明**：原文必然在网关进程内存中瞬时存在（签名计算所需）。网关不得将原文写入持久存储、审计或日志。
#### 6.2.1 属性代理：断流的可用性逃生路径
断流存在可用性代价：模型读取 `.env` 后无法回答“该密钥格式是否正确”，运维调试场景将频繁受阻。若不提供补偿，断流将在日常运维中持续引发绕过动机。
**方案**：策展属性披露。断流时网关对原文一次性计算一组非敏感属性，附加于代金券元数据返回。设计原则与标注负例条目同源：**逃生路径必须是策展白名单，不得是自由字段**。
```typescript
// 策展属性集：入 TCB，与标注注册表同路径治理（内容哈希 + 版本 + 全量回归后发布）
interface RedactionProfile {
  pattern: string;              // '**/.env'、'**/id_rsa*' 等
  attributes: AttributeKind[];  // 仅可取自策展属性集
}
type AttributeKind =
  | 'kind'           // 'api-key' | 'private-key' | 'oauth-token' | 'password'
  | 'prefix-class'   // 'sk-' | 'ghp_' | 'AKIA' | 'xoxb-'   ← 类别，非取值
  | 'length-bucket'  // '≤32' | '33–64' | '>64'             ← 粗桶，非精确
  | 'validity';      // 'format-ok' | 'malformed'           ← 布尔
```
**策展判据（唯一测试）**：披露该属性是否实质缩小穷举空间。
- 缩小 → 禁止：精确长度（`length=51` 将搜索空间缩减一个数量级）、值的任何字节、校验位；
- 不缩小 → 允许：厂商标识类（`sk-`）、粗桶、布尔有效性。
**配套不变量**：
- **INV-C（属性来源封闭）**：属性只能取自策展集合；策展集扩容 = 注册表变更，必须走同一条治理门（内容哈希 + 版本 + 全量回归）——防止属性集渐进放宽形成旁路；
- **INV-D（计算同一遍）**：属性计算在断流的同一次读取内完成，不得为属性计算额外读取原文；网关外任何组件不得计算或透传属性行的原始字节。
**设计说明**：部分表面上需要原文可读性的场景，实质需求为可达性验证，属动作语义而非读取语义。“该密钥当前是否可用”由网关代签一次 dry-run 探活调用满足，返回可达性布尔值，不经属性披露解决。
### 6.3 机制三：出站账本裁决
**规则**：系统维护账本，记录当前周期内读取过的敏感数据。出站操作（网络发送、跨域传输）执行前查账：
```
账本无敏感条目 → 静默放行（平时零摩擦）
账本含敏感读   → 拦截，附带数据流摘要转人工审批
账本含秘密读   → 结构上不存在（秘密已断流，机制二兜底）
```
摩擦分配：能力被授予而未使用时不产生摩擦；敏感数据与出站操作实际共现时，于该时刻一次性支付。
**账本条目**：
```typescript
interface LedgerEntry {
  label: 'sensitive' | 'secret';   // 秘密级因断流实际不出现，防御性保留
  source: string;                  // 来源资产
  stepId: string;                  // 读取发生的步骤（归因用）
}
```
**实现纪律**：
- **账本带版本号**：并发任务各自记账，出站裁决必须读最新已提交版本（精度由 §6.3.1 不变量定义）；
- **引用型出站必须钉版**：出站引用文件路径时，裁决时点必须完成内容投影（inline）或记录哈希并于执行前校验——封堵“裁决时干净、执行前被写入”的时序窗口。
#### 6.3.1 并发时序不变量
机制三的并发正确性依赖以下两条不变量，均为强制要求，不可配置关闭：
> **INV-A（记账先于可见）**：敏感读的账本提交必须先于该读的返回值对模型可见。网关按阶段顺序强制：读执行 → 账本提交 → 返回。提交失败 → 内容不返回（fail-closed；覆盖网关在读执行与提交之间崩溃的场景）。

> **INV-B（裁决用最新已提交）**：出站裁决读取最新已提交版本；裁决读与裁决落定之间出现新提交 → 重新裁决（fail-closed，可疑即拦截）。
**序列化点声明**：账本由网关独占写入——“唯一咽喉”结构本身即序列化点，并发正确性不依赖分布式共识；多网关部署为范围外事项（见 §10）。
上述不变量对泄漏窗口的封闭性论证：
```
出站参数中的内容只能来源于模型上下文；
上下文获得该内容 ⟹ 对应账本条目已提交（INV-A）；
裁决读取全部已提交条目（INV-B）；
⟹ 不存在"内容已可达、账本未记账"的泄漏窗口。
```
走查（“任务 A 读取敏感未提交、任务 B 同时出站”）：
- 若 B 的参数不含 A 的内容——A 未提交则内容对模型不可见，B 的干净裁决为**正确放行**而非漏放；
- 若 B 的参数含该内容——内容可见的前提为 A 已提交（INV-A），B 读取最新版本必然命中（INV-B），判定破缺转审批。
两条路径均闭合。
#### 6.3.2 粒度限制与审批疲劳治理
诚实声明：账本按**资产级**记账。读取 10MB 日志（其中一行含客户数据）将整文件入账，此后每次出站均触发审批——误报率高企 → 审批人习惯化 → 机制失效。**这是本机制最主要的运营风险，其威胁高于任何绕过攻击。**治理分三层：
1. **结构化源按投影记账**：数据库标注本已达列级；`db.read` 显式选列时按所选列记账，未选列不入账——现有标注结构可直接支撑的细粒度，无需新增机制。
2. **非结构化文件不承诺切分**：不存在可靠的结构切分手段，不做块级记账；补偿手段为负例条目策展（确认安全的日志模式标注 internal）。该近似为保守方向，代价为误报，此处如实声明。
3. **内容探测只丰富、不自动放行（默认档）**：审批摘要展示出站内容及其敏度分类，辅助人工判断——但不得自动清除审批。依据：探测为概率性组件，以概率组件为主防线违反 fail-safe；若允许探测自动放行，探测漏报即转化为静默泄漏。部署可显式选择**降级档**：账本无秘密级条目 ∧ 探测无命中 → 记日志放行（审计一等事件）——该取舍模式与底线 2 的“缺件拒绝 / gated+披露”一致。
#### 6.3.3 疲劳度量（一等健康指标，对应 G7）
```
对窗口 W 内每次出站审批：
  必要 ⟺ 回放证明出站载荷携带账本敏感读的派生内容
        （账本回放定位来源读；载荷与来源内容重叠比对；不可判定按"必要"计——保守方向）
  R  = 必要数 / 审批总数              ← 审批必要率
  F1 = 审批中位延迟（相对任务类型基线的偏移）
  F2 = 同意率漂移（相对任务类型基线）
反馈闭环：
  R < θ 持续一个窗口 → 触发来源资产标注复审（疑似误标或粒度问题）
  F2 漂移超阈        → 触发根层审阅——机制正被习惯化绕过，全体系最高优先级告警
  θ 由根层配置、随部署校准；起步建议区间 0.2–0.3，不写死
```
归因回放依赖账本条目的 `source + stepId` 字段——条目结构（§6.3）已包含，度量不需修改账本，仅需回放工具。
**设计立场**：审批机制的主要失效模式并非误报本身，而是误报诱发的审批人习惯化——F2 漂移即防线失效的前兆。R 偏低指示摩擦配置错误；F2 漂移指示防线正在失效，后者为全体系最重要的健康指标。
### 6.4 机制四：账本清除路径封闭
模型上下文会被压缩重建。若压缩顺带清除账本，攻击路径为：诱导模型产生大量输出触发压缩 → 账本清除 → 自由出站。因此：
> **压缩必须继承账本；仅用户显式重置可清除账本。该保守方向不可配置关闭。**

| 触发 | 账本处置 |
|------|----------|
| 新会话创建 | 新周期，账本置空 |
| **用户显式重置** | **唯一清账路径**；UI 必须呈现为安全决策 |
| **自动压缩** | **必须继承账本**（默认继承完整条目；最小部署档可降级为布尔标记，审批摘要须标注归因弱化） |
| 会话销毁 | 账本归档入审计，不删除 |
**配套约束**：账本默认记账单元为**周期**（自会话建立/压缩重建起，至下次压缩/销毁止），而非单轮对话——Turn 边界不构成风险消散边界，否则“跨轮出站”即构成洗账通道。
### 6.5 机制五：残留污点标记
敏感数据读取后写入工作区文件时，会话结束不消除残留——内容已落盘。**规则**：
> 写入文件时，若当前账本含**未断流**的敏感读，对目标文件施加污点标记。后续会话读取该文件、或将其内容出站，同样受账本裁决约束。

**三条边界**（防止机制被滥用或形成逃逸路径）：
1. **断流读不产生污点**——原文未进入上下文，后续写入不可能包含该内容。不施加污点是正确行为：断流是本系统的首选防御行为，不得对其施加额外代价；
2. **污点仅参与账本裁决，不触发底线**——污点文件不是秘密文件：可以再次编辑、再次读取。底线（如秘密写禁止）仅由静态标注触发。否则“写入报告 → 永不可修改”将把正常工作流拖入死锁；
3. **污点清除与账本重置解耦**——用户执行“重置账本”不得连带清除污点；污点清除为逐文件的独立安全决策。否则“重置”操作构成污点层的逃逸路径。
**生存期**：工作区文件 → 人工逐文件清除（文件寿命超过会话）；沙箱/草稿区 → 随域销毁。

## 7. 强制底线
以下四条在任何配置、任何档位（含 full-access）下恒生效：

| #   | 底线                       | 说明                                                           |
| --- | ------------------------ | ------------------------------------------------------------ |
| 1   | **秘密级文件写 = 禁止；读 = 必须断流** | 无豁免。秘密级写入不存在应走静默或普通审批的正当场景                                   |
| 2   | **缺件即拒绝**                | 沙盒不可用、审批服务缺失、账本损坏 → 拒绝执行。不可强制的轴默认禁止（部署方显式选择降级时，审批界面必须披露强制缺口） |
| 3   | **急停开关位于权限体系之外**         | 独立控制通道，任何策略不得阻挡；急停必须连带清理草稿暂存区                                |
| 4 | **系统不可自证** | 内核强制保证无旁路，不保证策略正确。故：根密钥、审批人身份、审计完整性由系统之外的锚背书；审计只追加、签名成链、定期外部锚定；规则变更全部可归因、可回放 |

## 9. 场景走查
| 场景 | 判定 | 结果 |
|------|------|------|
| 沙箱内写临时文件 | 三问皆否 | 静默放行 |
| 读取 `.env` | Q2 + 秘密级 | 断流：返回代金券及策展属性（kind / prefixClass / lengthBucket / validity），原文不进入上下文 |
| 读取 `.env` 后询问密钥格式 | 属性代理 | 以策展属性应答；不披露原文 |
| “该密钥当前是否可用” | 动作语义 | 网关代签 dry-run 探活，返回可达性布尔 |
| 当前周期无敏感读，发起网络请求 | 账本裁决：无条目 | 静默放行 |
| 当前周期含敏感读，发起网络请求 | 账本裁决：破缺 | 附数据流摘要转审批（摘要含探测分类辅助）；计入 R/F2 度量 |
| 读取 10MB 日志（一行客户数据）后出站 | 资产级记账 → 破缺 | 审批；R 计入度量，R 持续偏低触发标注复审 |
| `db.read` 显式选列后出站 | 投影记账 | 未选列不触发审批 |
| 任务 A 读取敏感未提交、任务 B 同时出站（参数不含该内容） | INV-A / INV-B | B 正确放行（内容尚不可见，非漏放） |
| 任务 A 读取敏感未提交、任务 B 出站参数含该内容 | INV-A | A 必已提交 → B 读取最新版本 → 破缺 → 审批 |
| 网关在读执行后、账本提交前崩溃 | INV-A fail-closed | 该读内容不返回（宁可重试，不得漏账） |
| 读取敏感 → 写 report.txt → 下一会话读取并出站 | 污点标记 | 跨会话仍拦截 |
| 读取敏感 → 写 report.txt → 用户重置账本 → 出站引用该文件 | 污点与重置解耦 | **仍拦截** |
| 诱导模型大量输出触发压缩后出站 | 压缩继承账本 | **仍拦截**（洗账路径失效） |
| 被注入的业务代码尝试自行签署 AWS 请求 | 代金券不透明 + 网关唯一构造 | 拒绝（`SIGN_POLICY_VIOLATION`） |
| 出站 body 中携带代金券字符串 | 券不透明 | 拒绝或原样透传 + 审计 |
| 写 `~/.ssh/authorized_keys` | Q3 + 秘密级 | 禁止（底线 1） |
| 写 crontab | Q3，非秘密 | 转人工审批 |
| `rm -rf src/` | Q1 | 转人工审批（动词匹配器识别为不可逆删除） |
| 修改 README / 工作区代码 | 持久写不在三问范围（§5.4） | 静默放行；账本含敏感读时由机制五施加污点 |
| 写入外部同步目录 | §5.5 边界澄清 | 按出站语义（boundary 标注或 external 域）处理 |
| 支付 | Q1 + 资金外流 | 限额内静默 + 日志；超限审批，必附交易摘要 |
| 新注册外部工具 | 默认不可信：最坏假设 + 逐调用风险事件 | 行为稳定后由人工放宽 |
| 沙盒后端不可用 | 底线 2 | 拒绝执行 |
| 审批同意率漂移超阈 | F2 告警 | 触发根层审阅 |
| 修改本系统标注表 | Q3 边界资产 | 转人工审批；运行中任务不受影响（快照已钉版） |

## 10. 边界与责任声明
**不覆盖、需独立治理面**：侧信道；多委托人共享上下文；提示注入的内容层免疫（仅压缩爆炸半径）；用户显式导出至系统外的数据——**最终边界始终是源头断流**；多网关分布式部署（账本序列化点假设单网关）。
**明确不承诺**：
- **规则无错**——底线 4 的治理降低概率，不归零；
- **标注正确**——三问判定最终落于工具语义标注（哪些操作不可逆、输出敏度几何）。标注错误不由设计消除，由缺省最坏假设（未声明 → 最坏）+ 红队定期复审兜底，**不归零**。须说明失败模式的不对称性：动词规则表漏标 = 静默旁路；后果标注表漏标 = 最坏假设兜底——此为判定模型从动词表挪移至后果表的价值所在。M1 验收矩阵由声明机械生成，矩阵规模不等于设计负担，但标注本身构成持续的专家成本；
- **账本零误报**——资产级记账为保守近似，结构性误报存在；治理依托投影记账、负例条目、探测辅助与疲劳度量闭环（§6.3），不承诺误报率为零；
- **审批人理解质量**——系统责任止于摘要的生成与签名；
- **内容探测不漏报**——探测为概率性兜底，安全承诺由断流承担；故探测不得自动放行；
- **污点精确**——污点为保守近似（曾接触敏感即视为可能含敏感），宁可误标。

## 12. 最小可行子集
资源受限时按优先级裁剪。**前三项裁掉任何一项，系统整体失效**：

| 优先级 | 项 | 理由 |
|--------|------|------|
| 必保 ① | 断流（含属性代理 + 券不透明） | 唯一结构性防线，其余均为检测；属性代理为其可用性组成，实现成本低 |
| 必保 ② | 压缩继承账本 | 否则存在单步洗账攻击路径，机制三整体失效 |
| 必保 ③ | 四条底线（§7） | 安全底线 |
| 必保 ④ | 账本版本号 + INV-A/INV-B | 否则并发竞态绕过裁决 |
| 必保 ⑤ | 污点标记 | 封堵文件中继这一结构性缺口，实现成本低 |
| 可裁 | 内容探测（含降级档） | 摘要退化为纯账本摘要；降级档本就需部署显式选择 |
| 可裁 | 疲劳度量闭环 | 降级为纯日志记录（账本条目字段已具备 R 的手工可算性） |
| 可裁 | 引用型哈希钉版 | 强制 inline 投影代替（大 payload 场景性能受限） |
| 可裁 | 污点逐文件 UI | 降级为整批确认，但必须显式呈现为安全决策 |
| 可裁 | 外部锚 | 降级为本地签名链，篡改检测依赖本地完整性 |
