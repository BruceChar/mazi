# Agent Harness Auth 层设计 v5.0（单级别自适应 · 实现基线）

**状态**：设计定稿，可作实现基线。取代 v9.3 双模式设计——机械骨架（底线、指纹、fail-closed、审计）沿用，模式系统移除，新增学习层与校准纪律。
**范围**：只管"一个操作该自动执行还是弹窗问用户"。强制层（沙箱替位）在本设计内规定部署条件，不规定实现；UI 布局不在内。

---

## 0. 设计立场

系统只有一个权限等级：**auto**。每个操作由系统判定放行还是弹窗；判定依据是三层——机械规则（永远成立）、指纹记忆（完全相同的重复）、学习模型（用户已形成惯例的重复）。**弹窗不是模式，是系统在说"这个我不确定，或这个机械高危"。**

两条铁律贯穿全设计：

1. **学习只碰目标轴，永不碰风险轴。** 风险等级由操作性质机械决定（不可逆、改能力边界、出站到新目标……）；学习只回答"这个具体目标/惯例是否属于该用户"。学习不能把"这类都放行"泛化到高危操作。
2. **静默放行必须可发现、可撤销。** 每次 auto 留痕，一处可查，可能处可撤；用户纠正立即失效并连带回滚。优化目标是纠正次数趋零，不是弹窗数趋零。

"和用户自己使用一样"的准确含义：**例行动作同频无感，新动作必问。**系统看到的是 op，用户有的是意图；这个鸿沟靠弹窗弥合，不靠学习填充。

## 1. 核心模型

```python
decide(op) -> auto | ask | deny:
    if bottom(op):         return deny         # B1–B4 底线，不可学习、不可覆盖
    if blocked(fp(op)):    return ask          # 用户红线：显式否决，点名也问一次
    if hazard(op):         return ask          # 机械高危层：学习不可达（§5）
    if passthrough(op):    return auto         # 用户逐字点名 + 本轮干净；仅当次，不落记忆
    if memory(fp(op)):     return auto         # 指纹记忆：完全相同的重复
    if routine(op, model): return auto + 留痕  # 学习层：已验证的例行惯例（§10–11）
    return ask                                 # 不确定 → 弹窗
```

七行，七个概念，一行一个，顺序即优先级。每行可独立删掉，删掉任何一行都重开一类已知失效：

| 行          | 删掉后重开的失效                   |
| ----------- | ---------------------------------- |
| bottom      | 秘密断流、系统毁灭、元操作失控     |
| blocked     | 用户否决被绕过                     |
| hazard      | 学习越过风险轴，高危操作被惯例放行 |
| passthrough | 用户点名被诱导劫持，或重复打扰     |
| memory      | 重复操作反复弹窗，指纹错绑         |
| routine     | 例行动作永远弹窗，或未验证即放行   |
| default ask | 不确定被乐观放行                   |

复杂度在 op 解析、分类与学习模型，不在决策函数。规则层可对最后一行收紧（额外 ask），永不越过以上任何一行。

**auto 的可达域（封闭枚举）**：工作区读（auto_log）、指纹记忆命中、例行惯例命中（限可逆/可补偿且目标绑定已学）、直通当次。hazard 与底线之外不存在任何通往 auto 的路径。

## 2. 弹窗语义

弹窗一行三要素：**动作 + 对象 + 为什么**。"为什么"引用三问答案与原因码：

- 机械高危："此操作不可撤回""这会改变将来自动执行的能力边界"
- 新颖："这是本会话/本项目未见过的操作模式"
- 红线："你曾拒绝过此类"
- 污点："这是敏感数据出站，永不学习"

用户对弹窗的响应集合就是他影响系统的全部接口（取代 v9.x 的模式选择）：**批准（可带作用域）、拒绝（进红线）、键入确认（高危持久化）、事后纠正（学习负样本 + 连带回滚）**。

---

## 3. 三问：分类器的契约

三问不独立计算等级。它是每个解析器/分类器必须能回答的填空题，答案直接是 op 的字段：

| 三问                        | 落到 op 字段                                               | 答不出时                                          |
| --------------------------- | ---------------------------------------------------------- | ------------------------------------------------- |
| Q1 后果：可撤回吗？         | `q1: reversible \| compensable \| irreversible \| unproven` | `unproven` → 按 irreversible 对待（进 hazard） |
| Q2 认知：带什么进出上下文？ | `data: clean \| tainted \| secret`                         | secret 由断流底线直接拦，不靠污点                 |
| Q3 包络：改能力边界吗？     | `envelope: bool`                                         | 判不了 → true（宁可问）                          |

三问答案同时是"为什么问"的展示语言和审计字段。**三问是 hazard 层的输入，学习模型对三问没有写权限。**

## 4. 结构化 op

```python
Op = {
  action, target,
  object: build_artifact | source | source_dirty | sensitive | external | critical | unknown,
  data, q1, envelope,
  origin_chain: bool,          # 来源链：本会话写入 / 网络下载 / 新装依赖
  target_fresh: bool,          # 目标链：目标不在会话基线（未知目标默认 true）
  channel: ui_user | agent | non_interactive,
  attested: verbatim | derived | none
}
```

| 类别           | 判定                        | Q1 默认            | 去向                           |
| -------------- | --------------------------- | ------------------ | ------------------------------ |
| build_artifact | gitignore 命中 / 生成目录   | reversible         | 可进例行学习                   |
| source         | git tracked，无未提交       | compensable        | 可进例行学习（限目标绑定已学） |
| source_dirty   | 有未提交改动                | irreversible       | hazard（高亮未提交）           |
| sensitive      | 用户标记敏感区              | —（读放行打污点） | 污点轴                         |
| external       | 工作区外                    | —                 | hazard（读/写/删/执行）        |
| critical       | `.git/`、备份、恢复能力区 | irreversible       | hazard                         |
| unknown        | 分类器拿不准                | unproven           | 按 irreversible 对待 → hazard |

**读的默认规则**：工作区内普通路径 `read` → `auto_log`（不弹窗，留痕）。`sensitive` 读 → `auto_log` + 打污点。`external` 读 → hazard 弹窗；项目显式授权路径后按普通路径分类，授权逐条、可撤销、入审计。秘密读 → B1 拒绝。

**envelope 判定语义（能力边界，非内容修改）**：写入改变的是"哪些代码/凭证/钩子将来会被自动执行"，而非"被执行的内容本身"。写 `src/app.py` 不是 envelope；写 `.husky/pre-commit`、`authorized_keys`、`crontab`、systemd user units、git hooks 及 `core.hooksPath` 重定向、CI workflow、`package.json` lifecycle scripts、remote/npmrc/PATH 配置、`.envrc`、`~/.gitconfig`、shell rc 是 envelope。路径清单只作提示不作判定；**拿不准 → true**。

**解析器硬要求**：复合命令（管道、重定向、命令替换、多行）必须先拆解为完整 op 链再执行；任一 op 落 ask 且未获批准 → 整链暂停（原子语义）。拆不动 → 整链进 hazard；内联解释器（`sh -c`、`python -c`）按不可拆处理，整条 hazard 且不可指纹化。

**TOCTOU 约束**：整链执行时，每个 op 在真正落盘 / spawn 前必须重新校验分类（批准与执行之间环境可能变化）。写目标变为 external/critical 或符号链接变更 → 该 op 回 hazard，整链回到弹窗。执行类以脚本内容哈希绑定，spawn 前校验。

## 5. hazard 层（机械高危）

```python
hazard(op) =
    op.q1 in {irreversible, unproven}                # 不可逆 / 未证实
 or op.object == critical
 or op.object == external and op.action in {read, write, delete, exec}
 or op.envelope                                      # 能力边界写入
 or (op.origin_chain and op.action == exec)          # 会话来源代码执行
 or (op.action == egress and op.target_fresh)        # 出站到基线外目标
 or unparsed(op)                                     # 拆解失败 / 未知语法
```

**hazard 的语义：永远弹窗，至少一次。** 放行只有两个通道：

1. **指纹记忆**：完全相同指纹 + 目标绑定 + 内容哈希的重复（§9，作用域受限）；
2. **当次点名**：用户逐字指定，弹窗标注"来自你的指令"，仍需确认一次。

**学习不可达**：`routine(op, model)` 的输入不含任何能改变 q1 / envelope / hazard 判定的字段；模型 schema 按构造白名单（§10），物理上无法把 hazard 操作送进例行路径。这是 v9.x Tier A 时序投毒缺口的根治：**类别泛化不再是学习对象**。

不可逆类与 envelope 类的指纹记忆作用域限 once / session（envelope 绑目标文件内容哈希，文件改动即失效）；project 作用域需键入确认；**all 作用域对 hazard 类禁止**。

## 6. 底线（B1–B4）

| #  | 条件                                                                                                                                                                                     | 处置                              |
| -- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| B1 | **秘密断流**：未解锁的秘密不进上下文——读拒绝；携秘密出站/落盘拒绝。解锁是独立带外动作（一次性环境变量注入、专用 unlock 会话），解锁后按 `data=secret` 追踪，op 级出站/落盘仍拒 | deny                              |
| B2 | **系统毁灭**：系统路径删（`/`、`~`、`/etc`、`/usr`、裸设备）、`mkfs`、fork bomb                                                                                          | deny                              |
| B3 | **污点出站**：`data == tainted` 且 egress 到 external                                                                                                                            | ask，永不学习、永不记忆、永不例行 |
| B4 | **元操作与信任根**：auth 策略文件写、学习模型写、阈值变更、审计存储写仅接受 auth 内核或真人交互通道；模型与策略变更需键入确认；Agent 通道发起 → deny + 审计                       | deny / 带外                       |

**B1 残余披露**：解锁后的 secret 随执行进入子进程环境（如 `curl -H "Auth: $KEY"`），auth 层 op 级检测看不见进程内部。兜底是强制层的凭证隔离（§12）；无强制层部署时，B1 覆盖仅限 op 级参数与落盘，必须在部署文档如实声明。

**B3 看引用关系**：引用污点内容且目标为 external 才拦；引用到基线内自有资源不拦，记账。

**B4 将学习模型纳入信任根**：模型文件、阈值、模式清单的写权限与策略文件同级。学习层一旦可被 Agent 通道或污点内容改写，第 1 行铁律即失效。

未注册工具在管线入口拒绝；未归类工具按 unknown 落 hazard；fail-closed 落在非交互分支（§13）。

## 7. 直通（点名）

```python
passthrough(op) =
    op.attested in {verbatim, derived}
    and op.channel == ui_user
    and round_clean                     # 本轮无污点入上下文
    and not hazard(op)                  # hazard 点名仍问一次，标注"来自你的指令"
    and 未附加改变语义的参数
```

直通仅当次有效，不落任何记忆。锚点原则：命名的对象是用户原话中的操作与目标，不是 Agent 的转述；"按 README 执行" → `attested = none` → 落默认弹窗。结构化意图解析由 UI/网关可信侧产生，直通携带 UI 签发的一次性意图绑定令牌；**意图锚定器是最高风险扩展点**——UI 侧解析若也是 LLM，等于把最难的问题挪出 auth 边界，实现时独立评审。

复合命令：整链中任一 op 越 hazard，直通不适用于整链；hazard op 逐个询问，其余按直通，全部批准后整链执行。

## 8. 指纹记忆

**指纹** = 归一化命令行（realpath / 空白 / 引号等价；歧义即新指纹）+ 目标绑定（host / 收件人 / 分支+远端）+ 执行类绑脚本内容哈希 + envelope 类绑目标文件内容哈希（被绑对象改动即失效）。

**作用域**：once / session / project；hazard 类不可逆与 envelope 禁 project 之外的全部；不可逆 project 需键入确认。**all 作用域只对非 hazard 类开放且需显式开启 + 键入确认。**

设置中可见、逐条撤销、可过期；解析器/分类器版本变更 → 相关指纹失效重估。

指纹记忆解决"完全相同的重复"，**不做任何泛化**——泛化只属于学习层，且只沿目标轴。

---

## 9. 学习层：目标轴用户模型

模型只存**元数据**：路径、目标（host/remote/分支）、命令形态、批准/纠正事件、显式授权与标记。**不读文件内容，不存文件内容。**本地存储，可导出（不含内容）、可检查、可一键清空。

### 模型内容（目标轴白名单）

| 字段           | 来源                                | 用途                           |
| -------------- | ----------------------------------- | ------------------------------ |
| target_trust   | 批准事件、会话基线、显式授权        | "这个 remote/host/路径是他的"  |
| conventions    | gitignore、产物确认、高频低方差序列 | "这个目录是产物""这是例行流程" |
| sensitivity    | 出站拒绝、显式标记                  | "用户把什么当敏感"             |
| correction_log | 纠正事件                            | 负样本 + 连带回滚依据          |

### 铁律的工程落实

- **输入隔离**：污点内容参与过的会话，其批准/授权事件不进模型（防注入种植"总是允许"）。
- **持久化门**：任何 project/all 级模式写入需键入确认；Agent 通道写模型 → B4 deny。
- **schema 白名单**：模型字段在 auth 内核中按构造枚举，无风险轴字段（§5）。
- **版本失效**：解析器/分类器/模型版本变更 → 相关例行模式与指纹失效重估。

### 例行判定（routine）

```python
routine(op, model) =
    pattern = (action, object_class, target_binding)   # 目标轴模式
    pattern in model.conventions
    and op.q1 in {reversible, compensable}             # 风险轴硬门槛
    and not hazard(op)                                 # 双保险：hazard 已在前序行拦截
    and model.observations(pattern) >= 5               # 默认阈值
    and model.corrections(pattern) == 0                # 零纠正
    and variance(pattern) < ε                          # 低方差：参数形态稳定
```

新颖性检测内建于此：`pattern` 未见过 → 不满足第一条 → 弹窗。**个性化不许对未探索空间乐观填充。**

冷启动：新项目/新会话回到严格态——只带红线、指纹（per-project）、显式授权，惯例计数归零。惯例默认 per-project，全局共享需显式开启 + 键入确认。

## 10. 校准纪律与纠正

**目标函数 = 用户纠正次数，不是弹窗数。**弹窗数是可用性约束，纠正率是安全度量。两者冲突时，纠正率优先。

**纠正的语义**（用户对一次 auto 的事后撤销 / 执行中中断 / 对留痕的否认）：

1. 该次操作进入审计为负样本；
2. 对应指纹删除；
3. 同 `(action, object_class, target_binding)` 例行模式**归零重学**，该模式进入强制弹窗的"红区"直至重新积累零纠正历史；
4. 同目标绑定（同一 remote/host/路径）的其他记忆标记"待审"，24 小时内未确认则连带失效。

**爆炸半径原则**：撤销一个指纹，必须撤销它能推断出的同类放行。

**度量与降档**：按模式类统计纠正率；某模式纠正率超阈值（默认 1%）→ 自动降级为永远弹窗；全局纠正率异常 → 告警并收紧默认阈值。降档只收紧、不放开。

**留痕视图是安全基础设施**：每次 auto（指纹/例行/直通）一条记录（三问答案、类别、模式依据、绑定、结果），一处可查、可逐条撤销。用户不看留痕，校准就没有负反馈来源——这是"系统代决策"成立的前提，UI 必须让"最近自动执行"一屏可达。

## 11. 放行域与强制层

auth 是决策层，不是强制层。**决策层的安全上限 = 分类与学习质量，强制层把它变成结构性保证。**

### 部署矩阵（强制层成熟度 → auto 放行域）

| 强制层状态                                  | auto 放行域                                                                            |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| 无（纯 auth）                               | 工作区读、build_artifact 写；**执行类与出站类不进指纹记忆（限 once）、不进例行** |
| + Unix 基线（专用 uid、文件权限、凭证隔离） | 上行 + external 读写有 OS 后盾；凭证件落地后 B1 残余闭合                               |
| + 网络件（uid 限网 / 代理白名单）           | 上行 + 执行类与 egress 可 session 记忆、可进例行（出站有机械边界）                     |
| + 完整沙箱                                  | 全量；auth 从安全层降位为 UX 层                                                        |

Unix 基线不是"沙箱产品"：Agent 及子进程跑专用 uid，环境清洗，secret 走 credential helper / 受限 socket；nftables 按 uid 限网或强制本地代理 + 域名白名单；敏感目录用文件权限直接不可读。**这三件事不改 auth 任何一行，只是让 external/egress 的判定结果获得 OS 强制后盾。**

无强制层部署必须如实声明：auto 对执行类与出站类的放行是概率性的，进程内出站不可见。

---

## 12. 非交互与运行清单

无审批者时一律 fail-closed：应弹窗的操作 → deny + 留痕。

**运行清单** = 人写的明确计划，等价一次性预记忆。清单可包含 hazard 类，创建时逐条键入确认；清单外拒绝；清单不豁免 B1–B4。非交互场景是运行清单的主场景，也是唯一允许 hazard 类免弹窗执行的通道。

---

## 13. 污点与秘密

路径集 + 内容指纹；Agent 写出的文件带标记（xattr / sidecar），再读入延续——堵"敏感 → 临时文件 → 读回 → 外发"洗账路径。清除：新会话或人工重置；上下文压缩不清除。

秘密与污点分离：未解锁的秘密不走污点，根本不入上下文（B1 断流）；解锁后携带 `data=secret`，op 级出站/落盘仍由 B1 拒。

已知缺口（如实声明，不是保证）：敏感路径集是启发式，集合外且未经文件中继标记的敏感文件不被标记；用户手动复制/移动文件可能丢标记，此时仅路径集兜底。**污点会话的批准事件不进学习模型**——这是污点与学习层的交叉纪律。

---

## 14. 审计

**审计最小集**：每次决策一条记录（三问答案、类别、hazard 命中项、指纹/模式依据、目标绑定、污点、attested、通道、原因码、结果、作用域），追加日志 + 哈希链可回放。审计存储仅 auth 内核追加（B4），Agent 通道不可触达。

**链头周期性锚定**：链头哈希按固定周期（默认每日）锚定到 auth 内核外的独立位置（设置快照 / OS 日志），支持手动全量校验。篡改链需同时攻破两处。

auto 操作进"已自动执行"留痕视图（§10），弹窗历史进决策记录视图。审计不参与决策。

## 15. 扩展点

| 扩展点       | 接口                                               | 说明                                                          |
| ------------ | -------------------------------------------------- | ------------------------------------------------------------- |
| Op 解析器    | `parse() -> [Op]`                                | 必须拆解复合命令；拆不动 → hazard                            |
| 对象分类器   | `classify(target) -> (object, q1, envelope)`     | 契约 = 三问；unknown 按 irreversible；模型无写权限            |
| 污点追踪器   | `taint(read/write)`                              | 路径集 + 文件中继；输出连接学习层输入隔离                     |
| 意图锚定器   | `attest(op)`                                     | verbatim / derived / none；**最高风险扩展点**，独立评审 |
| hazard 谓词  | `hazard(op)`                                     | 加新条件需逐条评审；**学习模型对它无写权限**            |
| 指纹提取器   | `fp(op)`                                         | 归一化；歧义即新指纹                                          |
| 学习模型     | `routine(op, model)`                             | 目标轴 schema 白名单；键入确认门；版本失效                    |
| 记忆存储     | `blocked / memory`                               | 作用域、过期、版本失效                                        |
| 强制层适配器 | `enforce_level() -> {none, unix, network, full}` | 决定放行域矩阵（§11）                                        |
| 规则层       | `tighten`                                        | 仅可收紧，永不越过任何一行                                    |

**迭代路径**：先实现解析器拆解 + 三问分类 + B1–B4 + hazard 最小集 + 指纹记忆 + Unix 基线强制层；学习层后置——先跑纯指纹 + 弹窗，拿真实弹窗分布与批准数据，再开例行学习（只挂 build_artifact 与工作区读）。核心七行不动。

## 17. 诚实披露

| 缺口                                 | 影响                                                                                                                                              | 兜底                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **"和用户自己使用一样"的边界** | 系统看到 op，用户有的是意图；用户容忍自己的失误，系统代行失误不是用户意图                                                                         | 例行动作同频、新动作必问；新颖性检测不许乐观填充；"一样"只在零纠正惯例上成立               |
| **机械保证的真实范围**         | 机械的只有：底线（B1 秘密检测、B2 灾难模式、B3 污点判定、B4 通道判断）、hazard 骨架、非交互 fail-closed、审计哈希链。指纹与例行是校准的概率性放行 | 红队按"hazard 被绕过 + 模型被投毒后还剩什么"设计                                           |
| **校准质量无机械保证**         | 例行误判 = 静默错误，不可见                                                                                                                       | 目标函数 = 纠正数非弹窗数；留痕视图强制可达；纠正即连带回滚；纠正率超阈值永久弹窗          |
| 学习模型是新攻击面                   | 注入种植模式、模型投毒泛化                                                                                                                        | 输入隔离（污点会话不进模型）、schema 白名单、B4 信任根、键入确认门、版本失效、可检查可清空 |
| 无强制层时执行/出站类放行是概率性的  | 进程内出站不可见；B1 残余无兜底                                                                                                                   | 放行域矩阵（§11）：无网络件时执行/出站限 once；Unix 基线优先落地；如实声明                |
| 分类器误判                           | 操作进错 hazard/例行车道                                                                                                                          | unknown 按 irreversible；学习无风险轴写权限；改判限制与版本失效                            |
| 指纹归一化歧义                       | 记忆错绑                                                                                                                                          | 歧义即新指纹；绑定 + 内容哈希                                                              |
| 解析器不认识的语法                   | 复合命令整体绕判                                                                                                                                  | 拆不动 → hazard + 不可指纹化；整链原子                                                    |
| 敏感路径集是启发式                   | 集合外敏感文件不被标记                                                                                                                            | 默认项保守；用户可追加；污点隔离进模型                                                     |
| TOCTOU                               | 批准到执行之间目标被换                                                                                                                            | 每 op 落盘前重校验；symlink 变更回 hazard                                                  |
| 文件中继标记可丢失                   | 手动移动文件丢标记                                                                                                                                | 路径集兜底；已知缺口                                                                       |
| 审计链内部篡改                       | 内核被攻破可重写链                                                                                                                                | 链头周期外锚；篡改需攻破两处                                                               |
| `derived` 锚定依赖 UI 可信侧       | 直通被诱导                                                                                                                                        | 真人通道 + round_clean + 仅当次；意图锚定器独立评审                                        |

**核心声明**：机械保证 = 底线 + hazard 骨架 + 非交互 fail-closed + 审计哈希链。指纹与例行是"校准的概率性放行"，其上限 = hazard 完备度 + 校准质量。系统代决策的可靠性由纠正率持续度量，不由任何单点保证。红队验收按"hazard 被绕过 + 模型被投毒后还剩什么"设计。
