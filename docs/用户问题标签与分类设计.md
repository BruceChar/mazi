# 用户问题入库与标签分类系统设计

> 版本：v0.1 · 状态：设计定稿
> 范围：packages/libs（契约）、packages/runtime（存储/标注）、apps/api（接口）、apps/webui（视图）。
> 关系：本文**修订** docs/用户行为流设计文档.md 的存储决策（问题从 JSONL 文件迁到 SQLite 权威库，JSONL 降级为导出格式）；标签体系与 docs/web/后端与存储设计.md 的 `user_interactions` / 画像投影衔接。

---

## 1. 目标与范围

1. **问题入库**：用户的每一次提问（`input`）以结构化行落入 SQLite，可按用户/会话/时间/类型/类别查询；不再只躺在 `~/.mazi/behavior/*.jsonl`。
2. **可标注**：每条问题带**言说类型**与**内容类别**标签，另有开放话题标签与可选属性。
3. **可演进**：标签是**版本化注册表**（数据驱动、自说明、可覆盖），不是散落在代码里的魔法字符串。
4. **不臆造**：机器标注必须携带来源与置信度；证据不足时留空并标记「待标注」。

非目标（本期）：向量检索/语义聚类（后续接 VectorStore）；多用户鉴权；云端同步。

---

## 2. 现状与问题

| 现状 | 问题 |
| --- | --- |
| 行为流按 `rootGoalId` 落 JSONL 文件 | 问题不可按类型/类别/时间跨会话查询；文件是导出格式却被当权威库 |
| `StreamEvent.type` 只有 input/feedback/authorization/approval | 「问题」只是 `input`，没有语义标签 |
| 后端文档有 `user_interactions`（未落地） | 与行为流职责重叠，需要收敛为单一权威模型 |

---

## 3. 设计原则

1. **事实与解释分离**：问题原文是事实；标签是解释。解释必须带 `source`（rule/llm/user）与版本。
2. **闭集轴 + 开放话题**：结构性轴（类型/主域/子类）是闭集枚举；话题是开放但规范化的受控词表。
3. **append-only**：行为与标签只追加；更正 = 新行（`source=user`），不 update/delete。
4. **权威单一**：SQLite 为权威库；JSONL 只是导出物（存储即导出 → 导出即存储的反向投影）。
5. **数据驱动**：分类法放 `config/question-taxonomy.json`（带 `_doc`/`version`，可被用户覆盖），遵循 auth `commands.json` 既有模式。

## 4. 存储：从 JSONL 文件到 SQLite 权威库

### 4.1 决策

- `BehaviorStore` 抽象不变（`append/list/clear/close`），新增 `SqliteBehaviorStore` 并设为默认；`JsonlBehaviorStore` 保留，仅用于导出与迁移。
- 问题在统一信封之外增加**实体投影** `user_questions`（便于查询/外键/标注）；反馈/授权/审批仍只在 `user_behaviors`。
- `MAZI_HOME/behavior` 目录语义降级为「导出目录」；`config.storage.behavior` 文案同步调整。

### 4.2 表结构（SQLite）

```sql
-- 统一行为信封（append-only；行为流权威库）
CREATE TABLE IF NOT EXISTS user_behaviors (
  behavior_id   TEXT PRIMARY KEY,     -- 确定性 = 分区 + ts（「ts 即 id」，重复导入幂等）
  ts            INTEGER NOT NULL,     -- 单调守卫 ts = max(base, last+1)
  user_id       TEXT,
  session_id    TEXT NOT NULL,        -- rootGoalId
  conversation_id TEXT,
  type          TEXT NOT NULL,        -- input|feedback|authorization|approval|setting|session
  ref_ts        INTEGER,              -- ref.ts（授权→审批锚点，供索引）
  ref_json      TEXT,                 -- ref 全量 JSON（含 anchor）
  data          TEXT NOT NULL,        -- JSON（含正文）
  created_at    INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_user_behaviors_user_ts  ON user_behaviors(user_id, ts);
CREATE INDEX IF NOT EXISTS idx_user_behaviors_session  ON user_behaviors(session_id, ts);

-- 问题实体（input 的规范化投影；标注与查询的主体）
CREATE TABLE IF NOT EXISTS user_questions (
  question_id   TEXT PRIMARY KEY,     -- ULID
  behavior_id   TEXT NOT NULL REFERENCES user_behaviors(behavior_id),
  ts            INTEGER NOT NULL,
  user_id       TEXT,
  session_id    TEXT NOT NULL,
  conversation_id TEXT,
  text          TEXT NOT NULL,
  derived       INTEGER NOT NULL DEFAULT 0,  -- 1=历史回填（非实时采集）
  created_at    INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_user_questions_user_ts ON user_questions(user_id, ts);

-- 标签：轴 × 标签 × 来源（用户覆盖=新行，append-only）
CREATE TABLE IF NOT EXISTS question_labels (
  question_id  TEXT NOT NULL REFERENCES user_questions(question_id),
  axis         TEXT NOT NULL,         -- speech_act|domain|category|topic|sentiment|urgency|sensitivity
  label        TEXT NOT NULL,
  source       TEXT NOT NULL,         -- rule|llm|user
  confidence   REAL,                  -- 0..1（llm 生效；rule=1）
  taxonomy_version INTEGER,           -- 分类法版本（可复现）
  model        TEXT,                  -- classifier 模型（llm）
  created_at   INTEGER NOT NULL,
  PRIMARY KEY (question_id, axis, label, source)
);
CREATE INDEX IF NOT EXISTS idx_question_labels_axis ON question_labels(axis, label);
```

### 4.3 有效标签（effective labels）与更正

- **单标签轴**（speech_act/domain）：每轴取来源优先级最高的一个标签：`user > llm > rule`。
- **多标签轴**（category/topic）：取各来源并集；`source=user` 可显式排除（`label=__none__` 或 `data.excluded`，本期用「用户覆盖整轴」语义：同轴存在 user 行时，忽略 rule/llm）。
- **更正**：用户改标签 = 追加 `source=user` 行；旧行保留，审计可回放（宁浪费空间，不改历史）。

### 4.4 迁移与回填

1. 启动时若 `mazi.db` 尚无 `user_behaviors` 行且存在 `~/.mazi/behavior/*.jsonl`：逐行导入（保序、过单调守卫），并记录 `migration: behavior-jsonl→db`。
2. 历史 run（采集上线前）无记录：沿用「历史提问回填」，写 `input` + `derived=1`，并触发一次标注。
3. 迁移后 JSONL 不删除（保留原始证据）；权威读路径切换为 DB。

### 4.5 导出

导出 = 从 DB 读 + 生成文件头 + JSONL 切片（`GET /api/users/:id/behaviors/export`）；**不再读写文件作为权威**。

## 5. 标签与分类体系（核心）

### 5.1 轴模型

| 轴 | 中文 | 基数 | 值来源 | 用途 |
| --- | --- | --- | --- | --- |
| `speech_act` | 言说类型 | 单标签 | rule+llm+user | 区分「任务/问题/陈述/反馈/决策…」 |
| `domain` | 主域 | 单标签 | rule+llm+user | 个人/成长/情感/专业/领域知识… |
| `category` | 子类 | 多标签 | llm+user | 主域内的细分（健康/财务/工程…） |
| `topic` | 话题 | 多标签（开放） | llm+user | 长尾关键词（typescript/sqlite…） |
| `sentiment` | 情感极性 | 单标签（可选） | llm | 正/中/负 |
| `urgency` | 紧迫度 | 单标签（可选） | llm | 低/中/高 |
| `sensitivity` | 敏感度 | 单标签（可选） | rule+user | 普通/敏感/秘密（治理） |

### 5.2 轴 A · 言说类型 `speech_act`（单标签，闭集）

| label | 中文 | 判据 | 例 |
| --- | --- | --- | --- |
| `task` | 任务/指令 | 祈使句；要求执行有副作用动作 | 「把这个文件改成 TS」 |
| `question` | 问题 | 疑问句/求解释/求信息，无执行要求 | 「这个设计有什么根本问题？」 |
| `statement` | 陈述 | 提供事实/背景，无请求 | 「我用的是 Node 24」 |
| `feedback` | 反馈 | 对既有产出评价/纠偏 | 「太啰嗦，直接说结论」 |
| `decision` | 决策/授权 | 拍板、选择、授权 | 「用方案 B」「允许写入」 |
| `meta` | 元沟通 | 关于对话/系统/自身 | 「你是什么模型？」 |
| `chitchat` | 闲聊 | 社交寒暄，无信息诉求 | 「在吗」 |

判据优先级：显式祈使/疑问语气 > 是否引用既有产出（feedback）> 是否授权语义（decision）> 兜底 statement。

### 5.3 轴 B · 主域 `domain`（单标签，闭集）

| label | 中文 | 覆盖 |
| --- | --- | --- |
| `personal` | 个人 | 个人生活、习惯、家庭、吃喝住行 |
| `growth` | 成长 | 学习、心态、技能、长期规划 |
| `emotion` | 情感 | 情绪、关系、冲突、自我认同 |
| `professional` | 专业 | 职业工作、工程、管理、产品、研究 |
| `knowledge` | 领域知识 | 与技术/生活无关的学科知识（科学/人文/法律/医学） |
| `system` | 系统 | 关于本 agent/工作流/设置/数据 |
| `other` | 其他 | 无法归入且非零信息（兜底，需人工复核） |

未命中任何关键词且 LLM 置信度低于阈值 → **不出主域**（标 `待标注`），不强行 `other`。

### 5.4 轴 C · 子类 `category`（多标签，注册表内闭集）

| 主域 | 子类（示例，注册表可扩） |
| --- | --- |
| personal | `health` `finance` `relationship` `family` `lifestyle` `habit` |
| growth | `mindset` `learning` `skill` `career-plan` |
| emotion | `mood` `anxiety` `conflict` `motivation` `self-esteem` |
| professional | `engineering` `management` `product` `design` `research` `operations` |
| knowledge | `technology` `science` `humanities` `law` `medicine` `education` |
| system | `agent` `workflow` `settings` `data` |

约束：`category` 与 `domain` 必须兼容（注册表声明 `domain → categories` 映射）；不兼容的 LLM 输出被机械丢弃。

### 5.5 轴 D · 话题 `topic`（开放多标签）

- 规范：小写、连字符、单数优先（`typescript`、`sqlite`、`tax-filing`）。
- 抽取：LLM 从问题文本抽 1..5 个；已存在词表则复用，否则新增（受控词表演化）。
- 别名归一：注册表维护 `aliases`（`ts→typescript`、`nodejs→node`）。
- 话题是长尾检索面，不参与画像主维度。

### 5.6 轴 E · 属性（可选，默认关闭）

`sentiment`（positive/neutral/negative）、`urgency`（low/medium/high）、`sensitivity`（normal/sensitive/secret，触发脱敏与本地-only 策略）。属性属隐私敏感项，默认不采集，由用户显式开启。

### 5.7 注册表：`config/question-taxonomy.json`

数据驱动、自说明、版本化（对齐 auth `commands.json`）：

```jsonc
{
  "$schema": "...",
  "version": 1,
  "_doc": { "speechAct": "言说类型判据", "domains": "主域→子类映射" },
  "speechAct": ["task", "question", "statement", "feedback", "decision", "meta", "chitchat"],
  "domains": {
    "personal": ["health", "finance", "relationship", "family", "lifestyle", "habit"],
    "growth": ["mindset", "learning", "skill", "career-plan"],
    "emotion": ["mood", "anxiety", "conflict", "motivation", "self-esteem"],
    "professional": ["engineering", "management", "product", "design", "research", "operations"],
    "knowledge": ["technology", "science", "humanities", "law", "medicine", "education"],
    "system": ["agent", "workflow", "settings", "data"]
  },
  "aliases": { "ts": "typescript", "js": "javascript", "nodejs": "node" }
}
```

`version` 写入每条标签行（`taxonomy_version`），保证标注可复现；改注册表 = 新版本，重跑时可对照差异。

## 6. 标注流水线

### 6.1 规则预标注（写入时同步，零成本）

- `speech_act`：疑问词/问号→question；祈使动词（改/写/跑/修/加/删）→task；引用产出（“太…”“别…”）→feedback；授权词→decision。
- `sensitivity`：命中密钥/证件/密码词表→sensitive。
- 规则结果 `source=rule`，`confidence=1`；仅作兜底，可被 llm/user 覆盖。

### 6.2 LLM 精标（异步，结构化输出）

- 独立调用（复用 TocAnalyst 的 provider 通道），输入=问题文本 + 注册表摘要，输出**严格 JSON schema**：`{ speechAct, domain, categories[], topics[], confidence }`。
- 机械验收：标签必须存在于注册表、category 必须属所选 domain，否则丢弃该项。
- 低于阈值（默认 0.6）或 schema 失败 → 不落该轴标签，标「待标注」；**不重试到臆造**。
- 写 `source=llm` + `model` + `taxonomy_version` + `confidence`。

### 6.3 用户覆盖

- 用户在 UI 改标签 → 追加 `source=user` 行；同轴生效优先级最高。
- 用户可一键「重新标注」（新增 llm 行，不删旧行）。

### 6.4 幂等与去重

- 同一 `question_id + axis + label + source` 主键去重；重跑幂等。
- 分类任务失败只留系统日志，不阻断主流程（问题已入库）。

## 7. 接口契约

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/api/users/:userId/questions?type=&domain=&category=&topic=&q=&from=&to=&limit=&cursor=` | GET | 问题查询（轴过滤 + 全文 + 时间窗 + 分页） |
| `/api/questions/:questionId` | GET | 单条：原文 + 有效标签 + 标注来源 |
| `/api/questions/:questionId/labels` | POST | 用户覆盖标签（append-only；body: `{ axis, labels[] }`） |
| `/api/questions/:questionId/classify` | POST | 重新标注（llm，新增行） |
| `/api/question-taxonomy` | GET | 分类法注册表（含 version 与 _doc） |
| `/api/users/:userId/behaviors/export` | GET | 导出（DB → JSONL 切片，见 §4.5） |

问题视图线协议（libs）：`UserQuestionView = { questionId, ts, text, derived, sessionId, labels: { speechAct?, domain?, categories[], topics[], source, confidence } }`。

## 8. UI

- **行为链/问题视图**：每条问题显示「言说类型徽标 + 主域 + 子类 chips + 话题 chips」，支持按轴过滤与全文检索。
- **画像**：新增「类别分布」「言说类型分布」机械特征（来自标签计数，非 LLM 结论）。
- **标签编辑**：问题详情内联编辑；「重新标注」按钮；来源（rule/llm/user）与置信度可见。
- 「待标注」以弱提示呈现，不阻塞。

---

## 9. 隐私与治理

1. 默认**本地库 + 本地标注**；LLM 精标可关闭（仅保留规则标签）。
2. `sensitivity` 命中 → 原文不入 LLM 调用（只标 rule），并在导出时可剥离文本。
3. 标签是解释：可随时重算；问题原文是资产：只在用户显式「清除」时删除。
4. 删除遵循治理操作：`clear` 删问题 + 标签（级联），导出保留能力在清除前使用。

## 10. 验收标准

| # | 验收项 | 标准 |
| --- | --- | --- |
| QQ-1 | 问题入库 | 新会话问题落 `user_questions` + `user_behaviors`；进程重启后仍在 |
| QQ-2 | 文件非权威 | 删除 `~/.mazi/behavior/*.jsonl` 后查询/画像不受影响 |
| QQ-3 | 标签来源 | 每条标签有 `source`；llm 行有 `confidence/taxonomy_version/model` |
| QQ-4 | 注册表校验 | 非注册表标签/域-子类不兼容被机械丢弃 |

| QQ-6 | 用户覆盖 | 覆盖后查询生效，旧行保留（append-only） |

| QQ-8 | 导出 | export 由 DB 生成，格式与旧 JSONL 兼容 |
| QQ-9 | 纯用户资产 | 标签可重算；问题原文不因重算改变 |
