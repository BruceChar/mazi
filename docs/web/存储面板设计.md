# 存储面板设计（Storage Panel）

> 版本：v0.1
> 依据：docs/web/后端与存储设计.md（SQLite 默认存储、MAZI_HOME/mazi.db）、docs/webui.md（右侧栏审计/Context/日志）。
> 范围：右侧栏新增「存储」页签，把 SQLite 数据库当作可视化看板：各表数据量、占用空间、表数据浏览、关键字搜索、库级使用量。

---

## 1. 背景与目标

后端默认以单文件 SQLite（`$MAZI_HOME/mazi.db`，见 runtime paths.ts）持久化 Goal/Task/Step、
sessions/turns/steps、user_interactions、failure_ledger。当前只能通过 `/api/health`、`/api/config`
看到数据库路径，没有任何手段从 UI 观察「数据存在哪、有多少、占多大」。

目标：

1. **存储总览**：数据库路径、文件大小、页统计（page/free）、各表行数与占用空间。
2. **逐表浏览**：选择某张表查看列定义与分页数据，JSON 单元格可展开。
3. **搜索**：对全库文本列做关键字搜索，命中按表分组；进入表视图后可在表内过滤。
4. **使用量可视化**：以占用空间占比条 + 排行列表展示「谁最占地方」。

明确不做：写入/编辑/删除数据（只读看板）、迁移管理、跨驱动（PostgreSQL 预留不实现）。

---

## 2. 数据来源

- 数据库文件：`MaziPaths.dbPath`（`MAZI_HOME/mazi.db`）。
- 表清单与列：`sqlite_master` + `PRAGMA table_info`。
- 行数：`SELECT COUNT(*)`。
- 占用空间：SQLite `dbstat` 虚拟表按对象聚合 `SUM(pgsize)`；不可用时降级为 `null`（UI 隐藏大小，仅显示行数）。
- 库级页统计：`PRAGMA page_size / page_count / freelist_count`，文件大小 `fs.statSync`。

已存在的表（当前版本）：`goal_nodes/goal_tasks/goal_steps`、`sessions/turns/steps`、
`user_interactions`、`failure_ledger`。面板不硬编码表名，全部动态发现，后续新增表自动出现。

---

## 3. 后端 API 契约

统一 `/api` 前缀。全部 GET、只读、无副作用。

### 3.1 GET /api/storage

存储总览。

```jsonc
{
  "driver": "sqlite",
  "path": "/Users/xx/.mazi/mazi.db",
  "exists": true,
  "fileBytes": 2682880,        // mazi.db 文件大小；不存在为 0
  "walBytes": 0,               // -wal 附属文件大小
  "pageSize": 4096,
  "pageCount": 655,
  "freePages": 0,
  "freeBytes": 0,
  "sizeSource": "dbstat",      // "dbstat" | "unavailable"
  "tables": [
    {
      "name": "goal_steps",
      "columns": [{ "name": "step_id", "type": "TEXT", "pk": true }],
      "rows": 451,
      "bytes": 2281472,        // 表数据页字节；sizeSource 不可用时为 null
      "indexBytes": 53248,     // 该表全部索引页字节
      "indexes": 2
    }
  ],
  "totals": { "tables": 8, "rows": 718, "bytes": 2560000, "indexBytes": 200000, "dataBytes": 2682880 },
  "updatedAt": 1700000000000
}
```

- 表按 `bytes` 降序（相同则按行数）；无大小的表排在最后。
- 数据库文件不存在时返回 `exists:false`、空 `tables`，不报错（首次启动尚未落库）。

### 3.2 GET /api/storage/tables/:name?limit=&offset=&q=

单表分页数据。

| 参数     | 默认 | 约束                    |
| -------- | ---- | ----------------------- |
| limit    | 50   | 1..200                  |
| offset   | 0    | >=0                     |
| q        | 空   | 表内过滤关键字（含即命中，大小写不敏感） |

```jsonc
{
  "table": "goal_steps",
  "columns": ["step_id", "task_id", "goal_id", "json"],
  "rows": [ { "step_id": "...", "task_id": "...", "goal_id": "...", "json": "{...}" } ],
  "total": 451,       // 过滤后的总行数
  "offset": 0,
  "limit": 50,
  "query": ""
}
```

- 表名不存在或为 SQLite 内部表 → 404 `{ error: "table not found" }`。
- 过滤对每个列做 `instr(lower(CAST(col AS TEXT)), lower(:q)) > 0`，字面匹配、不解析 LIKE 通配符。
- 排序：优先主键列，无主键时 `rowid`，保证翻页稳定。

### 3.3 GET /api/storage/search?q=&limit=

全库搜索。

| 参数  | 默认 | 约束   |
| ----- | ---- | ------ |
| q     | 空   | 空则返回空结果 |
| limit | 5    | 1..50，每张表最多返回的行数 |

```jsonc
{
  "query": "permission",
  "total": 12,          // 命中行数合计
  "tables": [
    { "table": "goal_steps", "matches": 9, "rows": [ { "step_id": "..." } ] }
  ]
}
```

- 仅返回 `matches > 0` 的表，按 `matches` 降序。
- 单次搜索逐表扫描 + 限制返回行，避免大表拖垮 UI。

## 4. 前端交互设计

右侧栏页签：审计 / Context / 日志 / **存储**。默认仍为「审计」。

「存储」面板自上而下：

1. **总览卡**：数据库路径（可 hover 看全路径）、文件大小、页数、表数、总行数；右上角「刷新」。
2. **占用条**：按表的 `bytes` 画堆叠占比条（Top N + 其他），下方图例显示色块与名称。
3. **搜索框**：输入即触发全库搜索（300ms 防抖）；结果按表分组，点击某条结果进入该表视图。
4. **表清单**：每行 = 表名 + 迷你占比条 + 行数 + 大小 + 占比；点击进入表视图。
5. **表视图**（选中表后替换清单）：
   - 面包屑「← 全部表 / 表名」返回；
   - 表内过滤框（复用 `q`）；
   - 列头 + 分页数据（每页 50，上一页/下一页/页码）；
   - 单元格默认单行截断，点击行展开完整内容（JSON 列格式化为缩进文本）。

视觉沿用现有审计面板的语言：`audit-section` 卡片、等宽 `seg-content`、`empty-hint` 空态、
CSS 变量（`--bg-panel`/`--border`/`--accent` 等），不新增主题。

## 5. 安全与性能

- **只读**：所有连接以 `readOnly: true` 打开，仅 SELECT/PRAGMA；不暴露任何写端点。
- **注入防护**：表名先经 `sqlite_master` 参数化校验，再以双引号转义标识符；过滤值全部走绑定参数。
- **资源上限**：`limit` 上限 200（表数据）/50（搜索）；搜索逐表限制返回行；每次请求独立开关连接，不长期持有。
- **大字段**：值序列化时把 BigInt 归一到 number/string、Buffer 归一为 `<BLOB n bytes>`，避免 JSON 序列化失败。

## 6. 验收标准

| #   | 验收项       | 标准                                                                 |
| --- | ------------ | -------------------------------------------------------------------- |
| S1  | 总览可用     | `GET /api/storage` 返回文件大小/页统计/全部用户表行数与占用        |
| S2  | 表数据浏览   | `GET /api/storage/tables/:name` 支持 limit/offset，返回列与行       |
| S3  | 表内过滤     | 传 `q` 时 total 与 rows 均为过滤结果，字面匹配、大小写不敏感        |
| S4  | 全库搜索     | `GET /api/storage/search?q=` 跨表命中并按表分组                    |
| S5  | 只读安全     | 非法/不存在表名 404；无写接口；标识符转义                            |
| S6  | UI 接入      | 右侧栏出现「存储」页签，总览/占用条/搜索/表浏览均可用                |
| S7  | 回归         | vitest 全绿 + vue-tsc/biome 干净 + 每 feature 单原子提交             |
