## 0. 结论先行

| 决策点 | 结论 |
| --- | --- |
| 默认链路 | **浏览器只做采集 → 本机 API → sherpa-onnx（Node addon，本地 CPU 推理）流式 ASR**，音频只走 `127.0.0.1`，零 API key、零公网（模型下载除外） |
| 默认引擎 | 本机流式识别；**服务启动即后台自动下载/安装模型**（默认中文轻量 **52MB**），用户无需手动选择 |
| 「默认开启实时监听」的定义 | 设置默认 `enabled=true`；完成麦克风授权 + 模型安装后，**页面可见期间默认连续监听**，无需每次手动开麦；不是后台/锁屏常驻（浏览器不允许） |
| 降级 | 本机模型不可用 → 明确报错并回退文字输入；Chrome 系可选「浏览器内置 on-device 识别」实验项（**禁止静默回退云端**）；不做云端 ASR 默认路径 |
| 不选 | whisper.cpp / faster-whisper / transformers.js（非真流式、中文弱）、Vosk（停更、中文 WER 高）、FunASR Python 直跑（引入 Python 栈） |
| 对 runtime 的影响 | **零改动**：ASR 在 UI 侧完成，最终只产出文本，复用现有 `POST /api/sessions` 与 Composer 提交流程；不引入 `AudioBlock`、不改 provider |
| 新增后端 | `apps/api/src/voice`（WebSocket + 模型管理 + ASR child process）；新增纯契约包 `packages/voice`（协议 / 模型注册表 / 引擎接口） |
| 新增前端 | `apps/webui/src/voice/*`（采集、VAD、状态机、WS 客户端）、Composer 语音入口、Settings → Voice |
| 最大风险 | 本机流式模型中文 CER / 首字延迟无公开数字，必须真机实测；sherpa addon 动态库与 Node 24 ABI 需三平台冒烟；默认开麦的信任成本与权限持久性需产品验证 |

> **P0 实现说明（2026-11-08）**：为避免新增传输依赖，传输采用本机 HTTP 分块（`POST /api/voice/asr/chunk`）而非 WebSocket；共享契约落在 `packages/libs/src/voice.ts`；`sherpa-onnx-node` 已作为 `apps/api` 依赖声明，服务启动时后台自动下载/安装默认本机模型（3 次自动重试），用户不需要手动选择或安装；模型就绪后 `auto` 优先本机。WS / packages/voice / 两遍识别保留为 P1。详见 §17。

> **2026-11-08 最终方案（当前实现以此为准，详见 §18）**：
> - **只做本机识别**：浏览器 Web Speech / 云端识别完全移除，不再显示浏览器同意卡片。
> - **DSH 同款整段离线转写**：点击麦克风开始录音，再次点击停止；停止后用 SenseVoiceSmall + Silero VAD 一次性离线转写，结果直接写入输入框，用户手动点发送。
> - **不做流式 partial / 自动发送 / 常驻监听**；录音期间不写输入框；单次录音上限 5 分钟。
> - **输入框上方不再显示语音状态 / 模型安装 / 浏览器识别卡片**；模型自动安装状态只在 Settings → Voice 查看。
> - 麦克风按钮位于**发送按钮左侧并放大**。
> 下方历史章节中的 Web Speech 降级、流式 zipformer、VAD endpoint、自动发送、VoiceBar 等均为设计演进记录，与本节和 §18 冲突处以后者为准。

## 1. 需求与边界

### 1.1 原始需求与澄清

| # | 需求 | 设计响应 |
| --- | --- | --- |
| R1 | 增加语音输入功能 | 麦克风采集 + 实时转写；final 文本注入 Composer，可编辑后发送 |
| R2 | **默认开启实时监听** | 默认设置开启；授权 + 模型就绪后自动进入连续监听；页面可见才监听；一键暂停 |
| R3 | 免费 | 默认链路全部免费：sherpa-onnx 代码 Apache-2.0、模型免费下载、无 API key、无云服务账单 |
| R4 | 原需求提到「免费的 TTS」 | **用户后续确认：TTS 不需要，只要语音输入识别**。TTS 从设计与调研中移除 |
| R5 | 先调研方案，给设计文档 | 本文 + 两份调研文档（ASR、UX/隐私） |

### 1.2 目标

1. 用户无需离开键盘/鼠标，直接用中文（含中英混说）向 Composer 输入任务，final 文本可编辑、可撤销。
2. 默认识别在本机完成，音频不上传公网、不落盘；关闭页面即停止。
3. 实时 partial（目标首个 partial ≤ 800ms，p95），说完停顿后自动 final；自动发送可配置，默认带倒计时撤销。
4. 不改变既有权限/审批模型：语音只是「另一种输入方式」，不能提升权限、不能确认审批。
5. 失败可降级、可诊断、可回归；不因 ASR 故障阻塞文字输入。

### 1.3 非目标

- **TTS / 语音播报**（用户已确认不做）。
- 唤醒词（「Hey Mazi」）与后台常驻监听：浏览器页面生命周期内无法可靠实现，本期不做。
- 语音确认审批、语音提权：安全红线，永不做。
- 多说话人分离、声纹识别（涉及敏感个人信息）。
- 把原始音频存入会话/事件/审计（本期明确不保存）。
- 移动端 App / 原生客户端。

## 2. 现状与约束

### 2.1 代码事实（已核对）

| 事实 | 位置 | 对设计的影响 |
| --- | --- | --- |
| WebUI 是 Vue 3.5 + Vite 8 的纯浏览器 SPA，无 Electron/Tauri | `apps/webui/package.json` | 麦克风只能由浏览器 `getUserMedia` 采集 |
| Composer 是受控 textarea；IME composition 与 Enter 提交有专门判定 | `apps/webui/src/components/Composer.vue`、`apps/webui/src/scripts/composer-keys.ts` | 语音 final 必须通过 `emit('update:modelValue')` 注入，**不能模拟键盘事件** |
| 提交入口 `submitPrompt()` → `createRun()` → `POST /api/sessions` | `apps/webui/src/App.vue`、`apps/webui/src/scripts/store.ts` | 语音文本复用现有链路；不新增会话 API |
| 线程模型：NestJS 12 + Fastify 5；已有 SSE 单向事件流 | `apps/api/src/events/sse.ts`、`apps/api/src/main.ts` | SSE 不能上行音频；ASR 需要 WebSocket 或分块 POST |
| API 默认监听 `0.0.0.0`，CORS 默认反射 Origin | `apps/api/src/main.ts` | 本机语音端点必须做 loopback + Origin + 短期 token 校验，防止局域网被当作免费 ASR |
| WebUI 开发服 `host: 0.0.0.0`；生产 `serve.mjs` 的 `listen(PORT)` 未指定 host | `apps/webui/vite.config.ts`、`apps/webui/serve.mjs` | 用局域网 IP + http 打开时不是 secure context，`getUserMedia` 直接不可用；需明确 localhost/HTTPS |
| 设置体系：前端 localStorage（主题、run-settings、用户偏好）+ 后端 `$MAZI_HOME/settings.json` | `apps/webui/src/scripts/run-settings.ts`、`packages/runtime/src/configs/config-io.ts` | 语音交互偏好放 localStorage；引擎/模型等机器级配置放 settings.json |
| 无 WebSocket 依赖、无 native addon | `apps/api/package.json`、`packages/runtime/package.json` | 需新增 `@fastify/websocket`（或等价方案）与可选的 `sherpa-onnx-node` |
| Node ≥ 24、pnpm 10、biome | 根 `package.json` | addon 需 N-API / Node 24 兼容；pnpm 下动态库路径需冒烟 |

### 2.2 浏览器与安全上下文约束

- **secure context**：`getUserMedia` 只在 HTTPS 或 `localhost`/`127.0.0.1` 可用；`window.isSecureContext === false` 时直接隐藏语音入口并提示改用 localhost/HTTPS。
- **用户手势**：`AudioContext` 的 `resume()`、Safari 的采集/识别通常需要用户手势；冷启动不可能「静默自动开麦」，只能「尝试自动开麦，失败后一次点击」。
- **权限持久性**：Chrome 116+ 提供「仅这次 / 每次访问 / 不允许」，Firefox 115+ 摄像头/麦克风默认一次性授权；不能假设授权永久有效，每次进入语音模式都要实际探测 `getUserMedia` 并处理拒绝。
- **页面生命周期**：切后台、锁屏、关闭标签页都会停止采集；设计上明确「仅当前标签页前台监听」。
- **多标签页**：同一浏览器可能同时打开多个 mazi 标签页；用 `BroadcastChannel` 协调，只有一个标签页占用语音，其余显示「另一标签页正在使用语音输入」。
- **系统层权限**：macOS TCC、Windows 隐私设置可能在浏览器授权之外再拒一次；统一映射 `NotAllowedError` / `NotReadableError` 并给指引。

> 详细的浏览器支持矩阵、竞品模式与权限证据见 [`docs/research/voice/ux-privacy.md`](../research/voice/ux-privacy.md)。

## 3. 方案调研与选型

### 3.1 评估维度（按权重）

1. 真流式 partial（决定「实时监听」体验）
2. 默认零公网上传（音频不出本机）
3. 免费 / 零 API key
4. 中文为主、中英混说
5. 分发不需要用户装 Python 或编译工具链
6. macOS arm64 为主，Windows x64 / Linux x64 可用
7. 常驻监听的低 CPU / 低功耗

### 3.2 三条路线对比

| 路线 | 链路 | 隐私 | partial | 浏览器覆盖 | 成本 / 复杂度 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **B. 浏览器采集 + 本机流式 ASR** | AudioWorklet PCM → 本机 WS → sherpa-onnx | 音频只到 `127.0.0.1` | ✅ 真 chunk 流式 | 任意现代浏览器（只要求采集） | 需模型分发、CPU/内存、WS | **首选** |
| C. 纯浏览器 WASM ASR | 页面内 onnxruntime-web + 模型 | 最强（不出浏览器） | ⚠️ 视引擎，部分非真流式 | 需 WASM SIMD/WebGPU、内存受限 | 模型下载大、桌面性能低于 native | 备选 / 后续 |
| A. 浏览器 Web Speech API | Chrome/Safari 内置识别 | ❌ 默认云端上传（除非 on-device 且可用） | ✅ interimResults | Firefox 默认不可用（BCD 记 160 但 caniuse 标默认禁用，需实测）；Edge 不可靠；on-device 中文未核实 | 零安装、零成本 | 仅实验性降级，**不能默认** |

### 3.3 ASR 引擎对比（摘要）

| 引擎 | 许可 | 形态 | 真流式 | 中文质量（可核实） | 体积 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **sherpa-onnx（Node addon）** | 代码 Apache-2.0；权重逐个核对 | 本机进程内 / child process | ✅ | 流式 zipformer-large AISHELL-1 CER 1.75 | 模型 25MB / 48MB / 160MB 起 | **首选** |
| sherpa-onnx（WASM） | 同上 | 纯浏览器 | ✅ | 同上 | wasm 包约 15MB + 模型 | 备选 |
| Web Speech API（on-device） | 浏览器内置 | 纯浏览器 | ✅ interimResults | 未核实（zh-CN 语言包） | 0 | 实验性降级 |
| whisper.cpp / faster-whisper | MIT | native / Python sidecar | ❌ 滑窗伪流式 | Whisper-large-v3 平均 CER 9.86 | 547MB–1.5GiB | 不选 |
| Vosk | Apache-2.0 | addon/CLI | ✅ | small-cn WER 23.54 | 42MB | 不选（停更、中文弱） |
| transformers.js | Apache-2.0 | 纯浏览器 | ❌ | 更弱 | 需 WebGPU/WASM | 不选 |
| FunASR Python | MIT 工具包；权重自定义协议 | Python sidecar | ✅ | SenseVoice-L 4.47 / Paraformer-L 4.56 | 数百 MB | 不直选（Python 栈） |

> CER 数字来自各自论文/README，跨数据集不可直接比较；完整来源、模型体积、维护活跃度与 9 项「未核实」清单见 [`docs/research/voice/asr.md`](../research/voice/asr.md)。

### 3.4 选型结论

- **首选 B + sherpa-onnx Node addon**：唯一同时满足「真流式 + 默认不出公网 + 零 Python + 三平台预编译 + 中文可换模型」的组合。
- **模型策略**：默认中文轻量 `streaming zipformer zh 14M mobile`（约 52MB）；英文/中英混模型作为 P1 可选（需更小分发或按需单文件下载）。模型不提交到仓库、不打进 npm 包，首次启用按需下载 + sha256 校验。
- **权重文件实测**：旧版中英混模型的 int8 encoder/joiner 会截断长音频（30s 音频仅识别 29 字）；同一音频 fp32 识别 127 字。引擎优先选用 fp32 文件，只有归档缺少 fp32 时才回退 int8。
- **两遍识别（P1）**：流式小模型出 partial；finalize 时可选离线模型收尾提精度。注意 SenseVoice / FunASR 权重走自定义模型协议（非 Apache/MIT），是否启用需单独核对许可并在下载前展示。
- **Web Speech 仅作实验项**：且只在 `processLocally === true` 且语言包可用时启用；**禁止静默回退云端**。
- **不做 TTS**，不引入 `speechSynthesis`。

### 3.5 「免费」的边界与许可

| 组件 | 费用 | 许可 / 义务 | 默认 |
| --- | --- | --- | --- |
| sherpa-onnx 运行时 + Node addon | 免费（npm） | Apache-2.0；保留版权/许可声明 | ✅ 默认 |
| 流式 ASR 模型（small 系列） | 免费下载 | **候选权重许可需逐个核对**；上线前确认可商用/可再分发 | ✅ 默认（仅核对通过的模型） |
| 浏览器 Web Speech API | 免费、无 API key | 受浏览器厂商服务条款约束；默认云端上传 | ❌ 仅实验项 |
| 本地推理 | 免费 | 消耗 CPU/内存/电量 | — |
| 付费 ASR API | — | — | ❌ 不引入 |

> 「免费」指**无 API 账单、无订阅**；一次性模型下载流量（约 52MB）与本机 CPU 成本仍存在。模型不提交仓库，下载前展示体积与许可证。

## 4. 总体架构

### 4.1 分层

```text
┌──────────────────────────── 浏览器（apps/webui） ────────────────────────────┐
│ Composer.vue / VoiceStatus / Settings→Voice                                 │
│   ↑ final 文本（受控注入）        ↑ partial / final / error                  │
│ VoiceController（状态机 · 自动发送 · 多标签页协调）                           │
│   ↑ PCM16 16kHz + VAD 事件        ↑ WS JSON                                 │
│ AudioCapture（getUserMedia → AudioWorklet → VAD → 100ms 帧）                 │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ ws://127.0.0.1:6294/api/voice/asr/stream
┌──────────────────────────────────────▼──────────────────────────────────────┐
│ apps/api/src/voice                                                          │
│   VoiceController：capabilities / models / asr session token                 │
│   VoiceGateway：WS 鉴权（loopback + Origin + token）、帧限流、会话状态机       │
│   VoiceService：会话编排、超时、错误映射、指标                                │
│   AsrHost（child_process fork）：加载 sherpa-onnx-node，流式识别               │
│   ModelManager：$MAZI_HOME/voice/models 下载 / 校验 / 许可 / 磁盘检查          │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ 文本（不传音频）
┌──────────────────────────────────────▼──────────────────────────────────────┐
│ 既有链路：App.submitPrompt() → POST /api/sessions → runtime（零改动）          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 关键数据流

0. API 服务启动时后台自动安装默认本机模型（`capabilities.install` 返回进度），无需用户操作。
1. 用户点麦克风（或已授权后自动）→ `getUserMedia` → AudioWorklet。
2. Worklet 输出 16kHz / mono / Int16 PCM（100ms/帧）+ RMS 电平；能量 VAD 门控，静音帧不上行。
3. 检测到语音 → 申请一次性 token 并建立 WS 会话（每个 utterance 一条连接，句末关闭、下一句重连；本机 loopback 握手 <100ms，P1 可提前预取 token/预连接），发送 `start`，随后持续发送二进制 PCM 帧。
4. 本机 ASR child process 逐 chunk 解码 → `partial`（可多次修正）→ 静音 endpoint → `final`。
5. UI 将 partial 显示为 ghost 文本；final 追加到 Composer 草稿。
6. 自动发送倒计时（默认 1.5s）结束 → `submitPrompt()` → 既有 `createRun` → runtime。
7. 用户暂停/页面隐藏/切换标签/空闲 → 发 `end`、关闭 WS、释放 `MediaStream`（系统麦克风指示消失）。

### 4.3 模块清单

| 层 | 新增 / 修改 | 职责 |
| --- | --- | --- |
| 契约 | `packages/voice/src/protocol.ts`、`models.ts`、`engine.ts`（新增包） | WS 帧类型、错误码、模型注册表、`StreamingAsrEngine` 接口；**纯 TS，无 Node 内置依赖** |
| API | `apps/api/src/voice/*`（新增） | controller / gateway / service / model-manager / asr-host / engine 适配 |
| API | `apps/api/src/app.module.ts`、`apps/api/src/main.ts`、`apps/api/package.json` | 注册 VoiceModule、`@fastify/websocket` 插件、可选依赖 |
| WebUI | `apps/webui/src/voice/*`（新增） | settings / state / controller / capture / vad / ws-client / browser-fallback / text |

## 5. 交互与状态机

### 5.1 「默认开启实时监听」的产品定义

浏览器页面做不到「打开即静默常驻」，因此本设计的可验收定义是：

1. **默认偏好开启**：`voice.enabled = true`，用户不需要每个会话手动打开语音。
2. **一次性准备**：服务启动时后台自动完成本机模型下载/安装；用户只需授权麦克风，之后自动进入连续监听。
3. **自动开麦**：已授权且模型就绪时，页面首次用户交互（点击/按键）后自动启动；浏览器要求时降级为「一次点击」并说明原因。
4. **仅前台**：页面可见时监听；切后台/锁屏/空闲超时自动暂停，返回后可恢复。
5. **随时可停**：常驻状态条 + 快捷键（默认 `⌘/Ctrl+Shift+M`）+ 点击麦克风暂停；暂停即释放采集，系统麦克风指示消失。
6. **不后台偷听**：不做 Service Worker / 后台常驻监听。

### 5.2 状态机

状态与迁移（纯函数 reducer，`apps/webui/src/voice/state.ts`，可单测）：

```text
OFF ──enable──▶ REQUESTING ──granted+model──▶ ARMED
  ▲                  │ denied/error                 │ VAD speech
  │                  ▼                              ▼
  │               ERROR ◀──error── CAPTURING ◀──────┘
  │                  │                │ partial
  │                  │                ▼
  │                  │             PARTIAL
  │                  │                │ endpoint
  │                  │                ▼
  │                  │            FINALIZING
  │                  │                │ final
  │                  │                ▼
  │                  │            COMMITTED ──auto-send──▶ (既有 submitPrompt)
  │                  │                │ user edits / cancels
  │                  ▼                ▼
  └────────────── PAUSED ◀────────────┘
```

| 状态 | 含义 | UI | 麦克风 |
| --- | --- | --- | --- |
| `OFF` | 语音未启用（首次 / 用户关闭） | 麦克风按钮（灰），首次引导卡片 | 关 |
| `REQUESTING` | 请求权限 / 恢复 AudioContext / 加载模型 | loading + 「正在准备麦克风…」 | 尝试开 |
| `ARMED` | 已监听，等待说话 | 状态条「正在听…」+ 呼吸波形 | 开（VAD 门控） |
| `CAPTURING` | 检测到语音，采集中 | 波形活跃 + 「识别中…」 | 开 |
| `PARTIAL` | 有 interim 文本 | Composer ghost 文本 | 开 |
| `FINALIZING` | 端点已判定，等待 final | 「正在确认…」 | 开（短） |
| `COMMITTED` | final 已进入草稿，等待发送/编辑 | 倒计时 chip | 开（继续监听下一句） |
| `PAUSED` | 手动暂停 / 失焦 / 空闲 / 执行中 | 「已暂停」+ 恢复入口 | 关 |
| `ERROR` | 权限/设备/模型/网络错误 | 错误条 + 文字兜底 | 关 |

关键事件：`enable`、`permission.result`、`model.ready`、`vad.start`、`vad.end`、`asr.partial`、`asr.final`、`send.countdown`、`send.cancel`、`pause`、`resume`、`blur`、`idle`、`busy.changed`、`error`。

### 5.3 Composer 布局

```text
┌────────────────────────────────────────────────────────────────────┐
│  （textarea：已有草稿 + 语音 partial ghost 文本）                    │
│                                                                    │
│  [mic] 正在听…  ▂▄▂▁  [暂停]      workspace · 权限     model · 发送   │
└────────────────────────────────────────────────────────────────────┘
                     1.5s 后发送 · 点此编辑 · Esc 取消
```

- 麦克风按钮放在左下角工具区（workspace / 权限按钮旁），与现有 `ws-btn` 风格一致；图标用新增的线条 `mic` / `micOff` / `waveform`（遵循 `docs/webui.md` 的线条图标规范，不用 emoji）。
- partial 文本以灰色斜体 ghost 叠加在 textarea 光标处/下方，不写入 `prompt`（避免 IME 与 Enter 判定冲突）；final 才通过 `update:modelValue` 注入。
- 状态条只在 `ARMED/CAPTURING/PARTIAL/PAUSED/ERROR` 显示；`OFF` 只显示麦克风按钮与首次引导。
- 自动发送倒计时 chip：显示剩余时间 + 取消 + 编辑；用户开始说话/打字立即取消倒计时。
- 首次引导（非模态卡片：空会话欢迎区，或已有会话时 Composer 上方的一次性提示条）：说明「本机识别、音频不上传、可随时暂停」+「启用麦克风」+「设置」。

### 5.4 自动发送与多段输入

| 场景 | 行为 |
| --- | --- |
| 默认 | final 后 1.5s 倒计时，期间无输入则自动调用 `submitPrompt()` |
| 用户继续说话 | 取消倒计时，把新 final 追加到同一草稿（中文直接拼接，英文/代码术语加空格） |
| 用户打字 / 按 Esc | 取消倒计时，保留草稿，进入手动发送；若正在采集，立即结束当前 utterance 并丢弃未 final 的 partial，避免键盘与语音同时写 Composer |
| 识别为空 / 过短（<2 字或 <300ms） | 丢弃并提示「没听清，再说一次」；不发送 |
| 执行中（`busy`） | 默认暂停监听（见 §5.6），不产生新草稿；显示「执行中，语音已暂歇」 |
| 编辑模式（设置关闭自动发送） | final 只进草稿，用户 Enter 发送 |

> 为什么默认自动发送：语音输入的预期是「说完即走」；为降低误触发，保留 1.5s 可撤销窗口、final 可编辑、发送后仍可点停止，且语音不改变权限/不走审批捷径。该默认值建议在灰度中 A/B 验证。

### 5.5 键盘与无障碍

- `⌘/Ctrl+Shift+M`：暂停/恢复语音；`Esc`：停止当前采集/取消倒计时（不停止正在运行的 agent）。
- 状态变化通过 `aria-live="polite"` 播报（仅状态与 final，不对每个 partial 播报）。
- 波形动画尊重 `prefers-reduced-motion`；语音不可用时文字输入完全不受影响。
- 焦点管理：语音按钮可 Tab 聚焦，Enter/Space 触发；不劫持输入框快捷键。

### 5.6 暂停 / 恢复规则

| 触发 | 默认行为 | 可配置 |
| --- | --- | --- |
| 用户点暂停 / 快捷键 | 释放 `MediaStream`，状态 PAUSED | — |
| 页面隐藏 / 窗口失焦 | 自动暂停；回到前台后可自动恢复（需手势时提示一次点击） | `pauseOnBlur` 默认 true |
| 空闲 10 分钟无语音 | 自动暂停，省电 | `pauseAfterIdleMs` |
| agent 执行中（`busy=true`） | 暂停监听，run 结束后自动恢复 | `pauseOnBusy` 默认 true；P2 可做「执行中插话」 |
| 切换会话/工作区 | 停止当前识别会话，清空 draft（避免串话） | — |
| 另一标签页占用 | 本标签页只读提示，可「接管」 | BroadcastChannel |

## 6. 本机流式 ASR 服务设计

### 6.1 引擎接口（`packages/voice/src/engine.ts`）

```ts
export interface AsrAudioFormat {
  sampleRate: 16000;
  channels: 1;
  encoding: 'pcm16le';
}

export interface AsrPartial {
  type: 'partial';
  text: string;
  /** 同一 utterance 内单调递增，UI 用它丢弃过期 partial。 */
  revision: number;
  latencyMs?: number;
}

export interface AsrFinal {
  type: 'final';
  text: string;
  durationMs: number;
  latencyMs?: number;
  confidence?: number;
}

export interface AsrError {
  code: 'asr_failed' | 'timeout' | 'engine_unavailable' | 'rate_limited';
  message: string;
  retryable: boolean;
}

export interface StreamingAsrSession {
  /** 服务端可将 Uint8Array 直接映射为 Buffer；纯契约层不依赖 Node 内置类型。 */
  push(pcm: Uint8Array): void;
  end(): Promise<AsrFinal>;
  close(): void;
  onPartial(cb: (p: AsrPartial) => void): void;
  onError(cb: (e: AsrError) => void): void;
}

export interface StreamingAsrEngine {
  readonly id: 'sherpa-onnx';
  readonly modelId: string;
  open(opts: { language: string; format: AsrAudioFormat }): Promise<StreamingAsrSession>;
}
```

### 6.2 进程模型

- `AsrHost` 通过 `child_process.fork` 启动独立 Node 进程，加载 `sherpa-onnx-node`（调研时 npm 最新 2.0.1，2026-11）与模型；**不放在 API 主进程**：
  - 原生 addon 崩溃/泄漏不会拖垮 Nest API 与 SSE；
  - 模型常驻内存与 CPU 推理与 HTTP 事件循环隔离；
  - 可单独重启、限流、设 CPU 亲和（后续）。
- 主进程与 host 通过 IPC 传 `{type:'open'|'audio'|'end'|'close'}` 与 `{type:'partial'|'final'|'error'}`；PCM 帧 `ArrayBuffer` 直接 transfer，100ms/帧、3200 字节，IPC 开销可忽略。
- host 生命周期：首个语音会话懒启动；空闲 10 分钟退出并释放模型；崩溃后指数退避重启（最多 3 次），期间 API 返回 `engine_unavailable` 并提示文字输入。
- 并发：默认 `MAZI_VOICE_MAX_SESSIONS=1`（本地单用户）；第二个会话返回 `busy`。host 内部一个 recognizer，`end` 后立即 `close()` 释放。

> 备选：若 addon 在三平台冒烟中不稳定，切换到 `sherpa-onnx` 自带 WebSocket server 作为 sidecar，API 只做鉴权与转发；接口不变。

### 6.3 本机识别传输协议（P0：HTTP 分块；P1：WebSocket）

> **P0 实现采用 HTTP 分块**：客户端顺序 `POST /api/voice/asr/chunk`（JSON: sessionId/token/seq/pcmBase64/end），服务端返回 partial/final。WebSocket 设计保留为 P1 的低延迟替代，语义相同。P0 契约与端点见 §17.2。

WebSocket（P1 设计）：

端点：`GET /api/voice/asr/stream?token=<one-time>`（HTTP/1.1 Upgrade）。

> 接入说明：应用使用 Fastify，推荐在 `main.ts` 创建应用后、`app.listen()` 前对 Fastify 实例 `register(@fastify/websocket)`（调研时 11.x，与 Fastify 5 对齐）；在 VoiceModule 的 `onModuleInit` 里用 `fastify.get('/api/voice/asr/stream', { websocket: true }, handler)` 注册裸路由。Nest 的 `setGlobalPrefix('api')` **不作用**于裸 Fastify 路由，因此路径必须显式带 `/api`；REST 端点仍走 Nest Controller `@Controller('voice')`。

建立前：
```http
POST /api/voice/asr/sessions
{ "engine": "local", "modelId": "sherpa-streaming-zipformer-zh-14m-mobile",
  "language": "zh-CN", "format": { "sampleRate": 16000, "channels": 1, "encoding": "pcm16le" } }

200 { "sessionId": "...", "token": "...", "expiresAt": 1760000000000,
      "wsPath": "/api/voice/asr/stream", "maxUtteranceMs": 30000 }
```

WS 消息：

| 方向 | 类型 | 示例 |
| --- | --- | --- |
| C→S | `start` | `{"type":"start","sessionId":"...","language":"zh-CN"}` |
| S→C | `ready` | `{"type":"ready","engine":"local","modelId":"..."}` |
| C→S | binary | PCM16LE mono 16k，建议 100ms（3200B）/帧 |
| C→S | `ping` | `{"type":"ping","t":1760000000000}` |
| S→C | `pong` | `{"type":"pong","t":...}` |
| S→C | `partial` | `{"type":"partial","revision":3,"text":"帮我改一下","latencyMs":210}` |
| S→C | `final` | `{"type":"final","text":"帮我改一下这个文件的类型。","durationMs":2400,"latencyMs":180}` |
| S→C | `error` | `{"type":"error","code":"asr_failed","message":"...","retryable":true}` |
| C→S | `end` | `{"type":"end"}`（VAD 端点或手动停止） |
| S→C | `closed` | `{"type":"closed","bytesIn":32000}` |

约束：

- `start` 中声明的配置必须与创建 token 时一致；首帧 `start` 必须在 5s 内到达，否则关闭；`start` 前收到的 binary 丢弃。
- 每帧 ≤ 64KB；单次 utterance ≤ 30s（客户端 VAD 超时即发 `end`，服务端自动 final 并关闭）；单条 WS 连接 ≤ 5 分钟。
- 服务端按 `bytesPerSecond` 限流（16k × 2B × 1.2 冗余）；超限关闭 `rate_limited`。
- `partial.text` 是当前 utterance 的**累计假设（全量替换）**，不是增量 delta；`revision` 单调递增，UI 只接受 ≥ 当前 revision 的 partial，避免乱序。
- 模型 chunk 大小可配（建议 320ms–1s）；chunk 越小 partial 越快、CPU 越高，默认 320ms 起步，按实测调整。
- `end` 后服务端最多 3s 内返回 final 并关闭；客户端超时则本地 finalize 已收到的 partial（若有）并报错。
- 连接建立后 5s 未收到 `start`、或 30s 未收到任何音频帧则关闭；utterance 期间心跳 15s；客户端指数退避重连最多 2 次。
- token 用于**单次 WS 握手**（单次使用）；每个 utterance 申请一次，TTL 60s；P1 可在 ARMED 时预取以降低首字延迟。
- 日志只记录 sessionId / 时长 / 错误码，**不记录 PCM、不记录 transcript 文本**；`token` 在访问日志中脱敏。

### 6.4 模型管理

| 项 | 设计 |
| --- | --- |
| 存储 | `$MAZI_HOME/voice/models/<modelId>/`；`$MAZI_HOME/voice/models.json` 记录版本、sha256、许可接受时间 |
| 默认模型 | `sherpa-streaming-zipformer-zh-14m-mobile`（约 52MB，中文轻量；服务启动自动安装） |
| 下载 | `POST /api/voice/models/:id/download` 返回 jobId；`GET /api/voice/models/downloads/:jobId` 轮询进度；校验 sha256 后原子 rename；失败可重试 |
| 来源 | 固定官方 release/HuggingFace URL 白名单；不拼接用户输入；下载前展示体积 + 许可证 |
| 磁盘 | 预留 ≥ 2× 模型体积；不足返回 `disk_full` |
| 加载 | host 启动时按会话选择模型；模型常驻，空闲 10 分钟释放；不提交进 git/npm |
| 许可 | 默认模型只选 Apache-2.0 可商用权重；SenseVoice / FunASR 权重（自定义协议）若要用于 final 二遍，必须单独展示许可并记录用户确认，默认关闭 |

### 6.5 端点判定与 VAD

- 浏览器侧能量 VAD（P0）：自适应噪声底 + RMS 阈值；语音开始需连续 ≥150ms 超阈值；静音 ≥700ms 判定端点；最短语音 300ms；最长 30s。
- 发送策略：语音开始前的 300ms 预滚缓冲一起发送，避免吞首字；静音帧不上行（除非会话已开始，用于服务端判断终点）。
- P1 可换 Silero VAD（ONNX/WASM，MIT）提升嘈杂环境表现；`@ricky0123/vad-web` 许可证字段存疑，使用前需法务/人工确认。
- 端点最终以服务端 final 为准；客户端 `vad.end` 只触发 `end` 请求，不直接发送文本。

### 6.6 资源预算（目标值，待实测）

| --- | --- |

| 识别中 CPU | < 25% 单核（52MB 流式模型） |

## 7. 浏览器原生降级（实验）

仅作为「本机引擎不可用」时的可选实验项，**默认关闭**：

1. 检测 `window.SpeechRecognition || window.webkitSpeechRecognition`。
2. 仅当实现支持 `processLocally` 且 `available({ langs:['zh-CN'], processLocally:true })` 返回 `available`（或 `downloadable` 且用户同意安装语言包）时启用。
3. 设置 `lang='zh-CN'`、`interimResults=true`、`continuous=true`；`onend` 时按状态机重启，指数退避。
4. 错误映射：`not-allowed` → 权限；`no-speech` → 忽略；`network` → 提示不可用；`language-not-supported` → 隐藏入口。
5. **禁止静默回退云端**：若 `processLocally` 不可用或语言包不可用，不展示入口；不调用默认云端识别。
6. 若未来产品决定提供云端识别，必须作为独立设置项、二次确认、明确告知「音频将发送给浏览器厂商」，且默认关闭；本期不实现。

## 8. API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/voice/capabilities` | 引擎/模型/限制/安全上下文提示；不返回任何密钥 |
| POST | `/api/voice/asr/sessions` | 创建识别 session + token；校验模型已安装、并发限制 |
| POST | `/api/voice/asr/chunk` | **P0 实际传输**：上行 PCM16 base64、下行 partial/final；`end:true` 落定 final；单 session 30 分钟 |
| WS | `/api/voice/asr/stream?token=` | （P1 可选）上行 PCM、下行 partial/final |
| GET | `/api/voice/models` | 模型列表：id、体积、语言、许可、安装状态、磁盘占用 |
| POST | `/api/voice/models/:id/download` | 启动下载，返回 jobId |
| GET | `/api/voice/models/downloads/:jobId` | 进度 / 状态 / 错误 |
| DELETE | `/api/voice/models/:id` | 删除模型（可选，P1） |
| POST | `/api/voice/warmup` | 预热 host（可选，P1） |

> 说明：`engines.local` 由服务端返回；「浏览器 on-device 识别」是否可用只能由浏览器端探测（`processLocally` / 语言包），不放进服务端 capabilities。

Capabilities 响应示例：

```json
{
  "version": 1,
  "engines": {
    "local": { "available": true, "reason": null, "modelId": "sherpa-streaming-zipformer-zh-14m-mobile" }
  },
  "models": [
    { "id": "sherpa-streaming-zipformer-zh-14m-mobile", "sizeBytes": 50331648,
      "languages": ["zh", "en"], "license": "Apache-2.0", "installed": true }
  ],
  "limits": { "maxUtteranceMs": 30000, "maxSessionMs": 300000, "maxFrameBytes": 65536, "maxSessions": 1 },
  "security": { "loopbackOnly": true, "secureContextRequired": true }
}
```

错误码统一为 `{ code, message, retryable }`，与现有 API 错误过滤器的 `{ error }` 契约兼容（HTTP 层仍返回 `{ error }`）。

> 安全边界：**所有** `/api/voice/*`（含 capabilities、模型下载、session 创建）都默认仅接受 loopback 连接，并校验 `Origin` 与 `Host` 同源；模型下载会消耗磁盘与带宽，不能被跨站页面触发。模型 ID 与文件名以 `packages/voice/src/models.ts` 的注册表为准。

```ts
  maxUtteranceMs: number;        // 默认 30000
  inputDeviceId: string;         // 默认 'default'
  pauseOnBlur: boolean;          // 默认 true
  pauseOnBusy: boolean;          // 默认 true
  pauseAfterIdleMs: number;      // 默认 600000
  showPartial: boolean;          // 默认 true
  shortcut: string;              // 默认 'Mod+Shift+M'
  browserConsent: boolean;       // 浏览器云识别显式同意；默认 false
}
```

- 读取时与默认值深合并、按 `version` 迁移；损坏时回退默认（不抛错，参照 `run-settings.ts` 模式）。
- 只存偏好，不存音频/转写文本/设备标签等敏感信息。

### 9.2 服务端设置（`$MAZI_HOME/settings.json` 的 `voice` 段）

```json
{
  "voice": {
    "enabled": true,
    "engine": "local",
    "modelId": "sherpa-streaming-zipformer-zh-14m-mobile",
    "maxSessions": 1,
    "allowRemote": false,
    "modelDir": null
  }
}
```

- 只由 `ModelManager` / VoiceService 读取；不在前端暴露路径。
- `allowRemote=false` 默认：WS/ASR API 仅接受 loopback 连接；如未来要支持局域网/远程，必须配合 HTTPS + 反向代理认证，本期不做。

环境变量（优先级：env > settings.json > 默认值）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MAZI_VOICE_ENGINE` | `local` | `local` / `off` |
| `MAZI_VOICE_MODEL_DIR` | `$MAZI_HOME/voice/models` | 模型目录 |
| `MAZI_VOICE_MAX_SESSIONS` | `1` | 并发识别会话上限 |
| `MAZI_VOICE_ALLOW_REMOTE` | `false` | 是否允许非 loopback 连接（不建议开启） |
| `MAZI_VOICE_HOST_IDLE_MS` | `600000` | host 空闲退出时间 |

## 10. 隐私、安全与合规

### 10.1 隐私默认值

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 音频上传 | ❌ 不上传公网 | 默认只到 `127.0.0.1` 的本机 API |
| 音频落盘 | ❌ 不落盘 | 仅内存环形缓冲；host 不写临时文件；日志不含 PCM |
| 转写文本 | 仅作为用户输入进会话 | 与打字同权：可见、可编辑、可删；不额外写入 audit/telemetry |
| 浏览器云识别 | ❌ 关闭 | 不静默回退；实验项仅 on-device |
| 模型下载 | 需联网一次 | 只连接固定白名单源，校验 sha256 |
| 状态指示 | 应用内 + 系统麦克风指示 | 暂停即释放采集 |
| 多标签页 | 单标签占用 | BroadcastChannel 协调 |
| 诊断数据 | 本地计数，不含文本/音频 | 可选上报需单独同意（本期不做） |

### 10.2 威胁模型与防护

| 威胁 | 防护 |
| --- | --- |
| 局域网内其他设备调用 ASR 端点（API 默认 0.0.0.0） | 默认仅 loopback；检查 `req.socket.remoteAddress`；`allowRemote=false` 时拒绝 |
| 跨站 WebSocket 劫持（CSWSH） | 校验 `Origin` 与 `Host` 同源；一次性、短期（60s）HMAC token；token 单次使用 |
| 跨站 REST 触发模型下载 / 建会话 | 所有 `/api/voice/*` 校验 Origin 同源 + loopback；下载接口另做速率与并发限制 |
| token 泄漏到日志 | 访问日志对 `token` query 参数脱敏；不建议放 URL referer（WS 不发送 Referer 到第三方） |
| 任意模型路径 / 路径穿越 | 模型 ID 白名单；下载 URL 固定；解压校验路径与 sha256 |
| 帧洪泛 / 内存耗尽 | 帧 ≤64KB、字节速率限制、并发 1、会话超时、缓冲区上限 |
| 转写注入 / XSS | transcript 只以纯文本注入 textarea；渲染沿用现有 markdown 转义 |
| 语音误触发执行 | 不改变权限；审批必须点击；发送后仍可停止；默认暂停执行中监听 |
| 权限被撤销 | 每次开麦实际探测；失败降级文字并说明 |
| 多标签页争抢麦克风 | BroadcastChannel 抢占；后到标签只读提示 |
| addon 崩溃拖垮 API | child process 隔离 + 自动重启；失败降级文字 |
| 模型许可风险 | 下载前展示许可；默认仅 Apache-2.0 权重；自定义协议模型默认关闭 |

### 10.3 合规提示（非法律意见）

- 音频属于个人信息；默认本机处理符合数据最小化原则；若未来提供云端识别，需按 PIPL 告知目的/方式/种类/期限并取得同意，提供撤回入口。
- 不做声纹识别，避免敏感个人信息。
- 企业/离线场景：本机 ASR 可完全断网运行，是相对云产品的差异点。

## 11. 失败与降级矩阵

| 场景 | 检测 | 行为 | 文案 |
| --- | --- | --- | --- |
| 非安全上下文（LAN http） | `!window.isSecureContext` / 无 `mediaDevices` | 隐藏麦克风，仅文字 | 「当前地址不是安全上下文，浏览器禁止麦克风。请用 http://localhost:6295 或 HTTPS。」 |
| 无模型 | capabilities.install.status=running | 显示「服务启动自动安装语音包（约 52MB）」进度，不提供手动安装 | 「本机语音模型自动安装中，音频不会上传。」 |
| 模型下载失败 | job error / sha256 mismatch | 重试 + 手动链接；文字兜底 | 「语音包下载失败，可重试或继续用文字输入。」 |
| 权限拒绝 | `NotAllowedError` | ERROR，不重复弹窗；指引地址栏 | 「麦克风被拒绝。点地址栏麦克风图标重新允许。」 |
| 无麦克风/被占用 | `NotFoundError` / `NotReadableError` | ERROR，文字兜底 | 「没有检测到麦克风，或麦克风被其他应用占用。」 |
| WS 失败/断线 | 连接失败 / 90s 无消息 | 重连 2 次；仍失败则保留已识别文本，文字兜底 | 「本机识别暂不可用，已切回文字输入。」 |
| 首 partial 超时 3s | 无 partial | 关闭该次会话，提示重说 | 「没听到声音，请再说一次。」 |
| host 崩溃 | child `exit`/error | 自动重启；期间 `engine_unavailable` | 「语音识别进程已重启，请重试。」 |
| 服务端忙 | `busy` | 排队 1 次/提示 | 「语音识别忙，请稍后再说。」 |
| 页面隐藏/锁屏 | `visibilitychange` | PAUSED，释放采集；返回恢复 | 「语音输入已暂停（页面切到后台）。」 |
| 空闲超时 | 10 分钟无语音 | PAUSED | 「语音已自动暂停，点麦克风恢复。」 |
| 浏览器 on-device 不可用 | `processLocally` 不支持/语言包缺失 | 隐藏实验入口 | 不展示 |
| 另一标签页占用 | BroadcastChannel | 只读 + 接管按钮 | 「另一标签页正在使用语音输入。」 |

### 17.2 P0 实际 API 契约

与 §8 的差异：WS 端点改为 HTTP 分块；其余语义一致。

```http
GET  /api/voice/capabilities
GET  /api/voice/models
POST /api/voice/asr/sessions   { "modelId"?, "language"? }
     -> { sessionId, token, expiresAt, limits }
POST /api/voice/asr/chunk      { sessionId, token, seq, pcmBase64, end? }
     -> { type: "partial"|"final"|"error", revision?, text?, latencyMs?, done?, error? }
POST /api/voice/models/:id/download  -> { jobId }
GET  /api/voice/models/downloads/:jobId -> { status, progress, bytesReceived, ... }
DELETE /api/voice/models/:id
```

- 鉴权：session token 在内存 Map 中，随 session 结束/过期删除；所有 `/api/voice/*` 默认仅 loopback + Origin 同源。
- 音频：PCM16LE / mono / 16kHz；客户端每 100ms 顺序上传一帧（base64），同一时刻只有一个在途请求；服务端限制 chunk 64KB、单 utterance 30s、session 5min、并发 1。
- final：用户点击停止时发送 `end:true`；服务端调用引擎 `end()` 后返回 final 并释放 session。
- 日志不记录 PCM / transcript；只记录 sessionId、耗时、错误码。

### 17.3 当前录音行为（2026-11-08 收敛）

1. **仅本机引擎**：不再解析 browser-on-device / browser-cloud；浏览器 Web Speech 代码与同意卡片已移除。
2. **点击开始**：点击发送键左侧麦克风 → 请求麦克风权限 → 建立本机 ASR session → 持续上传 PCM，partial 实时写入输入框。
3. **点击停止**：再次点击麦克风 → 停止采集 → 发送 `end` → final 写入输入框；**不自动发送**，用户自行点发送。
4. **持续录音**：不做 VAD 端点/自动分段；录音持续到用户停止（服务端 session 上限 30 分钟）。
5. **模型自动安装**：服务启动后台安装；安装中点击麦克风会提示等待，安装完成后可直接使用。
6. **无 UI 卡片**：输入框上方不再渲染浏览器识别、模型安装、自动发送倒计时等卡片；安装状态只在 Settings → Voice 展示。

### 17.4 本机引擎与服务启动自动安装

服务启动时自动完成本机模型准备，用户不需要手动选择或点击安装：

1. `sherpa-onnx-node` 已声明在 `apps/api/package.json` 的依赖中，`pnpm install` 时安装；平台预编译包由该包按 OS/arch 自动选择。
   - 注册表保留旧版 `sherpa-streaming-small-bilingual-zh-en`：已有安装时自动识别并优先使用，不会重复下载；只有本机没有任何已安装模型时才自动下载推荐轻量模型。
2. API 启动后由 `main.ts` 调 `ModelManager.ensureDefaultModel()` 后台自动下载默认模型（3 次指数退避重试）；`MAZI_VOICE_AUTO_INSTALL=0` 可关闭（CI/离线）。
3. 模型落在 `$MAZI_HOME/voice/models/`（可用 `MAZI_VOICE_MODEL_DIR` 覆盖），归档校验后解压，sha256 记录到 `$MAZI_HOME/voice/models.json`；下载/安装进度通过 `capabilities.install` 返回。
4. 安装完成前 `capabilities.engines.local.available=false`，UI 显示「本机语音模型自动安装中」；就绪后 `auto` 自动优先本机。
5. 本地验证可绕过 npm 安装：`MAZI_VOICE_SHERPA_NODE_PATH=/path/to/sherpa-onnx-node`（指向已解压包目录）。

> 解压依赖系统 `tar` 的 bz2 支持（macOS/Linux/Windows 10+ 自带 bsdtar）；Windows 未实测。

### 17.6 与 DeepSeek Harness 语音方案对比

- **DSH 方案**：`SenseVoiceSmall ONNX + Silero VAD`，**完整录音后一次性转写**（`OfflineRecognizer`），不做流式 partial；UI 用 MediaRecorder 录制，Host 子进程按 VAD 分段离线解码。
- **本实现**：流式 zipformer（`OnlineRecognizer`），partial 实时写入输入框。
- **本次故障归因**：代码优先选用了 int8 encoder/joiner，导致长音频截断；改用 fp32 后同一 30.5s 音频经 `SherpaHost` 输出完整 127 字。结论是**权重选择/代码问题，不是模型能力问题**。

## 18. 最终落地：DSH 同款整段离线转写（2026-11-08）

> 本节为当前实现，优先级高于 §17 的流式演进记录。

### 18.1 方案

- **模型**：SenseVoiceSmall int8（`model.int8.onnx`，239MB）+ `tokens.txt` + Silero VAD（1.8MB）
- **方式**：前端用 AudioWorklet 录完整段 PCM16（16kHz mono），用户点停止后一次性 `POST /api/voice/asr/transcribe`；后端 child process 用 Silero VAD 分段，再逐段 `OfflineRecognizer` 解码，返回整段文字
- **不做流式 partial**；录音期间不写输入框，停止后一次性写入，再手动发送
- **模型来源**：优先只读复用本机 DSH 缓存 `~/.dsh/speech-to-text/sensevoice/models/`（零下载）；没有缓存时才按固定 URL/size/sha256 下载到 `$MAZI_HOME/voice/models/sensevoice-small-int8/`
- **自动安装**：API 启动时后台 `ensureInstalled()`，`capabilities.install` 返回 running/done/error；`MAZI_VOICE_AUTO_INSTALL=0` 可关闭

### 18.2 API

```http
GET  /api/voice/capabilities
POST /api/voice/asr/transcribe
     { "audioBase64": "<PCM16LE base64>", "sampleRate": 16000, "language": "zh-CN" }
  -> { "text": "...", "durationMs": 30000, "inferenceMs": 950 }
```

- body limit 20MB（5 分钟音频约 9.6MB PCM / 12.8MB base64）
- 仅 loopback + Origin 同源；不保存音频、不记录转写文本
- 无 session / token / 并发 busy 语义；整段请求一次完成

### 18.3 UI 行为

1. 点击发送按钮左侧麦克风开始录音；
2. 再次点击停止，按钮进入“正在转写录音…”；
3. 转写结果直接 append 到输入框原有草稿后；
4. 用户检查/编辑后手动点发送；不会自动发送；
5. 空/过短/静音结果丢弃并提示“没听清，请重试”；
6. 打字、切换会话、关闭页面会取消录音/转写，保留输入框当前内容；
7. 最长录音 5 分钟，到时自动停止并转写。

### 18.4 实测

| 项目 | 结果 |
| --- | --- |
| 30.5s 中文 TTS 音频 | SenseVoice 完整输出 137 字，含标点；推理约 0.95s |
| 9.9s 中英混合 TTS 音频 | 输出中英混合文字（受 TTS 英文发音影响，部分英文词不准，但不再是全大写） |
| DSH 缓存复用 | `installed=true`，`install={status:'done'}`，API 转写 200 |
| 测试 | SenseVoice store 13 / host 11 / API 4 全过；旧流式测试仍保留 |

### 18.5 与旧流式方案的关键差异

- 精度：SenseVoiceSmall 对中英混说、标点/ITN、英文大小写明显优于小 zipformer；
- 延迟：录音中无文字，停止后需约 0.3s–1s 推理（30s 音频实测 <1s）；
- 复杂度：无 partial revision / 无逐 chunk 编解码；一次请求完成；
- 模型：从 52MB/437MB 换成 239MB int8；有 DSH 缓存可零下载。

- 英文大小写/专名仍受模型与发音影响，后续可加自定义词表/热词；
- 云端 Provider 未接入（DSH 也仅默认本机）。
