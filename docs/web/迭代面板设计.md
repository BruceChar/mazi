# 迭代面板设计（Iterations：思维链 → 分析报告 → 系统迭代记录）

> **版本**：v1
> **定位**：右侧边栏「Iterations」页。把「冻结思维链（TOC）→ 独立 Agent 分析报告 → 反馈 →
> **系统迭代记录**」串成一条可追溯的自我迭代闭环，并提供**系统版本 / 构建信息**。
> **变更**：v1 重做 UI（master-detail + 报告 Markdown 渲染 + 状态/搜索过滤）；
> 新增 `iteration_records` 记录闭环（提案 → 进行中 → 已应用 / 已回滚 / 已驳回）；
> 新增 `GET /api/system/info` 版本与构建信息；报告由 `<pre>` 直出改为 Markdown 渲染。

---

## 1. 目标

- **方便查看每条思维链**：TOC 列表可按状态 / 关键字筛选，详情完整展示冻结的 thinking 链原文。
- **分析报告可读**：报告以 Markdown 渲染（标题 / 列表 / 代码块 / 表格），支持复制、失败原因展示。
- **让系统自迭代更新可追溯**：任意一条分析报告可「采纳为迭代项」，形成
  `提案 → 进行中 → 已应用 / 已回滚 / 已驳回` 的状态闭环，并钉住**基线版本**与**应用版本**。
- **关于系统版本**：展示版本标识（`git describe`）、提交号/提交说明/提交时间、分支、
  工作区是否 dirty、Node 与平台。
- 窄栏与最大化两种宽度都可用：窄栏单列下钻（列表 → 详情，带返回），最大化 ≥1180px 双栏。

### 1.1 非目标

- **不自动改代码**：面板不派发写代码的 Agent 任务；「标记已应用」由人来点（人在环）。
- 不做跨仓库/多项目的迭代管理；不做分析质量的自动评分；不做团队协作与权限。
- 不改动 TOC 冻结与分析的既有口径（`toc_records` / `toc_analyses` / `toc_feedback` 语义不变）。

## 2. 数据契约（packages/libs/src/iteration.ts）

### 2.1 既有（不变）

`TocRecordView`（冻结思维链）1 ── N `TocAnalysisView`（分析报告）1 ── N `TocFeedbackView`（反馈）；
聚合视图 `TocIterationView`。

### 2.2 新增：系统版本

```ts
/** 迭代记录钉住的系统版本快照（轻量、随记录落库）。 */
export interface SystemVersionRef {
    /** `git describe --tags --always`；无 git 时回落 package.json version */
    version: string;
    /** 提交短号；无 git 时为 '' */
    commit: string;
    branch: string;
    /** 读取时工作区是否有未提交改动 */
    dirty: boolean;
}

/** GET /api/system/info：面板「系统」页展示的完整版本与构建信息。 */
export interface SystemVersionView extends SystemVersionRef {
    /** HEAD 提交说明 */
    commitSubject: string;
    /** HEAD 提交时间（ISO；无 git 时 ''） */
    commitDate: string;
    /** 根 package.json 的 version */
    packageVersion: string;
    /** process.version */
    node: string;
    /** `${process.platform} ${process.arch}` */
    platform: string;
    /** 读取时刻（epoch ms） */
    readAt: number;
}
```

### 2.3 新增：系统迭代记录

```ts
export type IterationStatus = 'proposed' | 'in_progress' | 'applied' | 'reverted' | 'rejected';

/** 一条系统迭代记录（分析报告 → 系统改动）的完整视图。 */
export interface IterationRecordView {
    iterationId: string;
    /** 来源分析（可空 = 手工新建） */
    analyzeId?: string;
    /** 来源 TOC（便于从记录回到思维链） */
    tocId?: string;
    /** 一句话标题 */
    title: string;
    /** 迭代意图 / 采纳的改进点 */
    intent: string;
    status: IterationStatus;
    /** 创建时的系统版本快照 */
    base: SystemVersionRef;
    /** 标记「已应用」时的系统版本快照 */
    applied?: SystemVersionRef;
    /** 复盘备注（改了什么 / 为什么回滚） */
    notes: string;
    createdAt: number;
    updatedAt: number;
}
```

**状态机**（唯一合法迁移；其余拒绝）：

| 当前 | 动作 | 目标 |
| --- | --- | --- |
| proposed | 开始迭代 | in_progress |
| proposed | 驳回 | rejected |
| in_progress | 标记已应用 | applied |
| in_progress | 驳回 | rejected |
| applied | 回滚 | reverted |
| reverted | 重新开始 | in_progress |
| rejected | 重新提案 | proposed |

- `applied` 迁移时服务端**注入当前系统版本快照**（`applied` 字段），形成 base → applied 的版本差。
- 记录不可删除（审计留痕）；状态与备注可改。

## 3. REST（apps/api）

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/api/system/info` | — | `SystemVersionView` |
| GET | `/api/iterations` | — | `{ iterations: TocIterationView[] }`（既有） |
| POST | `/api/iterations/analyses` | 既有 | 既有 |
| POST | `/api/iterations/:analyzeId/feedback` | 既有 | 既有 |
| GET | `/api/iterations/records` | — | `{ records: IterationRecordView[] }`（倒序） |
| POST | `/api/iterations/records` | `{ title, intent?, analyzeId?, tocId? }` | `{ record }`（服务端注入 `base`） |
| PATCH | `/api/iterations/records/:iterationId` | `{ status?, title?, intent?, notes? }` | `{ record }` |

校验：`title` 必填（≤200 字）；非法状态迁移 → 400；`iterationId` 不存在 → 404。

## 4. 存储（packages/runtime）

- 新增表 `iteration_records`（同 `toc_*` 模式：`node:sqlite` + JSON 列）：
  `iteration_id TEXT PRIMARY KEY, analyze_id TEXT, status TEXT, json TEXT NOT NULL`；
  索引 `idx_iteration_records_analyze(analyze_id)`、`idx_iteration_records_status(status)`。
- 新增 `IterationStore`（`MemoryIterationStore` / `SqliteIterationStore`）与
  `IterationTracker`（create / update / list + 状态机校验）。版本快照由 **API 层**注入，
  runtime 不读 git（保持运行时与 VCS 解耦）。
- 版本读取在 API 层：`readSystemVersion()` 用 `git -C <repoRoot>` 读
  `describe/branch/status/commit/subject/date`，任何一步失败都降级为 package.json version
  且字段留空，**不抛错**。

## 5. 面板结构（右侧边栏 Iterations）

    ┌─ Iterations ───────────────────────────────┐
    │ [思维链] [迭代记录] [系统]       ⟳ 刷新      │  分段 + 工具
    ├────────────────────────────────────────────┤
    │ 思维链页                                    │
    │ ┌────────────────────┬───────────────────┐ │
    │ │ 搜索… [全部|成功|失败]│ TOC a7f3 · model  │ │  左：TOC 列表
    │ │ ▸ a7f3 帮我审计…    │ [Copy][再分析][▾] │ │  右：详情
    │ │   3 次分析 · 已采纳  │ ── 思维链原文 ──   │ │
    │ │ ▸ b21c …           │ ── 分析报告（MD）──│ │
    │ │                    │   状态 · 「采纳为迭代项」│
    │ └────────────────────┴───────────────────┘ │
    ├────────────────────────────────────────────┤
    │ 迭代记录页：[全部|提案|进行中|已应用|已回滚|已驳回] │
    │  ▸ 收敛 TOC 提示词   提案  v0.0.0→—  ← 来源报告 │
    │  ▸ 上下文裁剪       已应用 abc1234→def5678     │
    ├────────────────────────────────────────────┤
    │ 系统页：版本/提交/分支/dirty/提交时间/Node/平台  │
    └────────────────────────────────────────────┘

### 5.1 思维链页（master-detail）

- **列表行**：`TOC <短id>` + 输入摘要（`userInput` 首行，截断）；右侧为模型、创建时间、
  分析次数与最新状态徽标；「已采纳」标记（其下有分析被采纳为迭代记录时）。
- **过滤**：关键字匹配 `userInput` / 思维链原文 / taskId / 短 id；状态 = 全部 / 成功 / 失败 / 未分析。
- **窄栏**：列表 → 点击进入详情，详情顶部有「← 返回」；**最大化 ≥1180px**：左列表 / 右详情双栏。
- **详情**：
  - 头部：TOC 短 id、模型、创建时间；动作：Copy（复制思维链）/ Analyze again（再分析）/
    展开原文。
  - **思维链原文**：默认折叠为定高滚动区，可展开全文（等宽、保留换行）。
  - **分析报告**：每次分析一张报告卡（倒序）——状态徽标、模型、耗时、时间、
    「采纳为迭代项」（已被采纳的显示「已采纳」且不可重复采纳）；
    请求诉求；**Markdown 渲染的报告正文** + 「复制报告」；失败显示错误原因；
    反馈列表 + 输入框（Enter 提交）。
- 空态：说明入口（在 Trace 面板选中 Task → ⋯ → Analyze）。

### 5.2 迭代记录页

- 状态过滤 chips + 计数；记录按 `updatedAt` 倒序。
- 每行：标题、状态徽标、`base.version → applied.version`（未应用显示 `—`）、
  更新时间、来源（可点击跳回思维链页并选中该分析报告）。
- 展开行内详情：意图、备注编辑与保存、**状态机允许的动作按钮**。

### 5.3 系统页

- 版本卡片：`version`（git describe）、提交短号 + 提交说明、分支、dirty 徽标、
  提交时间、`packageVersion`、Node、平台、读取时间；刷新按钮。
- 无 git 时降级显示 package version，并标注「未检测到 git」。

---

## 6. 计算规则

- **TOC 状态**：取该 TOC 下最新一次分析的 `status`；无分析 = `none`。
- **耗时**：`endedAt - createdAt`（缺失时显示 `—`）。
- **已采纳**：存在 `record.analyzeId` 属于该 TOC 的分析集合 → 该分析「已采纳」。
- **版本展示**：`commit`（短号）+ `branch`；`dirty` 显示 `*`。全是空 → 显示 packageVersion。
- **时间显示**：不超过一天 → `HH:MM:SS.mmm`；超过 → `YYYY-MM-DD HH:MM:SS.mmm`（与 Trace 面板一致）。

---

## 7. 异常与降级

| 场景 | 表现 |
| --- | --- |
| 无 TOC | 空态 + 入口说明 |
| 无分析记录 | 空态「还没有迭代记录」 |
| 分析失败 | 报告卡显示 `failed` 与错误原因，仍可反馈/采纳 |
| 无 git | 系统页显示 packageVersion，标注未检测到 git |
| 状态迁移非法 | 400，前端刷新该记录并提示 |
| 加载中 | 骨架/`Loading…`，不闪空态 |
