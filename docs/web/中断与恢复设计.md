# 任务中断与恢复设计（Step 级可中断恢复）

> 版本：v0.1
> 范围：packages/runtime（执行面）、apps/api（控制面）、apps/webui（交互面）。
> 前置：docs/Agent Harness Framework.md（可中断、可恢复、可审计）、docs/web/会话与Session结构定义.md、docs/core/AHF_CORE_GTS.md（Goal/Task/Step 状态机）。

---

## 1. 目标与边界

### 1.1 目标

1. **可中断**：任务执行过程中，用户可随时点击「停止」，运行在**最近一个完整 Step 边界**协作式停止，已落库的 Goal/Task/Step 事实全部保留。
2. **可恢复**：停止后的 Task 处于可恢复状态；用户点击「继续」后，从已落库的 Step 重放上下文并继续后续轮次，**不重复执行已成功的工具调用**。
3. **交互**：执行中 composer 的「发送」按钮变为「停止」按钮；存在可恢复运行且空闲时，出现「继续」入口。

### 1.2 非目标（本期不做）

- 不中断正在执行的工具进程（工具与审批是有副作用的外部动作，中途强杀会留下不确定状态）；停止生效于下一个 Step 边界。
- 不做进程崩溃后的自动恢复（checkpoint 由 runtime 协作式写入；崩溃恢复属 OBS 事件回放范围）。
- 不新增独立队列/异步任务调度；执行仍在 HTTP 生命周期内 await（维持 D-HTTP-3）。

## 2. 术语与状态模型

沿用 @mazi/core GTS 状态机。本特性只新增语义，不新增状态枚举：

| 角色 | 状态 | 含义 |
| --- | --- | --- |
| Task | `active` | 执行中（首次执行与恢复执行期间） |
| Task | `aborted` | 协作式停止点：可被 resume 复用并继续 |
| Task | `succeeded` / `failed` / `blocked` | 终态，不可恢复 |
| Goal | `aborted` | 其 Task 在未终结时被停止（可恢复） |
| Goal | `active` | 尚未执行 |
| Goal | `succeeded` / `failed` | 终态 |

**Checkpoint 定义**：一个完整轮次 = 一个 deliberation Step + 该轮全部 invocation Step。停止只发生在轮次之间，因此已落库 Step 永远是完整轮次，恢复重放不产生悬挂的 tool result。

## 3. 中断（stop）语义

### 3.1 信号传播

```
POST /api/sessions/:id/stop
  -> HarnessRuntime.stopGoalTree(rootGoalId)     // AbortController.abort()
  -> runGoalTree(signal)
  -> executeTask(signal)
  -> requestRound(ctx.signal)
  -> RoundRunner.requestRound -> LLMRequest.signal
  -> RoundExecutor（caller-cancel -> ProviderError('aborted')，不重试、不降健康）
```

- 每个轮次开始前检查 `signal.aborted`；已触发则直接返回 `aborted` 结果。
- 模型调用进行中被中断：provider 层报 `aborted`，**该轮不落任何 Step**（deliberation 仅在轮次成功返回后落库），checkpoint 保持在上一个完整轮次。
- 工具执行进行中收到中断：当前轮次正常跑完（不把 signal 注入工具面），下一轮开始前检测并停止。

### 3.2 落库行为

- Task：`status='aborted'`，记录 `endedAt`；已完成的 Step 原样保留。
- Goal：`status='aborted'`。
- 事件：发 `run.aborted`（runtime 层事件），**不发** `goal.ended`（运行未终结）。
- TaskOutcome：`{ ok:false, reason:'aborted' }`，HTTP 响应与 `/run` 同形。

## 4. 恢复（resume）语义

### 4.1 复用 Task

`POST /api/sessions/:id/resume` -> `HarnessRuntime.resumeGoalTree(rootGoalId)`：

1. `listGoalsByRoot(rootGoalId)`，取 `status in {active, aborted}` 的 Goal（`active` 兼容首次执行路径）。
2. 对每个 Goal：`store.listTasks(goalId)`，若存在最近一个 `status in {aborted, active}` 的 Task 则复用（保持同一 taskId/step 历史）；否则新建。
3. 发 `run.resumed` 事件。

### 4.2 上下文重放

`executeTask` 接收 `resumeSteps: Step[]`（该 Task 已落库 Step，按 startedAt 升序）：

- deliberation -> `context.appendAssistant({ text: answer, toolCalls })`；
- 紧随其后的 invocation -> 合并为一条 `context.appendToolResults([...])`（callId 配对）；
- 成功 invocation 回填 `executedCalls` 去重表（tool+args 指纹 -> 结果），恢复后不重复执行；
- 缺失的 callId（异常场景）补一条 `[error] 中断前未执行`，保证 assistant toolCalls 与 tool results 一一对应；
- 轮次计数从已重放轮次数继续，`maxSteps` 仍为 Task 全程上限；死循环护栏 `prevCallKey` 取最后一个重放轮次。

### 4.3 恢复执行

重放完成后回到正常 `executeTask` 主循环：下一轮继续向模型请求、执行新工具、收尾，直到终态。恢复不修改历史 Step，只追加新 Step。

## 5. 事件契约

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `run.aborted` | `{ rootGoalId, reason:'user-stop' }` | 停止生效（checkpoint 已落库） |
| `run.resumed` | `{ rootGoalId }` | 恢复开始 |

两者加入 `RUNTIME_EVENT_TYPES`；WebUI SSE 订阅 `run.aborted` 以刷新快照。

---

## 6. API 契约

| 端点 | 方法 | 请求 | 响应 | 异常 |
| --- | --- | --- | --- | --- |
| `/api/sessions/:id/stop` | POST | `{}` | `{ sessionId, state:'stopping' }` | 运行中才有实际停止；空闲返回 `state:'idle'`（幂等，200） |
| `/api/sessions/:id/resume` | POST | `{ goal?: { modelId?, reasoningLevel? } }` | 同 `/run`（`rootGoalId/tasks/ok`） | 无未终结 Task 时按首次执行语义规划并执行（等价 `/run`） |

- `stop` 不进串行锁（`runExclusive`）；`resume` 与 `run` 共用串行锁。
- `stop` 与 `run` 可能并发：stop 在目标 runtime 实例上 abort，run 随后以 `aborted` 结果返回。

## 7. 前端交互

| 状态 | 主按钮 | 附加入口 |
| --- | --- | --- |
| busy（当前 run 执行中） | **停止**（红色圆角方块，title「停止」） | — |
| 空闲且当前 run 可恢复 | **发送** | **继续**（play 图标 + 「继续」，调用 resume） |
| 其余 | **发送** | — |

- 「可恢复」判定：当前 run 的快照中最新 Task `status==='aborted'`，或本次 HTTP 结果 `reason==='aborted'`。
- 决策为纯函数 `composerPrimaryAction({ busy, resumable })`，便于单测（apps/webui/test/run-control.test.ts）。

## 8. 验收标准

| # | 验收项 | 标准 |
| --- | --- | --- |
| IR-1 | 停止落库 | 中断后 Task `aborted`、Goal `aborted`，已完成 Step 数量不变，发 `run.aborted` |
| IR-2 | 模型中途中断 | 被中断轮次不落 Step，checkpoint = 上一完整轮次 |
| IR-3 | 恢复重放 | resume 后新 Step 追加在历史之后，不重复成功工具调用 |
| IR-4 | 恢复续跑 | aborted 后 resume 能继续到 `succeeded`，finalMessage 正确 |
| IR-5 | API 幂等 | 空闲 stop 返回 `idle` 不抛错；无 aborted Task 的 resume 不破坏数据 |
| IR-6 | UI | busy 时主按钮为「停止」并触发 stop；aborted 后出现「继续」并触发 resume |
| IR-7 | 回归 | 既有 Goal 执行/流式测试全绿，`pnpm build` 通过 |
