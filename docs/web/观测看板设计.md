# 观测看板设计（右侧边栏审计面板）

> **版本**：v1
> **定位**：WebUI 右侧边栏的「审计」页。点击主对话区的 Task / Step 时，面板展示该执行单元的 token、成本、
> context 装填与逐步骤 context diff，落实 docs/webui.md §1.1「透明即信任 / 实时可观测」。
> **依赖契约**：packages/libs StepUsage（本文件第 2 节定义其扩展面）。

---

## 1. 目标与范围

### 1.1 目标

- 在主对话区点击任意 Step 或 Task，右侧边栏自动切到「审计」页并展示其可观测事实。
- 展示四类事实：Token 用量（Vendor 层 + Runtime 层）、成本、Context 装填、逐步骤 Context Diff。
- Runtime 层的五段 token（system prompt / history / tool schema / user input / observation）以占比呈现，
  回答「prompt、context、userinput、tool 各占多少」。
- 数据实时：执行中点击正在运行的 Step，面板随 SSE 增量刷新。

### 1.2 非目标

- 不做跨会话/跨 run 的历史趋势图（属后续「账本」）。
- 不做成本对账、配额、定价管理。
- 不新增独立 API 端点：数据复用 GET /api/sessions/:id/timeline 快照与 SSE step 事件的 usage 载荷。

## 2. 数据契约（packages/libs StepUsage）

Step.usage（core 的完整 Usage）经 goal-snapshot 投影为线协议 StepUsage。为支撑看板，投影保留以下字段
（缺省字段不出现，前端按可选处理）：

    interface StepUsage {
      vendor?: {
        inputTokens: number;
        outputTokens: number;
        cacheCreationInputTokens?: number;
        cacheReadInputTokens?: number;
        reasoningOutputTokens?: number;
        reportedByVendor?: boolean;
      };
      runtime?: {
        totalContextTokens: number;
        systemPromptTokens: number;
        historyTokens: number;
        toolSchemaTokens: number;
        newInputTokens: number;
        observationTokens: number;
        retrievedTokens?: number;
        exampleTokens?: number;
        systemPromptRatio?: number;          // systemPromptTokens / totalContextTokens
        contextWindowUtilization?: number;   // 0-1，相对 contextWindow
        contextDeltaFromPrev?: number;       // 相对上一步；< 0 表示压缩；每轮首次为 0
        strategyApplied?: string[];
        budgetPressureAction?: string;
        estimationDriftTokens?: number;      // |runtime total - vendor.inputTokens|
      };
      cost?: {
        inputCostUsd: number;
        outputCostUsd: number;
        cacheWriteCostUsd: number;
        cacheReadCostUsd: number;
        reasoningCostUsd: number;
        totalCostUsd: number;
        priceTierApplied?: string;
        pricingVersion?: string;
        currency?: 'USD';
      };
      timing?: { ttftMs: number; totalMs: number; tokensPerSecond: number };
    }

**来源**：runtime 的 measureContext 产 runtime 段；provider 层 computeCostBreakdown 产 cost；
RoundExecutor 的 ttft/total 产 timing；三者随 vendor usage 一起挂到本轮第一个 Step。

## 3. 选择交互

| 动作 | 结果 |
| --- | --- |
| 点击对话流中的 Step 行 | 选中该 Step；右侧面板打开并切到「审计」页 |
| 点击对话流中的 Task 头 | 选中该 Task（聚合其全部 Step）；面板打开并切到「审计」页 |
| 切换 run / 会话 | 清空选中，面板回到「未选择」态 |
| 面板标题 | 显示当前目标：Step S#n · kind，或 Task T#n · title，或 Run 汇总 |

选中态在对话流中以高亮行体现；点击空白或再次点击已选目标不改变目标（幂等）。

## 4. 面板结构

    ┌─ 审计 ─────────────────────────────┐
    │ Step S#2 · tool_call               │
    │ goal_output · 0.4s · ok            │
    ├────────────────────────────────────┤
    │ Token 用量                          │
    │  Vendor   in 120 · out 45          │
    │           cache read 2,100 (86%)   │
    │  Context  2,530 tok                │
    ├────────────────────────────────────┤
    │ Context 装填  ▓▓▓▓▓▓▓░░ 78%        │
    │  █ system prompt   890  23.5%      │
    │  █ history       1,240  32.8%      │
    │  █ tool schema     120   3.2%      │
    │  █ user input       80   2.1%      │
    │  █ observation     200   5.3%      │
    ├────────────────────────────────────┤
    │ Context Diff  +120 (2,410 → 2,530) │
    │  策略: sliding-window               │
    ├────────────────────────────────────┤
    │ Cost  $0.0012 · tier off-peak      │
    │   in $0.0003 · out $0.0005         │
    │   cache $0.0004 · reasoning $0     │
    ├────────────────────────────────────┤
    │ Timing  TTFT 180ms · 420ms · 28/s  │
    ├────────────────────────────────────┤
    │ 步骤明细 (Task/Run 级)              │
    │  S#1  thinking    2,410  +0        │
    │  S#2  tool_call   2,530  +120      │
    └────────────────────────────────────┘

### 4.1 Token 用量

- Vendor 层：input / output，cache read（附占 input 的命中率），cache write，reasoning。
- Runtime 层：totalContextTokens；estimationDrift 存在时以警示色展示漂移。

### 4.2 Context 装填（占比）

- 顶部为 contextWindowUtilization 进度条（无该字段时退化为不显示窗占比，仅显示绝对量）。
- 五段堆叠条 + 图例：system prompt（prompt）、history（context）、new input（userinput）、
  tool schema（tool 定义）、observation（tool 结果）。每段显示 token 数与占总 context 的百分比。
- 占比口径：segmentTokens / totalContextTokens；totalContextTokens = 0 时全部按 0。

### 4.3 Context Diff

- Step 级：读取 runtime.contextDeltaFromPrev；> 0 绿色、< 0 橙色（压缩）、= 0 中性。
  另展示 上一轮 = totalContextTokens − delta 便于对照。
- Task / Run 级：以步骤明细表逐行列出每个 Step 的 context 总量与 delta，落实「每个步骤 context diff」。

### 4.4 Cost 与 Timing

- Cost：总额 + 五成分拆分；priceTierApplied 作为档位标签；无 cost 时显示「未计价」。
- Timing：TTFT、总耗时、tok/s。

## 5. 计算规则

- **聚合**：Task/Run 的 token/cost 为各 Step 之和；timing.totalMs 求和，TTFT 取平均，tok/s 用
  ΣoutputTokens / Σ(totalMs − ttftMs) × 1000（无有效推理窗口时为 0）。
- **占比**：见 4.2；分段顺序固定为 system → history → tool → user → observation（视觉稳定）。
- **格式化**：token 用 K/M（如 2.3K、1.2M）；成本 6 位小数；百分比 1 位小数。
- **多 usage 归属**：Usage 挂在每轮第一个 Step；同轮后续 Step 无 usage 属预期，聚合时按 0 计。

---

## 6. 异常与降级

| 场景 | 表现 |
| --- | --- |
| 目标无 usage | 各区块显示「暂无用量数据」，不隐藏区块标题 |
| 选中的 Step 不在快照中（如已被清理） | 显示「目标已失效，请重新选择」 |
| 仅有 vendor、无 runtime | Context 区块显示「Runtime 未采集」 |
| 仅有 runtime、无 vendor | Vendor 区块显示「厂商未上报」 |
| 执行中的 live step 无 usage | 显示「执行中，用量待本轮结束」并随 step.ended 刷新 |
| contextWindow 未配置 | 装填进度条隐藏，仍显示各段绝对量 |
