# WebUI 流式响应设计（Streaming Response Design）

> 版本：v1.0
> 依据：docs/webui.md §3.4/§5.1（执行中实时追加 Step、验收 §8-2）、docs/web/后端与存储设计.md §6（SSE 实时事件通道）、docs/core/AHF_CORE_PROVIDER.md §7（askStream 流式事件契约）、docs/AHF_RUNTIME_PROVIDER.md §3（流式聚合）。
> 范围：把模型生成过程（token/推理增量）与步骤落库事件从 provider 层一路实时推送到 WebUI 并渐进渲染。

---

## 1. 背景与目标

当前链路的事实：

- provider 层已实现 `askStream`（`LLMProvider.askStream` 产出 `StreamCompletionEvent`），`aggregateStream` 在 **整轮结束后** 才把内容聚合成 `LLMResponse`。
- runtime 在每个 Step 落库后发 `step.ended`（`emitStep`），事件总线 + `GET /api/events/:id?follow=1`（SSE）已能把任意 `HarnessEvent` 实时转发到浏览器。
- WebUI 右侧「日志」看板已消费 `step.ended`；但主对话区的执行流（`ExecStream`）只在 `session.ended`（或阻塞式 `POST /api/sessions/:id/run` 返回）后整体刷新，模型输出**一次性出现**。
- `llm.stream_event` 事件类型已在 @mazi/core 契约中声明，但没有任何生产代码发出它。

目标（本设计交付）：

1. **token 级流式**：模型文本/推理增量在生成过程中实时到达浏览器并逐字渲染。
2. **步骤级流式**：`step.ended` 到达即刷新主对话执行流，而不是等整轮结束。
3. 保持既有契约不破坏：聚合结果、Step 持久化、事件回放、SSE 线上格式全部不变。

非目标：工具参数流式渲染、多进程/横向扩展的事件总线、WebSocket 替换 SSE。

## 2. 事件契约：`llm.stream_event`

`llm.stream_event` 属 **Task 级** 事件（见 packages/runtime/src/observability/event-bus.ts TASK_SCOPED），必须携带 `taskId`。

```ts
// HarnessEvent
{
  type: 'llm.stream_event',
  rootGoalId: string,        // 必填
  goalId: string,            // 本轮所属 work goal
  taskId: string,            // 必填（Task 级）
  attributes: {
    'gen_ai.provider.name'?: string,   // 命中并正在流式的 provider
    'gen_ai.request.model'?: string,   // 命中并正在流式的 model
  },
  payload: {
    streamId: string,        // 每次 requestRound 生成一次（ULID），同轮多 attempt 相同
    attempt: number,         // 1-based 网络尝试序号；重试/换家递增
    event: StreamCompletionEvent,  // provider 原始流式事件（start/text_delta/reasoning_delta/tool_call_*/usage/finish）
  },
  eventId: string,
  timestamp: number,
}
```

约束：

- 同一 `streamId` 内，`attempt` 单调不减；UI 见到更大的 `attempt` 必须丢弃该 `streamId` 的旧增量。
- 事件按 provider 到达顺序转发，聚合语义（AHF_RUNTIME_PROVIDER §3）不因转发而改变。
- 无 `taskId` 的执行路径（例如直接调用 `RoundExecutor`）**不** 发事件；`llm.stream_event` 只由 `HarnessRuntime.requestRound` 在具备 goalId/taskId 时发出。
- 落盘：与其它事件一致，经 `DefaultEventBus` 追加到 `<rootGoalId>.jsonl`。
- 回放：`replay` / `?follow=1` 的线上格式不变（`event: <type>\ndata: <json>\n\n`）；但 `llm.stream_event` 属传输态 Delta（AHF_CORE_PROVIDER §6），**不参与回放**（REST 与 SSE history 均过滤），正规内容以 `step.ended` 为准，避免订阅已完成 run 时历史增量被误当成 live。

## 3. 数据流

```
provider.askStream()                       // packages/provider（pi-ai deepseek …）
  │  AsyncIterable<StreamCompletionEvent>
  ▼
aggregateStream(stream, timers, onEvent)   // packages/runtime/provider/aggregate.ts
  │  onEvent(event) —— 纯观测钩子，逐事件同步回调
  ▼
RoundExecutor.execute(req, candidates, listener)  // orchestrator.ts
  │  listener({ providerId, modelId, attempt, event })
  ▼
HarnessRuntime.requestRound(rootGoalId, ctx)      // runtime.ts
  │  bus.emit(newHarnessEvent({ type:'llm.stream_event', goalId, taskId, payload }))
  ▼
DefaultEventBus → SSE follow（apps/api/src/events）
  ▼
WebUI store：applyStreamEvent() → liveStreams[streamId]
  ▼
ExecStream / ChatMain：渐进渲染 markdown 文本
```

同时：Step 落库后 `emitStep` 仍发 `step.ended`；WebUI 收到 `step.ended` 时

1. 清掉对应 `taskId` 的活动流式缓冲（该轮已结束，正式 Step 即将由时间线渲染）；
2. 触发去抖的 `GET /api/sessions/:id/timeline` 刷新，主对话执行流实时更新。

> **Step 生命周期可观测性（关键约束）**：`goalSnapshot`（`/api/sessions/:id/timeline`）按
> `GoalStore.listTasks()` 组装 Task → Step。因此 **Task 必须在执行前以 `status='running'` 落库**
> （`executeTask` 开头写入）；否则 run 进行中的快照里没有 Task，其下已落库的 Step 也会被整体隐藏，
> WebUI 只能等任务结束才看到内容（表现为“只显示执行中…”）。回归测试：
> `packages/runtime/test/goal-executor.test.ts`（running Task 先落库）、
> `packages/runtime/test/streaming.test.ts`（工具执行期间 `goalSnapshot` 已含 `thinking:ok` / `tool_call:running`）。

## 5. WebUI 状态与渲染

`liveStreams`：`Record<streamId, LiveStream>`，`LiveStream`：

```ts
interface LiveStream {
  streamId: string;
  taskId: string;
  attempt: number;
  reasoning: string;   // reasoning_delta 累积
  text: string;        // text_delta 累积
  startedAt: number;
  updatedAt: number;
}
```

规则：

- 收到 `llm.stream_event`：解析 `payload.{streamId,attempt,event}`；`attempt` 变化则重置该 stream 的 `reasoning/text`；`text_delta`/`reasoning_delta` 追加。
- 收到 `step.ended`：按 `payload.taskId` 清除该任务的 liveStreams；去抖 250ms 刷新时间线。
- 收到 `session.ended`/`goal.ended`：清空全部 liveStreams；刷新时间线。
- 打开/切换 run（`watchEvents`）或停止订阅（`stopEvents`）：清空 liveStreams。
- 主对话区只渲染 **当前 run 且 busy** 的活动流（取 `updatedAt` 最大者）；推理文本用灰色小字，正文用 markdown 渲染并附光标「▍」。

### 5.1 步骤级增量渲染（liveSteps，防抖动）

执行中若每次都按 timeline 快照整体替换 goal→task→step 树，会因内容伸缩而明显抖动。主对话在
`busy` 期间改为渲染 **append-only 的 step 列表**：

- `liveSteps[rootGoalId]`：由 `step.started` / `step.ended` 归约出的有序步骤行
  （`stepId / kind / toolName / title / status / startedAt / endedAt`）。
- `step.started`：追加一行；同时把上一条仍为 `running` 的 step 置为 `ok`（「下一个 step 开始 → 上一个结束」）。
- `step.ended`：按 `stepId` **就地更新**该行（工具调用 `running → ok/error`），不追加重复行。
- 行 `key = stepId`，只追加/就地更新，DOM 稳定；`status === 'running'` 的行显示转圈 spinner。
- 执行中渲染 `liveSteps`；执行结束后切换为 timeline 快照树（含最终回答与统计）。

| # | 验收项 | 标准 |
| --- | --- | --- |
| S1 | token 实时 | 模型文本增量到达 WebUI 的额外延迟 < 1s（SSE 直推，无轮询） |
