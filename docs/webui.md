# AI Agent Harness WebUI 设计文档

> **版本**：v1.0
> **定位**：面向复杂真实任务的 AI Agent 执行框架的可视化界面，供操作者、开发者与审计人员使用。
> **风格基准**：DeepSeek Harness WebUI（左侧会话导航 + 中央对话流 + 底部实时指标 + 右侧/内嵌审计面板）

---

## 1. 设计原则

### 1.1 核心原则

| 原则                 | 说明                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **透明即信任** | 每一步的"判断"由模型做出，每一步的"事实"由 harness 记录。UI 必须让三方记录（TurnContract 声明、Capacity 授权、Step trace 实际）可对照、可 diff。 |
| **层级可视化** | Session-Turn-Step 三层结构必须在界面中有明确的空间映射，任何 UI 元素可定位到"哪次输入、哪个子任务、哪个最小动作"。                               |
| **实时可观测** | 成本、延迟、token 消耗、缓存命中率等数据必须实时呈现，而非仅在结束后展示。                                                                       |
| **契约前置**   | 路由决策、预算分配、权限校验的结果必须在执行前以可视化方式呈现，让用户"看到授权"。                                                               |
| **反馈闭环**   | 用户反馈（决策更改、授权操作、输出评价）的入口必须嵌入在对应事件的上下文附近，而非集中到会话末尾。                                               |

### 1.2 视觉风格

- **布局**：三栏自适应（左侧导航 260px + 中央主内容区 弹性 + 右侧审计面板 320px，可折叠）
- **色彩**：深色主题为主（#0d1117 背景，#1f2937 面板，#374151 边框），高对比度语义色（成功绿、警告琥珀、错误玫瑰、信息蓝）
- **字体**：JetBrains Mono（等宽，用于代码/JSON/日志）+ Inter（无衬线，用于正文）
- **密度**：信息密度高，支持折叠/展开；关键数据始终可见，详情按需展开

## 3. 核心页面设计

### 3.1 左侧边栏（Sidebar）

**功能**：会话导航、工作区管理、快速创建

#### 3.1.1 会话列表

```
┌─ Sidebar ─────────────────┐
│  🔍 搜索会话...            │
├───────────────────────────┤
│  📁 工作区: my-project     │
│  ▼                        │
│  ● 审计网站代码结构         │  ← 当前激活，带绿色指示点
│    2 turns · $0.04 · ⏱3m │
│  ○ 重构登录模块            │
│    5 turns · $0.12 · ⏱8m │
│  ○ 数据分析: Q3报表        │
│    1 turn  · $0.02 · ⏱1m │
├───────────────────────────┤
│  📁 工作区: another-repo   │
│  ▼                        │
│  ○ 修复 API 超时问题       │
│    3 turns · failed       │
├───────────────────────────┤
│  [+ 新建会话]              │
└───────────────────────────┘
```

**设计要点**：

- 每个会话卡片显示：**主题标题**（从 `UserInteractionRecord.rawInput` 提取或模型生成）、**Turn 数**、**累计成本**（`SessionAggregate.totalCostUsd`）、**耗时**、**状态图标**（running/success/failed/aborted）
- 支持按工作区分组折叠
- 右键菜单：重命名、归档、删除、复制 Session ID、在新标签页打开
- 顶部切换器：Workspaces / Recent Sessions / Pinned Sessions

#### 3.1.2 快捷操作区

- **新建会话**：弹出 GoalContract 快速配置对话框（选择策略、预算上限、权限级别）
- **插件入口**：插件市场、已安装插件列表
- **设置齿轮**：全局设置、个人资料

### 3.2 中央主内容区（Main Content Area）

采用 **Tab 切换** 或 **上下分栏** 模式，核心包含：

#### 3.2.1 对话流（Chat Flow）

**用户消息气泡**：

```
┌─────────────────────────────────────────┐
│  👤 用户                                │
│  请审计这个网站的代码结构，从安全、性能、 │
│  可维护性三个维度给出报告。               │
│                              00:54:12   │
└─────────────────────────────────────────┘
```

**助手消息气泡**（含多级嵌套）：

```
┌─────────────────────────────────────────┐
│  🤖 Assistant (deepseek-v4-pro)         │
│                                         │
│  [💭 Thinking · 2.3s · 1,240 tokens]   │
│  ▼ 展开思考过程...                      │
│  我将从三个维度审计代码结构。首先，我需要 │
│  读取项目根目录下的关键配置文件...        │
│                                         │
│  [🔧 Tool Call: fs.read · 0.4s]        │
│  📄 AGENTS.md                           │
│  ▼ 参数 │ 结果 │ 副作用                 │
│  参数: { path: "AGENTS.md" }            │
│  结果: (文件内容摘要...)                 │
│  副作用: read-only ✓                    │
│                                         │
│  [📊 Observation · 0.1s]               │
│  已读取 AGENTS.md，识别到项目规则...     │
│                                         │
│  基于以上分析，代码结构审计结果如下...    │
│                              00:54:35   │
└─────────────────────────────────────────┘
```

**设计要点**：

- **Thinking / Tool Call / Observation** 三种 Step 用不同图标和背景色区分
- Tool Call 卡片包含：**工具名**、**执行时间**、**参数折叠面板**、**结果折叠面板**、**副作用标签**（来自 `SideEffectSpec`）
- 可展开查看原始 `Step.payload` 和完整 `Usage` 数据
- 嵌套子代理：在助手气泡内显示子代理卡片，含独立进度条和跳转链接

#### 3.2.2 轨迹时间线（Trajectory Timeline）

独立 Tab 或底部面板，替代/增强原始事件流：

```
┌─ Trajectory Tab ──────────────────────────────────────────────┐
│  [全部] [Thinking] [Tool] [Observation] [Policy] [Provider]   │
├───────────────────────────────────────────────────────────────┤
│  Turn 1 · 计划分解                                            │
│  ├─ Step 1  thinking  · 1,240 tok · 2.3s · deepseek-v4-pro  │
│  ├─ Step 2  tool_call  fs.read  ·  340 tok · 0.4s            │
│  ├─ Step 3  observation       ·  120 tok · 0.1s            │
│  └─ Step 4  thinking  ·  890 tok · 1.8s · deepseek-v4-pro  │
│                                                               │
│  Turn 2 · 并行审计（6 个子代理）                              │
│  ├─ SubAgent #1  scripts/     · running · 45%              │
│  ├─ SubAgent #2  _data/       · done    · $0.02           │
│  ├─ SubAgent #3  posts/       · running · 60%              │
│  └─ ...                                                     │
│                                                               │
│  Turn 3 · 汇总报告                                            │
│  └─ ...                                                     │
└───────────────────────────────────────────────────────────────┘
```

**设计要点**：

- 每个 Turn 为一个可折叠的区块，显示 `TurnContract.statement` 摘要
- Step 按 `seq` 顺序排列，显示 `kind`、耗时、`usage.vendor`/`usage.runtime` 关键指标
- 子代理并行执行时，显示实时进度条和预算消耗
- 点击任意 Step 展开右侧详情面板（见 3.3）

```

│  Turn 2 · Step 5 请求执行以下操作：                       │
│                                                           │
│  🔴 不可逆操作警告                                         │
│  工具: fs.write (文件写入)                                │
│  目标: /workspace/config/production.yml                    │
│  权限要求: draft → 需要审批                                │
│                                                           │
│  ┌─ 参数预览 ──────────────────────────────────────────┐  │
│  │  path: "config/production.yml"                      │  │
│  │  content: "(前200字符...) ..."                      │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                           │
│  预期副作用: fs 写入, reversible: false                   │
│  当前 Turn 预算剩余: $0.03 / $0.05                       │
│                                                           │

└───────────────────────────────────────────────────────────┘
```

**设计要点**：

- 明确显示**不可逆操作警告**（红色高亮）
- 展示三方记录对照（声明的工具、授权的权限、实际请求）
- 预算影响提示（执行后剩余预算）
- 用户反馈自动记录到 `UserInteractionRecord.feedback`（type: authorization）

### 3.7 用户反馈入口（User Feedback）

嵌入在每个助手消息和 Turn 结束处：

```
┌─ Feedback Bar ────────────────────────────────────────────┐
│  这个结果有帮助吗？                                        │
│  [👍] [👎] [💬 文本反馈] [🔄 重新生成] [✏️ 修改计划]       │
└───────────────────────────────────────────────────────────┘
```

**设计要点**：

- **点赞/点踩**：记录 `UserFeedback.type: output_rating`，含 `rating` 和可选 `content`
- **文本反馈**：打开内联输入框，记录 `type: text_feedback`
- **修改计划**：允许用户编辑后续 Turn 的 `TurnContract`，记录 `type: decision_change`
- 反馈数据实时写入 `UserInteractionRecord`，并 emit `user.feedback.captured`

## 4. 组件设计规范

## 5. 交互设计

### 5.1 核心交互流

**新建会话**：

1. 用户点击"新建会话" → 弹出 GoalContract 配置面板
2. 用户输入目标、选择策略、设置预算 → 创建 Session
3. UI 立即创建 `UserInteractionRecord`（状态 recording），显示在 Sidebar
4. Planner 生成 PlanGraph → UI 渲染 Turn 预览列表（可编辑）
5. 用户确认或修改 TurnContract → 开始执行

**执行中**：

1. 底部栏实时更新指标（SSE/WebSocket 推送 `HarnessEvent`）
2. 对话流追加 Step 卡片（thinking/tool_call/observation）
3. Tool Call 命中 Policy Engine → 弹出 ApprovalModal（如需）
4. 用户审批 → 记录 feedback → 继续执行
5. 子代理并行时，顶部下拉显示进度

**结束后**：

1. Reflector 评估 → UI 显示 Turn 结果（success/failed）
2. 弹出 Feedback Bar → 用户评分/反馈
3. `UserInteractionRecord` 状态置 completed，写入 outcome 和 metrics
4. 失败时自动提示是否加入 Failure Ledger

### 5.2 快捷键

| 快捷键                   | 功能                            |
| ------------------------ | ------------------------------- |
| `Ctrl/Cmd + N`         | 新建会话                        |
| `Ctrl/Cmd + Shift + N` | 从模板新建                      |
| `Ctrl/Cmd + F`         | 搜索会话                        |
| `Ctrl/Cmd + B`         | 折叠/展开 Sidebar               |

## 6. 数据流与状态管理

### 6.1 前端状态架构

```
┌─ Global Store (Zustand / Redux) ──────────────────────────┐
│  ├─ sessionStore: 当前 Session 完整对象（含 turns[]）      │
│  ├─ eventStore:  当前 Session 的 HarnessEvent[]（追加式）  │
│  ├─ uiStore:     界面状态（折叠、选中 Tab、主题等）        │
│  └─ userStore:   用户画像、设置、Flag 快照                 │
├───────────────────────────────────────────────────────────┤
│  WebSocket / SSE 连接                                     │
│  └─ 订阅 HarnessEvent 流，实时更新 store                   │
├───────────────────────────────────────────────────────────┤
│  API 层                                                   │
│  ├─ GET  /api/sessions          → Session[]               │
│  ├─ GET  /api/sessions/:id      → Session + Turn[] + Step[] │
│  ├─ GET  /api/sessions/:id/events → HarnessEvent[] (回放) │
│  ├─ POST /api/sessions          → 创建 Session            │
│  ├─ POST /api/approval          → 审批响应                │
│  ├─ POST /api/feedback          → 用户反馈                │
│  └─ GET  /api/profile/:userId   → 用户画像                │
└───────────────────────────────────────────────────────────┘
```

### 6.2 关键数据映射

| UI 元素      | 数据源                                                        |
| ------------ | ------------------------------------------------------------- |
| 会话列表     | `Session[]`（投影：sessionId, rawIntent, aggregate, state） |
| 对话流       | `Turn[] → Step[]`（按 seq 排序，渲染为气泡/卡片）          |
| 轨迹时间线   | `HarnessEvent[]`（按 timestamp 排序，过滤类型）             |
| 三方记录对照 | `TurnContract + Capacity + Step`（同 turnId/stepId 聚合）   |
| Usage 统计   | `Step.usage`（vendor + runtime + cost + timing）            |
| 实时底部栏   | `SessionAggregate` + 当前 Step 的增量事件                   |
| 用户画像     | `UserInteractionRecord[]`（按 userId 聚合）                 |
| 失败分类账   | `failure_ledger` 表查询                                     |
