## 1. 本次修订目的

v1.2 把“用户的一次输入”直接等同于 UI 会话，并且 Session 承载 `userId`。经评审后调整为：

1. core 的 Session/Turn/Step 继续描述执行链路，但 Session 不再是 UI“会话”的全部；
2. 新增 API 层 Conversation 抽象：一个 Conversation 持有 `Session[]`；
3. `userId`/`workspace`/`projectId` 归属 Conversation，不进入 core Session；
4. UI 侧列表与工作区分组都是 `Conversation[]` 的过滤视图。

本文仅对 v1.2 需要修订的部分做权威定义；未在本文件列出的章节，按 v1.2 继续有效。

## 2. 术语边界

| 术语 | 层级 | 含义 |
| --- | --- | --- |
| 会话 / Conversation | apps/api（应用层业务抽象） | 用户可见、可管理的一个会话容器；由 1..N 个 Session 组成 |
| Session | packages/core 等（执行领域） | 一次单独的用户输入 + 大模型完整输出，自含 sessionId，原有 Turn/Step 结构不变 |
| Turn / Step | packages/core 等（执行领域） | 一个 Session 完整输出内部的执行轨迹（子任务 / 最小执行单元） |
| 用户 / userId | apps/api Conversation + UserInteractionRecord | 会话归属用户；不落 core Session |
| 工作区会话 | apps/api Conversation | 与普通会话同构，仅多 `workspace` 与 `projectId` 两个归属字段 |

> 术语约定：文档、API、UI 中，“会话”应指 Conversation；涉及 core 执行对象时使用“Session”或“执行会话”，避免歧义。

## 3. core 结构定义（v1.3 调整）

### 3.1 Session / Turn / Step

```ts
// packages/core/src/session.ts
/** 一次用户输入 + 大模型完整输出；core 执行聚合，不含 userId，不感知 Conversation */
export interface Session {
    sessionId: string;
    rawIntent: string;
    goal: GoalContract;
    strategyId: string;
    state: SessionState;
    turns: Turn[];             // 完整输出内部的执行轨迹
    aggregate?: SessionAggregate;
    flagSnapshot: FlagSnapshot;
    createdAt: number;
    endedAt?: number;
    outcome?: 'success' | 'failed' | 'aborted' | 'timeout';
}
```

相对 v1.2 的差异：

- 移除 `Session.userId`；
- 移除“Session = 会话”的表述；
- Session 不增加 Conversation 反向引用（无 `conversationId` 字段）；
- Flag 求值、用户交互记录、画像仍需要用户上下文时，由 API/运行时在创建时注入。

Turn / Step 的定义与约束沿用 v1.2 §3.1：Turn 是 Session 内的执行分段，Step 是最小执行单元；二者只属于 Session，不属于 Conversation。

### 3.2 用户上下文来源

用户上下文现在有两个出口，均不属于 core Session：

1. Conversation.userId：业务归属；
2. UserInteractionRecord.userId：用户画像/账本聚合。

Flag/用户规则在 Session 创建时读取 API 传入的用户上下文求值并冻结为 `flagSnapshot`。

## 4. Conversation（API 层业务抽象）

### 4.1 定义

Conversation 不属于 `packages/core`，而是 apps/api 层的业务抽象/仓储；core Session/Turn/Step 不感知 Conversation。

```ts
// apps/api/src/conversations/conversation.ts
export interface Conversation {
    conversationId: string;
    title: string;
    userId?: string;
    sessions: Session[];
    workspace?: string;   // 与 projectId 成对出现才属于工作区项目
    projectId?: string;
    createdAt: number;
    updatedAt: number;
    archived?: boolean;
}
```

持久化形态使用 `ConversationRecord`，只保存 `sessionIds` 引用，投影时再水合为完整 `Session[]`。

### 4.2 不变量

1. Session 仍是独立聚合，自身只带 `sessionId`；
2. 一个 Conversation 可以只有一个 Session，也可以包含多个 Session；
3. 同一 Conversation 内的 Session 共享归属用户；
4. `projectId` 与 `workspace` 必须成对出现，否则视为普通会话；
5. Conversation 可归档；归档只改变会话可见性，不删除 Session。

## 5. 存储与 API 契约（v1.3 现状）

### 5.1 存储

- core 数据：SQLite `sessions/turns/steps/user_interactions`；
  - `sessions` 不再包含 `user_id` 列；
  - 删除会话通过 `MemoryStore.deleteSession(sessionId)` 级联清理；
- Conversation：apps/api 以 `$MAZI_HOME/conversations.json` 持久化；
- 旧 `$MAZI_HOME/workspaces.json` 的 `projects[].sessionIds` 在首次读取时自动回填 Conversation 并清除；`workspaces.json` 只保留项目 `title/path` 元数据。

### 5.2 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/conversations?limit=&offset=&q=` | 会话列表（含归档；支持分页与标题筛选；投影为 Session[]） |
| PATCH | `/api/conversations/:id` | 重命名 / 归档 / 恢复 |
| DELETE | `/api/conversations/:id` | 删除 Conversation 并级联删除 Session |
| GET | `/api/ledger?limit=` | 失败分类账查询 |
| POST | `/api/sessions` | 创建 Session；默认生成新 Conversation；请求带 `conversationId` 时追加到已有 Conversation |
| GET/POST | `/api/sessions*` | core Session 创建/执行/详情/反馈（保持兼容） |
| GET/POST | `/api/workspaces/current|pick` | 工作区选择与项目元数据 |
| PATCH | `/api/workspaces/project` | 重命名项目展示名 |

### 5.3 WebUI 展示规则

- 默认“会话”区：Conversation 无工作区归属；
- 工作区项目分组：同一 `Conversation[]` 中按 `workspace/projectId` 过滤；
- “已归档”分组：`archived: true` 的会话，可恢复或删除；
- Conversation 支持重命名、归档/恢复、删除；项目名支持重命名。

## 7. v1.2 → v1.3 变更清单

1. §3.1：`Session` 去掉 `userId`；明确 Session 是一次输入 + 完整输出的 core 执行聚合。
2. 新增 Conversation：位于 apps/api，持有 `Session[]` 与用户/工作区归属。
3. 术语：UI“会话”= Conversation；core 对象称 Session。
4. 存储：`sessions` 表不再存 `user_id`；Conversation 走 `conversations.json`。
5. API：补 Conversation CRUD、项目重命名，明确 `POST /api/sessions` 的 Conversation 生成语义。
6. 路线图不变：M1 核心闭环完成；后续按 M2–M8 演进，并优先补齐 Conversation 续聊与兼容层清理。
