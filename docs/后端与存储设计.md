# mazi 后端与存储设计文档（Backend & Storage Design）

> 版本：v0.2
> 依据：docs/webui.md（UI 需求、§6 数据流/API、验收 1-10）；docs/UserConfigWebUI设计.md（~/.mazi 与 Web 入口）；MVP/ProviderAdapter 文档。
> 范围：支撑 WebUI（及未来多端）的后端服务与存储层设计。默认 SQLite；存储经 SPI 可配置，后续可接入 PostgreSQL / 向量数据库。
> **v0.3 勘误（2026-09-06）**：现行传输层已完成 NG-0~NG-6（NestJS + Fastify）；Conversation 以 `$MAZI_HOME/conversations.json` 持久化并支持管理端点；`sessions` 表已移除 `user_id`；Conversation 列表支持分页/标题筛选；`failure_ledger` 最小闭环（SQLite 表 + 写入点 + `/api/ledger` + WebUI）已落地。BE-* 存储 SPI / migrations / PostgreSQL 仍为规划，未落地。术语与结构以总体设计 v1.3 为准。

## 1. 后端目标与边界

目标：让 webui.md 三栏界面可落地——会话列表、对话流（Step 卡片）、轨迹时间线、三方记录审计、实时指标、用户画像、失败分类账、设置、反馈与（未来）审批——由统一后端能力支撑：
1. 查询/投影服务：把运行聚合变成 UI 可分页/过滤/排序读取的只读模型。
2. 运行控制服务：创建会话/执行/中断/审批响应/反馈采集。
3. 实时事件通道：SSE 推送 HarnessEvent，底部栏/轨迹实时更新。
4. 审计与治理：三方记录对照所需原始数据、失败分类账、事件回放不依赖模型。
5. 存储抽象：聚合数据默认 SQLite；同接口可换 PostgreSQL；向量检索作为独立适配器为语义记忆预留。

明确不做（本期）：多用户鉴权体系（仅 userId/workspace 预留）；集群/分布式运行；前端实现。

## 2. 总体架构

Browser (webui.md 三栏)
   │ REST + SSE
   ▼
L-Web  apps/web (node:http)：静态页 + /api/* + SSE 桥(订阅 DefaultEventBus)
   ▼
L-App  应用服务：RunService(复用 HarnessRuntime, 串行队列) / QueryService(投影) / FeedbackService / ProfileService(批处理占位)
   ▼
L-Domain  packages/harness-runtime + strategy/executor/planner/...（现有，无改动）
   ▼
L-Storage SPI  存储契约：Repository 组 + StorageProvider + Dialect + 驱动注册表
   ▼
Driver：sqlite(默认 node:sqlite ~/.mazi/mazi.db) | postgres(预留 pg://…) | vector(独立适配器, 预留)
事件审计：DefaultEventBus JSONL(~/.mazi/events) 与关系库并存，双写原则(§5.4)

依赖单向：L-Web→L-App→L-Domain→L-Storage；L-Storage 只依赖 core 契约与 driver SDK（防腐）。

## 5. 存储层设计（核心）

### 5.1 决策

| # | 决策 | 说明 |
| - | ---- | ---- |
| S1 | 默认 SQLite（node:sqlite DatabaseSync；~/.mazi/mazi.db；MAZI_HOME 可覆盖；:memory: 测试） | 零依赖单文件，现状已实现 |
| S2 | 存储经 SPI(StorageProvider+Repository)，业务不触碰 SQL | 现有 MemoryStore(core) 演进为仓储组合 |
| S3 | 方言收敛窄接口，不引入 ORM | upsert/JSON/标识符/分页/时间戳差异由 Dialect 承担 |
| S4 | 事件审计走 JSONL(DefaultEventBus)；关系库存事实聚合与可查询投影 | 事件权威、行可重建，缺一报警 |
| S5 | driver/连接走环境变量：MAZI_STORAGE_DRIVER(sqlite|postgres)、MAZI_DB_PATH / MAZI_STORAGE_URI | 缺省 sqlite+home |
| S6 | 向量检索为独立 VectorStore 适配器，不并入关系驱动 | 语义记忆/检索未来接入 |
| S7 | schema 走版本化迁移 migrations v{n}，各 driver 各自 DDL | createSchema 演进出 v1 |
### 5.2 Repository 契约（core 类型层，零依赖）

    interface SessionRepo { save/load/updateState/list(filter,page)/aggregate }
    interface TurnRepo { save/loadById/listBySession/updateStatus/checkpoint }
    interface StepRepo { save/listByTurn/query(kind,seqRange)/usageRange }
    interface InteractionRepo { save/load/list(userId,status,page,updatedSince) }
    interface LedgerRepo { add/query(kind,timeRange,tags,page) }      // failure_ledger
    interface VectorStore { upsert(id,vector,meta)/search(query,topK,filter?) } // 预留
    interface StorageProvider { driver; open(config): Promise<void>; close();
      session/turn/step/interaction/ledger: Repos; transaction<T>(fn) }
    type StorageConfig = {driver:"sqlite", path?} | {driver:"postgres", uri} | {driver:"vector", uri?, dim?}

SqliteMemoryStore(@mazi/memory) 重构为 SqliteStorageProvider+Repos，对外保持 MemoryStore 实现者兼容（B9）。

### 5.3 数据模型（关系库）

沿用 ~/.mazi 目录与 MVP §4.3 表；增补：
| 表 | 说明 | 索引 |
| --- | --- | --- |
| sessions | 现列 + workspace + aggregate_json | (workspace,state)、(user_id,created_at) |
| turns | 现列(contract/capacity JSON) | (session_id,status) |
| steps | 现列(payload/usage JSON) | (turn_id,seq)、(kind)、(status) |
| user_interactions | 现列 | (user_id,updated_at) |
| failure_ledger | session/turn/step_id, failure_kind, cost_usd, provider_id, tags, summary, created_at | (kind,created_at) |
| migrations | version, applied_at | 迁移账本 |

规则：JSON 列存原始对象（sqlite TEXT / postgres jsonb）；查询所需标量（cost/tokens/state）落冗余标量列，写入双写、读取以标量为准 JSON 为证。

### 5.4 一致性原则

- 写入顺序：业务提交关系库 → 事件总线落盘；两者成功才算完成（启动可做 diff/修复）。
- 重建路径：replay(sessionId)（JSONL）重建 Session（现有 recovery 语义）→ 迁移/导出/修复。
- 事务边界：单聚合内事务（session+turns、turn+steps、record 单行）；跨聚合不强事务。

| --- | --- | --- |

| MAZI_STORAGE_DRIVER | sqlite | sqlite | postgres(预留) |

| MAZI_STORAGE_URI | - | postgres://…（预留） |

### 5.6 向量库预留

- 语料：rawInput + thinking/observation 摘要 + 未来跨会话 memory。
- 接口 VectorStore.upsert/search；meta 挂 sessionId/turnId/kind/tags。
- 管道：文本→embedding→upsert（模型未选型）；检索结果经 memory 接入 planner/executor（M3 起）。
- 候选后端：pgvector / qdrant / sqlite-vec，适配器隔离。

## 6. 实时事件通道（SSE）

- follow=1：按 sessionId+types 订阅 DefaultEventBus，转发 event: type + data: json；断开退订。
- 指标增量：随 llm.response/step.ended 推送 mazi.metrics 自定义 event。
- 心跳 comment 15s；断线重连先拉快照再 follow。

## 9. 风险与后续

1. JSON vs 标量冗余可能漂移：靠迁移/校验任务兜底，事件 JSONL 为权威。
2. sqlite 特有语义（rowid/upsert ON CONFLICT/JSON1）尽早收敛到 Dialect。
3. 向量选型未定：本期仅定接口，embedding/距离度量/分片接入时评审。
4. SSE 满足 MVP；WebSocket/横向扩展需事件总线可跨进程后置。
5. 多用户以 userId/workspace 维度预留，不上鉴权框架。

## 10. 传输层技术选型：NestJS + Fastify（v0.2 决策）

> 决策背景：apps/api 现行 API 为单文件手写 `node:http`（REST + SSE + CORS，约 286 行），
> 端点增至 sessions/timeline/profile/events/feedback 后路由、入参解析、校验、错误映射、
> 长连接管理均在手写样板中蔓延。经评审改为 **NestJS（平台适配 Fastify）** 模块化实现。
> 注：本文 §2 的 L-Web 描述的是收敛后单服务形态（静态页 + /api + SSE 同进程）；当前实际部署仍为
> **apps/web（静态，5174）+ apps/api（API，4317）**，本决策只作用于 apps/api 传输层。

### 10.1 决策表

| # | 决策 | 理由 |
| - | ---- | ---- |
| D-HTTP-1 | Web 框架：**NestJS 12 + @nestjs/platform-fastify**（不引入 Express 平台） | Fastify 内置 schema 校验/高性能/HTTP2 友好；Nest 提供模块化、DI、生命周期与全局异常管道；与手写 node:http 相比路由/校验/错误映射标准化 |
| D-HTTP-2 | 校验不引入 class-validator：沿用现有手工校验，错误体与状态码**逐字对齐旧实现**（`400 {error:'缺少 input'}`、`404 {error:'session not found'}`、`409 {error:'已有会话在运行，请稍候'}`、兜底 `500 {error:<msg>}`） | 契约稳定、零新依赖；DTO 后续再迁 OpenAPI 时可整体引入 |
| D-HTTP-3 | 运行/执行端点维持**进程内串行锁**（busy 标志 → 409），执行在 HTTP 生命周期内 await（与旧行为一致） | 单用户 MVP 语义不变；长任务队列化属 BE-4 演进范围，不在本次传输层替换内 |
| D-HTTP-4 | SSE 直接订阅 **HarnessRuntime 同一 DefaultEventBus 实例**（`runtime.eventBus`） | 旧实现每请求新建 bus 实例，live 事件推不到（实例间订阅不互通，仅回放生效）；复用同一实例使 follow 同时获得回放 + 运行中实时事件，线上格式不变（`event: <type>\ndata: <json>\n\n`，15s `: ping` 心跳） |
| D-HTTP-5 | feedback 经同一 bus 实例 emit + flush（双写 JSONL 语义不变） | 保证 SSE 订阅者可见、写盘完成后再应答（旧实现：每请求新建实例 emit+flush） |
| D-HTTP-6 | 依赖注入用 Nest 原生（构造器注入 + `@Inject` 令牌），不引第三方 DI | Nest 标准用法 |
| D-HTTP-7 | 编译配置：apps/api 开启 `experimentalDecorators` + `emitDecoratorMetadata` | Nest DI 依赖 design:paramtypes；已实测仓库 TypeScript 7.0.2 可正确发出（不污染 tsconfig.base，仅 apps/api 覆盖） |
| D-HTTP-8 | 环境变量不变：端口 `MAZI_SERVER_PORT ?? MAZI_WEB_PORT ?? 4317`；CORS `MAZI_CORS_ORIGIN` 默认 `*` | 与 README/web 冒烟脚本兼容，迁移对前端透明 |
