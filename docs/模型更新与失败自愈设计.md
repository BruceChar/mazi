# 模型更新与失败自愈设计

> 背景：生产出现 `400 The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-v41-flash`。
> 根因有二：① `packages/provider` 曾在离线目录里硬编码 `deepseek-v41-flash`；② 模型同步只做「合并、绝不删除」，
> 导致本地 pi-ai 目录的陈旧模型名（`deepseek-v4-flash`…）与硬编码补充永久残留在 `providers.json`，
> 启动与「同步模型」按钮都无法纠正。本设计给出**在线权威发现 + 权威替换 + 失败自愈**。

## 1. 目标

1. 服务重启后自动更新为端点**真实可用**的模型名；
2. 设置里的「同步模型」按钮真正生效；
3. 模型调用失败（如 400 invalid model）必须**发出事件**；
4. 模型/运行时能**消费事件并自愈**：重同步模型、换用正确模型重试，必要时重建运行时继续任务。

## 2. 在线权威发现（provider 层）

- 新增 `fetchRemoteModelIds()`：对 OpenAI/DeepSeek 兼容端点调用 `GET {baseUrl}/models`，
  解析 `data[].id`，去重后排序；`deepseek` 缺省 baseUrl 为 `https://api.deepseek.com`。
- `discoverModels(providerId, { apiKeyEnv, env, baseUrl, fetchImpl })`：
  - 有 API Key → 在线优先，成功 `{ source: 'remote', refreshed: true }`；
  - 无 Key / 非 2xx / 网络失败 → 回退本地 pi-ai 目录并带 `warning`（`source: 'local'`）。
- 离线目录 `builtinModelsFor()` **移除硬编码补充**，仅作回退，不再代表端点真实模型名。

## 3. 权威替换（api 层 `ApiRuntimeService`）

- `syncProviderModels()`（启动兜底，离线）：对本目录命中的 provider **替换** `models` 列表；
- `syncProviderModelsOnline()`（在线）：以 `discoverModels` 结果**替换** `models`；
- 替换规则（`applyModelList`）：
  - 保序保留同 id 的既有元数据；新 id 有本地目录则用目录元数据，否则 `{ id, name: id }`；
  - **厂商不再返回的陈旧 id 被移除**（这是修复 v41 的关键）；
  - `driver.model` 不在新列表内 → 重置为新列表首个模型；
  - 未在观测集中的 provider（未知厂商）原样保留。
- 触发：构造函数（离线同步 + 异步在线同步）、`POST /api/config/sync`、`POST /api/runtime/restart`。

## 4. 失败事件（core + runtime）

- `CoreEventType` 增加 `llm.error` 与 `provider.recovered`。
- `HarnessRuntime.requestRound` 的每次扩展轮失败都发 `llm.error`：
  - attributes：`gen_ai.provider.name`、`harness.level='error'`、可选 `harness.provider_error_code`；
  - payload：`{ code, message, model, attempt }`；
  - 事件经统一 EventBus 落盘/SSE，UI 与任何消费者（含模型）可观测。

## 5. 自愈路径（runtime + api）

- `HarnessRuntime.setModelRecovery(fn)`：注入恢复回调；
- 失败判定 `isModelRelatedError`：`invalid_request` 或消息含 `model/模型/unsupported/not found`；
- 首次失败（attempt=0）且命中判定 → 调 `fn({ providerId, modelId })`：
  - API 侧实现 = `recoverModels()`：在线重同步 + 重载配置 + 返回修正后的 `{ providerId, modelId }`；
  - runtime 用返回的 modelId 覆盖候选模型，**重试一次**；成功则发 `provider.recovered`；
- 非模型类失败 / 无回调 / 恢复无果 → 原样抛出，Task 记 `driver-error`（行为不回归）。

## 6. 运行时重启

- `POST /api/runtime/restart` → `ApiRuntimeService.restart()`：在线重同步 → 重载配置 → 丢弃并重建运行时；
- 有会话执行中不打断（`restarted=0`），语义等价「进程内重启」。

## 8. 运维注意

- 在线发现依赖服务进程环境中的 API Key（`DEEPSEEK_API_KEY` 或 provider `driver.apiKeyEnv`）；无 Key 时回退本地目录并告警。
- 自定义/私有网关：在 provider `driver.baseUrl` 指定端点，发现请求打到该端点。
- 权威替换会移除手工加入但端点未返回的模型；如需保留，应将其加入厂商目录或在端点暴露。
