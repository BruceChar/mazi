# 模型目录与计费实施设计（Implementation Design）

> 依据：\`docs/模型目录与计费数据架构设计文档.md\`（v1.0，五层模型 vendor → model → provider → offering → driver）。
> 本文把架构文档落到本仓库现实：**从 core 契约层往上推**，逐特性给出文件、接口、验收。
> 允许变更原设计的部分在 §2 显式记录。

## 1. 分层落位

| 层 | 包 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 契约/纯逻辑 | \`@mazi/core\` \`src/catalog.ts\` | 五层实体类型、能力合成、价格卡选择与计价、快照构建、生命周期/生效判定 | 不依赖 IO / 存储 / 厂商 SDK |
| 持久化 | \`@mazi/runtime\` \`src/catalog/store.ts\` | CatalogStore SPI：事实快照读写 + usage/changes 追加 | 不实现业务 diff |
| 同步管线 | \`src/catalog/sync.ts\` | 观测目录 → diff → upsert/软删/价格追加回填 → CatalogChange + epoch | 不感知存储介质 |
| 运行时快照 | \`src/catalog/snapshot.ts\` | 按 epoch 从事实重建 CatalogSnapshot，原子指针交换 | 不落库 |
| 路由 | \`src/catalog/router.ts\` | DriverConfig 默认绑定 + 迁移链 + 能力/价格/健康过滤 | 不做厂商通信 |
| 账本 | \`src/catalog/ledger.ts\` | 派发钉死 (offering, plan, epoch) → append UsageRecord → 审计查询 | 不 UPDATE/DELETE 历史 |

依赖单向：core ← runtime catalog ← apps/api / webui。core 零外部依赖。

## 2. 对原设计的必要变更（诚实记录）

1. **存储介质**：原设计定 Postgres。本仓库现无关系库存储层（goal 事实走 node:sqlite，配置走 JSON）。
   本期实现 **CatalogStore SPI + 内存实现 + 文件实现**（\`$MAZI_HOME/catalog/catalog.json\` + \`usage_records.jsonl\`），
   保持“目录事实整体原子提交、账本追加”的语义；后续可新增 Sqlite/Postgres 实现而不改上层。
2. **价格档位语义**：原设计 \`PricingTier{thresholdTokens, rates}\` 未定义阈值比较维度。本文明确为
   **按输入 token 数选择费率卡**：取 \`thresholdTokens <= inputTokens\` 的最大档，否则用 base；
   命中档位的 \`rates\` 整体替换 base（长上下文加价模型）。原运行时的按时段倍率 \`PricingSchedule\` 保留，
   服务现有展示与测试，catalog 账本只用 \`PricingPlan\`。
3. **同步范围**：一次 sync 只对**观测集中出现的 provider** 权威：其 offering 缺席即软删；
   provider 未出现的渠道与 model 行不受影响（避免误删运维手工目录）。厂商级 model 下架走显式运维操作。
4. **品牌 id**：遵循原设计 \`VendorId\` 等 branded string，另提供 \`vendorIdOf/providerIdOf/modelIdOf/offeringIdOf\`
   构造器，避免全仓裸 as 断言；\`offeringId = \`\${providerId}/\${modelId}\`\`。
5. **UsageRecord 货币**：加 \`currency\` 冗余列（与 CostBreakdown 一致的 USD 口径）。
6. **时间戳**：原设计用 \`Date\`；本仓库统一用 **epoch 毫秒 number**（与 createdAt/startedAt 等既有约定一致，
   JSON 往返无损）。\`effectiveAt/expiresAt/observedAt/occurredAt/sampledAt/mappedAt\` 均为 number。
7. **审计事件类型扩展**：新增 \`provider-updated\` / \`model-updated\` / \`offering-updated\`（厂商静默改规格、
   渠道 override 变更需留痕）；\`CatalogChangeSource\` 增加 \`manual-import\`（bootstrap）。
8. **同步观测时刻**：\`CatalogService.sync\` 的 \`now\` 缺省取服务时钟，且快照重建与写入共用同一逻辑时刻，
   保证「观测时点 → 价格生效」在同一时间轴上（生产二者都是 Date.now）。

**端到端闭环（已验证）**：
`providers.json` → seed 映射 → sync（diff/soft-delete/pricing append+backfill → `CatalogChange` + `epoch++`）
→ 快照整体重建并原子交换 → 路由（能力/价格/健康/fallback）→ 派发钉死 `(offeringId, pricingPlanId, epoch)`
→ 每轮 usage 追加 `UsageRecord`（按钉死价目计价）→ 审计查询 / REST 端点。

**验证命令**：`pnpm build`（6/6）、`pnpm test`（+36 项 catalog 用例全绿；仅 1 项仓库历史遗留失败）、
`pnpm exec biome check <touched files>`（无 error/warning）。

**按需扩展（非本轮要求）**：健康探测器周期采样与聚合旁路 · 多实例 epoch pub-sub/轮询 ·
`usage_records` 按月分区与冷归档 · WebUI 审计面板 · Sqlite/Postgres CatalogStore 实现。

## 5. 官方价目页抓取（价格随官网校准）

> 目标：展示与计费的人民币单价始终与厂商官网一致，而非代码内写死的近似值。

| 环节 | 实现 | 落点 |
| --- | --- | --- |
| 抓取地址 | **按厂商（vendor）配置**，持久化 `settings.json.pricing.vendors[vendor].sourceUrl`（空 = 该 vendor 不抓取）；旧 `pricing.sourceUrl` 视为 deepseek | `RuntimeSettingsFile`、`ApiRuntimeService.setPricingSource(vendor, url)` |
| 抓取时机 | 进程启动一次 + 定时任务（默认 5 分钟，`MAZI_PRICE_SYNC_MS` 可覆盖） | `ApiRuntimeService.syncModelsAndPricing` |
| 确定性解析 | DeepSeek 官方文档页正则解析（空闲/高峰 × flash/pro） | `@mazi/provider` `parseDeepseekPricingPage` |
| Agent 兜底 | 页面结构变化/新厂商时，把正文交给配置模型，要求回传严格 JSON，再 `parseAgentPricingJson` 解析 | `buildPricingAnalysisPrompt` + `createPricingAnalyst`（runtime） |
| 落盘 | 逐模型写 `models[].pricing`（flash/pro 各自单价），provider 级 `pricing` = 默认模型价目 | `syncOfficialPricing` |
| 高峰时段 | 官网仅给空闲/高峰两档：空闲为 base，高峰由 `DEEPSEEK_PEAK_TIERS`（UTC 周中 [1,4)/[6,10) ×2）表达 | `packages/provider/src/catalog.ts` |
| 模型清单 | 官网页同时列出模型名 → 以其为权威替换 `models`，并跳过单独的端点 `/models` 发现；**已落官方价后 pi-ai 目录不得再覆盖**（目录含已下线 id，如 `deepseek-v4-flash-vision-exp`） | `applyModelList` + `officialModelListVendors` + `hasOfficialPricing` |
| 旧模型名 | 页脚「旧模型名 … 仍可调用，但对应模型已下线」解析为 `deprecatedModels`，过滤陈旧 id | `parseDeepseekPricingPage` |
| 优先级 | 官方人民币价（`version=deepseek-2026-09`）不被 pi-ai 目录价（USD）反向覆盖 | `applyCatalogPricing` 守卫 |
| fail-safe | 抓取/解析失败只告警，不覆盖既有配置；解析器不合法（非 CNY/缺字段）一律拒绝 | `syncOfficialPricing` |
| 上下文/输出窗口 | 页面标注的「上下文长度 1M / 输出长度 最大 384K」一并解析并写入 `models[].contextWindow/maxTokens` | `parseDeepseekPricingPage` + `syncOfficialPricing` |

**逐模型计价**：`HarnessRuntime.pricingOf(providerId, modelId)` 优先取该模型的 `pricing`，缺省回落 provider 级；
`pricingSnapshot/roundCost/roundEstimatedCost` 均带 `outcome.metrics.modelId`，因此选 pro 时按 pro 单价计费。

**设置落点**：价格源属于 **vendor**，显示在 **Settings → Providers → 各 vendor 分组下**（不是 General）。
每个分时档展示**对应时段**（如「高峰 ×2 · 周一至周五 09:00–12:00」，UTC window 按浏览器时区换算）；
每模型展示空闲 + 各分时单价与货币，vendor 下有「更新价格」按钮（`POST /api/config/pricing/refresh`，
可带 `{ vendor }` 只更新该厂商）。`configOverview()` 把入库的分时价（`ProviderPricingView`：
base + tiers + currency + version）与 `vendor` 投影给前端，缺省才回退 pi-ai 目录价。

**API Key（secrets.json）**：设置里每个 provider 有「API Key」栏，写入 `$MAZI_HOME/secrets.json`
（`{ providers: { [id]: { apiKey } } }`，0600，不进 providers.json/configOverview，overview 只暴露
`apiKeySet` 布尔）。`withProviderSecrets` 在读配置后注入 `RuntimeConfig.providers[].driver.apiKey`，
adapter 优先使用字面 Key、否则回落 `apiKeyEnv`。

**同步口径**：`syncOfficialPricing(vendor?)` 遍历所有已配置价目源的 vendor（或指定 vendor），逐个
抓取→解析→只写该 vendor 的 providers 条目；返回 `vendors` 明细与聚合的 `updated/models/modelIds/error`，
并把 `lastSyncedAt/lastError/models` 记入 `settings.json.pricing.vendors[vendor]`（vendor 条目内部浅合并，
不丢 sourceUrl）。

**上下文占比**：`HarnessRuntime.contextWindowOf(provider, model)` 按模型真实窗口（providers.json
`contextWindow` → pi-ai 目录 `maxInputTokens` → 运行时缺省）解析，避免固定 64K 误算占比。

**测试**：`packages/provider/src/deepseek-pricing.test.ts`（确定性解析 + Agent JSON 解析）、
`packages/runtime/test/pricing-analyst.test.ts`、`apps/api/test/pricing-sync.test.ts`
（抓取落盘/Agent 兜底/fail-safe/目录不覆盖官方价）。测试注入 `setPricingFetch`、`setPricingAnalyst`
以保证 hermetic（网络默认在 `VITEST` 下禁用）。
