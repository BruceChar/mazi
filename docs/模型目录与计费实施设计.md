# 模型目录与计费实施设计（Implementation Design）

> 依据：\`docs/模型目录与计费数据架构设计文档.md\`（v1.0，五层模型 vendor → model → provider → offering → driver）。
> 本文把架构文档落到本仓库现实：**从 core 契约层往上推**，逐特性给出文件、接口、验收。
> 允许变更原设计的部分在 §2 显式记录。

## 1. 分层落位

| 层 | 包 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 契约/纯逻辑 | \`@mazi/core\` \`src/catalog.ts\` | 五层实体类型、能力合成、价格卡选择与计价、快照构建、生命周期/生效判定 | 不依赖 IO / 存储 / 厂商 SDK |
| 持久化 | \`@mazi/runtime\` \`src/catalog/store.ts\` | CatalogStore SPI：事实快照读写 + usage/changes 追加 | 不实现业务 diff |
| 同步管线 | \`src/catalog/sync.ts\` | 观测目录 → diff → upsert/软删/价格追加回填 → CatalogChange + epoch | 不感知存储介质 |
| 运行时快照 | \`src/catalog/snapshot.ts\` | 按 epoch 从事实重建 CatalogSnapshot，原子指针交换 | 不落库 |
| 路由 | \`src/catalog/router.ts\` | DriverConfig 默认绑定 + 迁移链 + 能力/价格/健康过滤 | 不做厂商通信 |
| 账本 | \`src/catalog/ledger.ts\` | 派发钉死 (offering, plan, epoch) → append UsageRecord → 审计查询 | 不 UPDATE/DELETE 历史 |

依赖单向：core ← runtime catalog ← apps/api / webui。core 零外部依赖。

## 2. 对原设计的必要变更（诚实记录）

1. **存储介质**：原设计定 Postgres。本仓库现无关系库存储层（goal 事实走 node:sqlite，配置走 JSON）。
   本期实现 **CatalogStore SPI + 内存实现 + 文件实现**（\`$MAZI_HOME/catalog/catalog.json\` + \`usage_records.jsonl\`），
   保持“目录事实整体原子提交、账本追加”的语义；后续可新增 Sqlite/Postgres 实现而不改上层。
2. **价格档位语义**：原设计 \`PricingTier{thresholdTokens, rates}\` 未定义阈值比较维度。本文明确为
   **按输入 token 数选择费率卡**：取 \`thresholdTokens <= inputTokens\` 的最大档，否则用 base；
   命中档位的 \`rates\` 整体替换 base（长上下文加价模型）。原运行时的按时段倍率 \`PricingSchedule\` 保留，
   服务现有展示与测试，catalog 账本只用 \`PricingPlan\`。
3. **同步范围**：一次 sync 只对**观测集中出现的 provider** 权威：其 offering 缺席即软删；
   provider 未出现的渠道与 model 行不受影响（避免误删运维手工目录）。厂商级 model 下架走显式运维操作。
4. **品牌 id**：遵循原设计 \`VendorId\` 等 branded string，另提供 \`vendorIdOf/providerIdOf/modelIdOf/offeringIdOf\`
   构造器，避免全仓裸 as 断言；\`offeringId = \`\${providerId}/\${modelId}\`\`。
5. **UsageRecord 货币**：加 \`currency\` 冗余列（与 CostBreakdown 一致的 USD 口径）。
6. **时间戳**：原设计用 \`Date\`；本仓库统一用 **epoch 毫秒 number**（与 createdAt/startedAt 等既有约定一致，
   JSON 往返无损）。\`effectiveAt/expiresAt/observedAt/occurredAt/sampledAt/mappedAt\` 均为 number。
7. **审计事件类型扩展**：新增 \`provider-updated\` / \`model-updated\` / \`offering-updated\`（厂商静默改规格、
   渠道 override 变更需留痕）；\`CatalogChangeSource\` 增加 \`manual-import\`（bootstrap）。
8. **同步观测时刻**：\`CatalogService.sync\` 的 \`now\` 缺省取服务时钟，且快照重建与写入共用同一逻辑时刻，
   保证「观测时点 → 价格生效」在同一时间轴上（生产二者都是 Date.now）。

## 3. 特性分解（每个特性单独提交，文档+测试先行）

| ID | 内容 | 文件 | 验收 |
| --- | --- | --- | --- |
| MC-1 | core catalog 契约：五层实体 + 生命周期 + 品牌 id 构造器 | \`packages/core/src/catalog.ts\` | \`catalog.test.ts\` 类型/构造器/id 生成 |
| MC-2 | core 纯逻辑：能力合成、价格卡选择、计价、生效计划、快照构建 | 同上 | 快照仅含 active、无价 pricing=null、档位计价 |
| MC-3 | runtime CatalogStore SPI + Memory/File 实现 | \`runtime/src/catalog/store.ts\` | 读回一致、文件原子写、usage 追加 |
| MC-4 | sync 管线：diff/upsert/软删/reactivate/价格追加回填/change/epoch | \`sync.ts\` | 幂等（重复无 diff 不推 epoch）；调价回填 expiresAt |
| MC-5 | 快照构建 + 原子交换 + epoch 订阅 | \`snapshot.ts\` | 重建后 current() 换代；旧快照引用不变 |
| MC-6 | DriverConfig 解析 + 路由过滤（能力/价格/健康/迁移链） | \`router.ts\` | 默认优先、逐级 fallback、无价/能力不符剔除 |
| MC-7 | 派发钉死 + UsageRecord 追加 + 审计查询 | \`ledger.ts\` | plan/epoch 钉死；成本与 plan 一致；append-only |
| MC-8 | 对外 API：目录/供给/账本/审计端点 + WebUI 展示 | apps/api, apps/webui | 端点测试 + 前端可查 |

实施顺序硬约束：MC-1 → MC-2 → MC-3 → MC-4 → MC-5 → MC-6 → MC-7 → MC-8。
