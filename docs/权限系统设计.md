
# Agent Harness 权限系统设计

**文档性质**：权限子系统设计规范（TaskContract 架构的权限面实现）

**定位一句话**：权限不是被「设置」的，是被「派生」的——根层授予、任务层请求、effective 永远是计算值。

## 1. 设计目标

权限系统要在同一份设计里同时回答四个问题：

1. **安全**：子任务如何结构性无法越权，而不是靠纪律？
2. **自治**：几千个子任务如何做到无人参与而不失控？
3. **可审计**：任何一个已发生的动作，能否回答「它是在哪一层的哪次决定下被放行的」？
4. **可控**：无论权限配置多错，人是否永远叫得停？
   这四问对应四个机制：派生式权限、三档确认门、decisionLog、格外中止权。缺任何一个，其余三个都会塌。

---

## 2. 设计抉择与理由

### 2.1 为什么不用布尔权限矩阵

直觉设计（`read-only` / `workspace.write` / `full-access` 等布尔字段，分系统层/任务层）有五个不可修复的结构性缺陷：

| #                                                                                                                    | 缺陷                                           | 后果                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| B1                                                                                                                   | 把「作用域 × 操作」两个正交维度压平成一列布尔 | 偏序无法表达：`workspace.write: true, workspace.read: false` 合法但语义未定义；`read-only` 与 `full-access` 同 true 是可表示的非法态 |
| B2                                                                                                                   | 层间约束（任务不得超过系统）只能写在注释里     | 正确性寄托于编写者纪律；类型系统排除不了非法状态，检查负担全部推给运行时                                                                   |
| B3                                                                                                                   | 二元 allow/deny                                | 无中间档：要么过度授权（full-access 逃生舱），要么过度拒绝（人被确认请求淹没）。确认门没有存在空间                                         |
| B4                                                                                                                   | fs / net 各轴独立校验，无组合规则              | `read-only + network: allow` 单轴全合法，组合即是数据外泄管道与指令注入入口                                                              |
| B5                                                                                                                   | 「最高优先级」的覆盖语义                       | 覆盖意味着子层可以冲掉父层限制；且没有任何字段表达中止权、没有平台层硬上限                                                                 |
| 结论：**预设**（read-only / workspace 等）不是权限原子，是权限的模板；**权限原子**是「效果类 × 三档」。 |                                                |                                                                                                                                            |

### 2.2 五个核心决策

| 决策                                 | 内容                           | 替代方案及否决理由                                 |
| ------------------------------------ | ------------------------------ | -------------------------------------------------- |
| 权限原子 = EffectClass × EffectTier | 资源×操作 上的三档            | 布尔矩阵：B1–B5；enum 单轴：表达不了路径/域名范围 |
| 根层授予、任务层请求                 | 任务层数据结构上没有授予字段   | 分层声明 + 运行时校验：B2，靠纪律                  |
| effective = 计算值                   | 永不持久化为可编辑配置         | 存储 effective：产生篡改面与双写不一致             |
| 层间 = meet（取严者）                | 而非优先级覆盖                 | 覆盖：子层可放宽父层，违反权限单调性               |
| kill switch 在权限格之外             | 独立通道、不受任何 policy 约束 | kill 走 policy 管线：坏 policy 构成不可恢复态      |

## 3. 权威链

```
平台硬上限      代码内置，不可配置、不可签署
    ∩
用户根授予      AgentGrant，用户签署根契约时签发（唯一授予点）
    ∩
任务派生收缩    derive() 在 spawn 子任务时计算，只能收紧
    =
EffectivePolicy  运行时对象，永不序列化为可编辑配置
```

性质：

- **链上任何一层无权放宽上层**。子层想变宽只有一条路：发起 ContractRevision 升给人批准。
- **closed-world**：未在任何层显式声明的效果类别即 `forbidden`。不存在「没说就是允许」。
- **根层是最高人类节点，不是最高节点**。平台硬上限在其上；kill switch 在整个格之外。
- 根层模型（如旧的「跟随系统」标志）不存在——任务层没有可覆盖或可跟随的东西，它只有请求。

## 4. 数据模型

### 4.1 EffectClass：权限原子

```typescript
export type EffectClass =
    | 'fs.read.workspace' | 'fs.read.host'
    | 'fs.write.draft' | 'fs.write.sandbox' | 'fs.write.workspace'
    | 'fs.exec'
    | 'net.fetch' | 'net.send'
    | 'publish' | 'pay' | 'delete';
```

设计要点：

- **枚举开放**：新工具注册新类别；未注册类别的工具默认 `forbidden`。
- **可逆性入了类型**：`draft`（可丢草稿区）、`sandbox`（可回滚沙盒）与 `workspace`（真实工作区）分开——因为确认的成本定价依据是不可逆性，粒度到不了这里，价格就定不准。
- **fetch 与 send 分开**：fetch 是入口风险（注入），send 是出口风险（外泄），治理手段不同（§8）。
- **`delete` 单列**：不可逆性的典型，恒为 gated（§7.4）。

### 4.2 EffectTier：三档

```typescript
export type EffectTier = 'auto' | 'gated' | 'forbidden';
```

| 档                                                                               | 语义                                               | 谁支付注意力             |
| -------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------ |
| `auto`                                                                         | harness 直接放行，仅记账                           | 无人                     |
| `gated`                                                                        | 见 §6：范围内 = 静默预授权；范围外 = 非阻塞确认门 | 人，但仅在范围外且不可逆 |
| `forbidden`                                                                    | 命中即违约，不可执行                               | —                       |
| 三档是「几千个子任务不烦人」的前提：确认按不可逆性收费，沙盒内的可逆操作零确认。 |                                                    |                          |

### 4.3 EffectRule

```typescript
export interface EffectRule {
    tier: EffectTier;
    paths?: string[];   // 省略 = 在已授予作用域内不额外限制
    hosts?: string[];   // 仅 net.*；由 egress proxy 强制执行（§8）
}
```

`paths` 使用显式 glob 方言（`draft/**`），语义由单测固定，避免前缀匹配歧义。

### 4.4 根层授予

```typescript
export type AgentGrant = Partial<Record<EffectClass, EffectRule>> & {
    budget?: { steps?: number; tokens?: number; cost?: number };
};
```

预设是工厂，不是权限：

```typescript
export const PRESETS = {
    'read-only':       { 'fs.read.workspace': { tier: 'auto' } },
    'workspace':       { 'fs.read.workspace': { tier: 'auto' },
                         'fs.write.draft':    { tier: 'auto' },
                         'fs.write.sandbox':  { tier: 'auto' } },
    'workspace-write': { 'fs.read.workspace': { tier: 'auto' },
                         'fs.write.workspace':{ tier: 'auto' } },
} satisfies Record<string, AgentGrant>;
// full-access 仅存在于根层：独立构造函数内部断言根契约身份，
// 派生路径上不存在任何调用点
export function fullAccessGrant(rootContractId: ContractId): AgentGrant;
```

### 4.5 任务层请求

```typescript
export interface TaskPolicyRequest {
    requires: EffectClass[];                            // 必需能力，见 §5.3
    wants?: Partial<Record<EffectClass, EffectRule>>;   // 非必需，参与 meet
}
```

任务层的全部词汇是 `requires` / `wants`。没有授予字段、没有模式开关——**「任务层无法表达授予」由类型结构保证，不靠注释**。

### 4.6 EffectivePolicy

```typescript
export interface EffectivePolicy extends AgentGrant {
    derivedFrom: { parentId: ContractId; parentVersion: number };
}
```

仅存在于运行时；派生缓存 key = `parentId@parentVersion + hash(request)`，父契约版本变化自动失效。

## 5. 派生算法

### 5.1 meet 语义

| 轴            | 规则                                                           |
| ------------- | -------------------------------------------------------------- |
| tier          | 取严者：`min(parent, want)`；gate 只增不减                   |
| paths / hosts | 集合交；`undefined` 为顶元（不设限），`undefined ∩ X = X` |
| 未声明类别    | `forbidden`                                                  |

### 5.2 derive 实现

```typescript
const TIER_RANK: Record<EffectTier, number> = { forbidden: 0, gated: 1, auto: 2 };
const minTier = (a: EffectTier, b: EffectTier): EffectTier =>
    TIER_RANK[a] < TIER_RANK[b] ? a : b;
const intersect = (a?: string[], b?: string[]): string[] | undefined =>
    a === undefined ? b : b === undefined ? a : a.filter(x => b.includes(x));
export type DeriveResult =
    | { ok: true;  policy: EffectivePolicy }
    | { ok: false; revision: { wants: EffectClass }; reason: string };
export function derive(
    parent: AgentGrant & { id: ContractId; version: number },
    req: TaskPolicyRequest,
): DeriveResult {
    // 1. fail-fast：必需能力不可满足 → 升级，不 spawn
    for (const cls of req.requires) {
        if ((parent[cls]?.tier ?? 'forbidden') === 'forbidden')
            return { ok: false, revision: { wants: cls },
                     reason: `任务必需 ${cls}，父层为 forbidden` };
    }
    // 2. meet：构造性收紧
    const policy: EffectivePolicy = {
        ...structuredClone(parent),
        derivedFrom: { parentId: parent.id, parentVersion: parent.version },
    };
    for (const [cls, w] of Object.entries(req.wants ?? {}) as [EffectClass, EffectRule][]) {
        const p = policy[cls] ?? { tier: 'forbidden' as EffectTier };
        policy[cls] = {
            tier: minTier(p.tier, w.tier ?? 'forbidden'),
            paths: intersect(p.paths, w.paths),
            hosts: intersect(p.hosts, w.hosts),
        };
    }
    // 3. 危险组合守卫（§7）
    applyGuards(policy);
    return { ok: true, policy };
}
```

### 5.3 requires / wants：fail-fast 的经济学

判据一句话：**这个能力缺了，任务还成立吗？成立 → wants；不成立 → requires。**

- `wants` 被父层收紧（clamp）：静默接受，任务照走，事件入日志。非必需能力砍掉无伤。
- `requires` 父层不可满足：**不允许静默 clamp**——砍掉必需能力意味着任务注定中途失败，预算照烧、失败原因埋在 trace 深处。正确行为是 spawn 即拒绝，携带 reason 发起 ContractRevision（非阻塞入队），人批准后根契约修订、重新派生；拒绝则任务取消。

### 5.4 语义自检表（单测基线）

| 子请求                                                                         | 父层          | 结果                  | 验证点           |
| ------------------------------------------------------------------------------ | ------------- | --------------------- | ---------------- |
| `net.fetch: auto`                                                            | `gated`     | `gated`             | 宽松档被钳制     |
| `fs.exec: forbidden`                                                         | `auto`      | `forbidden`         | 主动收缩允许     |
| `fs.write.workspace: auto`                                                   | `forbidden` | `forbidden`         | 越权请求静默失效 |
| requires`net.send`                                                           | 父层未声明    | fail-fast → revision | 不白烧预算       |
| 安全性由构造保证：**子层变宽的唯一路径是人**。这就是权限继承的全部纪律。 |               |                       |                  |

## 6. Gated：确认门的完整语义

gated 不是「问人」，是**范围判定的分派器**：

```
效果请求
  ├─ 命中 paths/hosts 白名单 → 用户预授权，静默放行 + decisionLog
  └─ 范围外 → 非阻塞确认门队列 → 批准执行 / 拒绝丢弃
```

关键性质：

1. **白名单命中 = 预授权**。根层 `net.fetch: gated { hosts: [registry.npmjs.org] }` 意味着 npm 安装永远静默——用户在签根契约时已经为「这一类操作」付过注意力了。
2. **范围外确认是非阻塞的**。「发布已入队待批，我先继续做关卡」——主干不停，确认是并行队列，人批量处理。
3. **确认请求携带完整上下文**：哪个契约、哪个效果、范围外多少（路径/域名）、守卫是否参与过降级。人批的是一次可判定的小决定，不是开放式问题。
4. `delete` **恒为 gated**，任何层不可设 auto，白名单也不豁免——不可逆操作没有「预授权的可逆形态」。

## 7. 危险组合守卫

单轴全部合法、组合构成攻击面的对，在 derive 尾部对 effective **全局合取**后统一检查：

```typescript
interface Guard {
    when: (p: EffectivePolicy) => boolean;
    downgrade: Partial<Record<EffectClass, EffectTier>>;
    reason: string;   // 全量写入 decisionLog
}
const GUARDS: Guard[] = [
    { when: p => tierOf(p, 'fs.read.host') >= 1 && tierOf(p, 'net.send') === 'auto',
      downgrade: { 'net.send': 'gated' },
      reason: 'host 读取 + 对外发送 = 数据外泄管道' },
    { when: p => tierOf(p, 'fs.read.workspace') >= 1 && tierOf(p, 'net.fetch') === 'auto',
      downgrade: { 'net.fetch': 'gated' },
      reason: '读盘 + 联网拉取 = 注入入口，fetch 内容须标 untrusted' },
    { when: p => tierOf(p, 'net.fetch') === 'auto' && tierOf(p, 'fs.exec') === 'auto',
      downgrade: { 'fs.exec': 'gated' },
      reason: '可拉取 + 可执行 = 下载即执行' },
];
```

| 组合                                        | 风险                             | 默认处置                                    |
| ------------------------------------------- | -------------------------------- | ------------------------------------------- |
| `fs.read.host` + `net.send: auto`       | 外泄：读到的数据有出口           | `net.send` → gated                       |
| `fs.read.workspace` + `net.fetch: auto` | 注入：fetch 回来的内容进入上下文 | `net.fetch` → gated；内容打 untrusted 标 |
| `net.fetch` + `fs.exec` 均为 auto       | 下载即执行                       | `fs.exec` → gated                        |
| `delete`                                  | 不可逆                           | 恒 gated，守卫表之外硬编码                  |
| 规则：                                      |                                  |                                             |

- 默认行为 = 降级 + decisionLog（含 reason）。用户可配置为仅告警，**但不可关闭日志**。
- 守卫表不完备是已知代价（§12）；补救纪律：新 EffectClass 注册时强制过一遍组合审查，危险对作为数据沉淀持续积累。
- 守卫发生在**派生时**而非执行时——每个子任务的 effective 在 spawn 时就已收敛到安全形态，运行时不做惊喜。

## 8. 网络策略与真实执行点

`hosts` 白名单不是文档字段，是 proxy 配置。两条硬性要求：

1. **egress proxy 是唯一网络出口**。工具进程在网络命名空间/沙盒层面无直连能力——应用层自觉检查域名是标准绕过面。
2. **DNS rebinding 防御**：域名校验发生在**连接时而非策略匹配时**。proxy 解析域名 → pin 住 IP → 用该 IP 建连 → 二次解析不一致即拒绝。只在匹配策略时查域名、建连时重新解析，等于白名单形同虚设。
   配套管线：`net.fetch` 返回的内容统一打 **untrusted 标记**——作为数据进入上下文，不作为指令。这不是内容层防御（上下文工程的事），但它是注入爆炸半径的上限：即便注入成功，攻击者在一个「send 恒 gated、exec 恒 gated、delete 恒 gated」的 effective 里拿不到不可逆能力。

## 9. Kill Switch：格外的中止权

- **控制通道独立于数据通道**：kill 走独立通路（进程信号级 + 沙盒销毁级），不经过 policy check 管线。
- **任何层级可触发，任何 policy 不可阻挡**——包括平台硬上限本身。若 kill 受 policy 约束，一个写错的 policy 就是不可恢复态：系统永远停不下来。
- 职责分工：权限格回答「模型能做什么」；kill switch 回答「人还能不能叫停」。**后者是前者存在的前提。**

## 10. 审计集成

权限事件是 decisionLog 的高价值子集，四类必录：

| 事件                | 触发                         | 记录内容               |
| ------------------- | ---------------------------- | ---------------------- |
| `clamp`           | wants 被 meet 收紧           | 被钳制的类别、父层档位 |
| `guard-downgrade` | 危险组合守卫降级             | 组合、降级结果、reason |
| `derive-reject`   | requires fail-fast           | 缺失能力、reason       |
| `grant-revision`  | 人批准/拒绝 ContractRevision | 修订前后授权对比       |

回放能力：`契约 spec + derivedFrom + decisionLog` 三者联合，可以完整回答**「这个效果是在哪一层的哪次决定下被放行的」**——每个放行都可归因到一次显式的人类决定或一条显式的守卫规则，没有「不知道谁允许的」。

## 11. 示例走查

### 11.1 贪吃蛇（几千个子任务，人出现两次）

```
根 grant = PRESETS['workspace']
         + net.fetch: gated { hosts: [registry.npmjs.org] }
         + publish: gated
安装依赖子任务  wants: net.fetch { tier: auto, hosts: [registry.npmjs.org] }
  meet → tier: gated（取严），hosts: [registry.npmjs.org]（交集）
  白名单命中 = 根层预授权 → 静默放行 + 日志
微决策（配色/按键/速度）  默认策略 + decisionLog，与权限无关
发布  publish: gated，无白名单豁免 → 非阻塞确认门
  「发布已入队待批，我先继续做关卡」
```

### 11.2 简历（fail-fast 修订链）

```
子契约请求 requires: ['net.send']（发邮件给 HR）
  根层未声明 net.send（= forbidden）
  → { ok: false, revision: { wants: 'net.send' } }
  → 人批准 → 根契约修订，增加 net.send: gated { hosts: [hr.example.com] }
  → 重新派生 → 发送走确认门
```

反例（若用静默 clamp）：任务执行到发信一步才失败，预算已烧，失败原因埋在 trace 深处。

### 11.3 危险组合降级

```
任务 wants: fs.read.host: auto + net.send: auto
  meet 通过（父层恰好都有）
  守卫命中：net.send → gated，reason 入 decisionLog
  结算时人翻日志可看到这次自动收紧并翻案
```

## 12. 边界、代价与开放问题

| 项                                                                                                                                                                                                                                                  | 现状                                              | 处置                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
| 守卫表不完备                                                                                                                                                                                                                                        | 危险对靠枚举，新组合可能漏                        | 新 EffectClass 注册强制过组合审查；危险对持续沉淀                        |
| `paths` glob 语义                                                                                                                                                                                                                                 | 前缀匹配有歧义                                    | 收敛到显式 glob 方言，单测固定                                           |
| 根授权修订成本                                                                                                                                                                                                                                      | 每次修订需人批准，可能成瓶颈                      | 授权包：一次批准一类修订（如「本会话 net.send 至固定域名」），带过期时间 |
| 沙盒强度依赖运行时                                                                                                                                                                                                                                  | spec 层只承诺「失败可回滚」契约，后端各自映射强度 | 文档化各后端保证等级                                                     |
| egress proxy 单点                                                                                                                                                                                                                                   | 挂了则全部 net 操作失败                           | 故障模式默认 deny（fail-closed）；探活 + 用户可选降级                    |
| wants 漫天要价                                                                                                                                                                                                                                      | clamp 已保证安全                                  | 成本侧由 budget 扣减自然抑制，不额外审查                                 |
| **明确不做的事**：本系统不治理 prompt injection 的内容层防御（那是 untrusted 管线与上下文工程的职责），只负责把注入成功的**可达爆炸半径**压到最小——注入者在一个 send/exec/delete 全 gated 的 effective 里，能做的最坏的事都是可逆的。 |                                                   |                                                                          |

## 13. 不变量总表（实现验收清单）

| #   | 不变量                                               | 执行点                                     |

| V1  | 授权只发生于根层；`full-access` 永不在派生路径出现 | `fullAccessGrant()` 根层断言，唯一调用点 |

## 15. 结语

整个系统只建立在一组很小的原语上：

- **一个原子**：EffectClass × EffectTier（资源×操作上的三档）；
- **一条链**：平台上限 ∩ 根授予 ∩ 派生收缩，合取而非覆盖；
- **一个算法**：meet 取严，构造性保证子层无法越权——安全不靠纪律，靠「变宽的唯一路径是人」；
- **两扇门**：gated 的范围分派（预授权静默 / 范围外确认），和权限格之外的 kill switch。
  这套设计最终兑现的承诺：人的注意力只花在三处——**事前的边界**（签根授予）、**事中的例外**（范围外确认门）、**事后的翻案**（decisionLog 审计）；中间的一切，包括几千个子任务的派生、执行、钳制与守卫降级，都在机器闭环里完成，且每一个已发生的效果都可归因到一次显式的决定。
